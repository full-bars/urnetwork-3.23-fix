### Release Notes: `v3.23.0-fix.14` — Autonomous Performance Suite

This is a major feature and stability release. It introduces the "Autonomous Performance Suite" which removes the need for manual performance tuning by making the provider hardware-aware.

## 🧠 Smart Auto Profile (`URNETWORK_PROFILE=auto`)
A "set and forget" solution that detects your hardware and selects the best internal balance.
• **Hardware-Aware Tiering**: Automatically scales contract floors and buffer depths based on system RAM.
• **Auto-Eco**: Launches dynamic GC pressure monitoring on RAM-constrained nodes (< 3GB).
• **Auto-RAMLOG**: Automatically moves logs to `/dev/shm` if your disk is too slow (< 50MB/s), preventing storage bottlenecks.
• **Seamless Handover**: Provides a 3-second countdown and clear instructions when transitioning logs to RAM.

## ⚡ System Optimizer (`urnet-tools optimize`)
A "one-click" command for Linux service installs that applies professional-grade network tuning.
• **Auto-Installation**: Automatically installs `conntrack` and `zram` on Arch, Debian, RHEL, Alpine, and OpenSUSE if missing.
• **Interactive Protection**: Detects pre-optimized states (high limits or active zram) and asks for confirmation before overriding. Use the `-f` flag to skip prompts.
• **High-Volume Networking**: Enables **BBR** congestion control and **Fair Queuing (fq)** for superior throughput and reduced latency.
• **Solved Boot Race Condition**: Configures `/etc/modules-load.d` so kernel settings apply correctly during boot.
• **ZRAM Acceleration**: Automatically configures compressed RAM swap (80% RAM, \`zstd\`) for low-memory stability.
• **Fleet-Standard Tuning**: Bumps \`ulimit\` to 1M and \`conntrack_max\` to 2M.
• **Systemd Lingering**: Auto-enables lingering so systemd --user services persist after logout.

## 🔍 System Auditor
• **Disk Benchmark**: Performs a 1GB cache-busting sync write test on every startup.
• **Health Alerts**: Warns about low disk space (< 1GB) or suboptimal host limits.
• **Docker Guidance**: Clear hints for Docker users on how to run \`urnet-tools optimize\` on the host machine.

---

### Other Improvements & Fixes
• **Message Pool Auto-Sizing**: Pool capacity now scales to RAM/32 at startup (floor 8 MiB, cap 256 MiB). This significantly reduces CPU overhead for large proxy deployments.
• **Reliable Outage Detection**: Requires 10 consecutive failures (5 min) to eliminate false alarms from brief network blips.
• **Webhooks**: Non-blocking delivery with automatic formatting for Discord and Slack.
• **Watchtower / JWT Persistence**: Fixed session loss during container updates. Container volumes now support auto-naming via the \`NAME\` variable.
• **Health Heartbeat**: New \`[health]\` log line emits uptime and memory metrics (heap/sys).
• **Log Visibility**: \`urnet-tools logs\` now shows **250 lines** of history in RAM logging mode.
• **Installer Robustness**: Fixed Python 3 date parsing crashes, graceful handling of Docker/root installs, and automatic systemd lingering setup.

---

## Installation & Setup

**Docker users**: Use the examples in the [README](https://github.com/full-bars/urnetwork-3.23-fix#docker-run--github-registry-ghcr). After first run, the System Auditor will report host-level optimizations. To apply them:

\`\`\`bash
# On the HOST machine (not inside the container):
curl -fSsL https://raw.githubusercontent.com/full-bars/urnetwork-3.23-fix/main/scripts/Provider_Install_Linux.sh | sh
sudo urnet-tools optimize -f
\`\`\`

The optimizer automatically enables systemd lingering and applies conntrack, BBR, zram, and boot persistence in one command.

**Linux service users**: Install via the script and run \`urnet-tools optimize\` for one-click tuning.
