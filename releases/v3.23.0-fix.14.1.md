## ZRAM Robustness Fix for Ubuntu Upgrades

This point release hardens ZRAM setup for systems upgraded from Ubuntu 20.04 to 24.04, where the zramswap service often fails to initialize due to residual device configuration.

### Changes

- **Dynamic kernel module loading**: Try dynamic device allocation (`num_devices=0`) first, fall back to static (`num_devices=1`)
- **Module reload recovery**: On disksize configuration failure, unload and reload the zram module to force clean initialization
- **Compression algorithm fallback**: Attempt zstd compression first, fall back to lz4 if unavailable
- **Permission checks**: Test sysfs write permissions before attempting configuration
- **Timing stability**: Add strategic delays between operations to allow hardware to settle
- **Improved diagnostics**: Better error messages indicating whether failures are due to missing kernel support vs. configuration issues

### Who Should Update

- Anyone deploying on Ubuntu systems that were upgraded from 20.04 to 24.04
- Systems experiencing "ZRAM could not be auto-enabled" errors despite kernel support
- Multi-region deployments where some nodes have inconsistent upgrade histories

### Testing

Run the optimizer after updating:
```bash
urnet-tools update
urnet-tools optimize -f
```

The manual fallback will now handle edge cases that previously caused silent failures.
