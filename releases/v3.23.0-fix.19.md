### 📊 Bandwidth Hub Dashboard (New)

A live fleet monitoring dashboard that aggregates bandwidth reports from all nodes in real time.

**Architecture:** Each provider sends a periodic POST to the hub's `/api/report` endpoint (configurable via `URNETWORK_REPORT_URL`). The hub persists state to `hub.json` and renders an HTML dashboard at the root path.

**Key features:**

- **Per-node traffic rates**: RX/TX Mbps calculated as delta between consecutive reports, shown as "In Mbps" / "Out Mbps" columns
- **Billable vs total traffic**: Each proxy reports both total wire bytes and billable bytes. The dashboard shows both alongside each other
- **Per-proxy drilldown**: Click any node row to expand its full proxy list with individual status, clients, age, RX/TX, and billable traffic
- **Auto-refresh**: Page reloads every 30s with a visible countdown; toggleable with the auto-refresh checkbox
- **Sortable columns**: Click any column header to sort by that metric (numeric-aware); triangles indicate sort direction
- **Status badges**: Color-coded proxy status counts (up/connecting/degraded) per node
- **Heartbeat health**: Dot indicator shows green (<2m), yellow (<5m), or red (stale)
- **JSON API**: `/api/nodes` returns the full node state as JSON for external tooling

**Running the hub:**
```sh
# Start the hub (default :8080, data in current dir)
./hub

# Custom port and data directory
./hub -addr :9090 -data /var/hub-data
```

**Configuring provider reporting:**
```sh
# In the provider's environment (binary or Docker)
URNETWORK_REPORT_URL=http://HUB_IP:8080
```

> [!TIP]
> The hub is a standalone binary (`hub/main.go`) that does not require the full provider stack. Build and deploy it once on a monitoring server; all nodes report to the same hub URL.

### 🚀 Proxy Startup Pacing (New in .19)

Starting a provider with a large proxy list (500+) no longer causes a thundering-herd against the platform WebSocket endpoint.

**Jittered Stagger:** Each proxy goroutine waits `index × stagger_ms ± 50% jitter` before dialing. The default stagger is 1 second per proxy, configurable via `URNETWORK_PROXY_STAGGER_MS`:

```sh
# 500ms stagger (faster startup, higher platform load)
URNETWORK_PROXY_STAGGER_MS=500

# 2s stagger (gentler startup, lower platform load)
URNETWORK_PROXY_STAGGER_MS=2000
```

This spreads the initial WebSocket connection wave across `N × stagger_ms` milliseconds instead of firing all at once.

**Pace Monitor:** A background goroutine logs warmup progress every 30s:

```
[pace] ⚠ warmup: 47/200 up (24%), 150 connecting, 3 done
[pace] warmup: 142/200 up (71%), 55 connecting
[pace] ✓ warmup: 196/200 up (98%), 4 connecting — done
```

- **⚠ Warning** appears when fewer than 50% are up and more than 10 are still connecting (slow warmup)
- **✓ Checkmark** appears when more than 90% are up and fewer than 5 are still connecting (nearly done)
- Plain status for everything in between

> [!TIP]
> No configuration is needed — the pace monitor fires automatically. Adjust `URNETWORK_PROXY_STAGGER_MS` if you need faster or gentler startup.

### 🔧 Stability & Fixes

**Bandwidth Reporter:** Now posts to `/api/report` on the hub (not the raw report URL), skips empty reports, and includes the connecting proxy count in each submission.

**Proxy Health Snapshot:** Extended to return the list of connecting proxies alongside up/dead/degraded counts, enabling better visibility into warmup state.

**Pulse Logging:** The hourly [pulse] wake log now includes the number of connecting proxies:

```
[pulse] waking stalled transports: down=3 dead=2 degraded=1 connecting=15
```

**Native Direct Proxy Fix:** `proxyIndex()` now correctly returns `index=0, ok=true` for native direct proxies, fixing downstream routing for that transport mode.

---

### ⏪ Breaking Changes / Deprecations

- `ProxyHealthSnapshot()` now returns 5 values instead of 4. The new 5th return value is `connecting []string` (list of proxy addresses currently in connecting state). All callers have been updated.
