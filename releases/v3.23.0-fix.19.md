### 🗺️ Fleet Bandwidth Hub Dashboard (New)

![Hub Dashboard Preview](https://raw.githubusercontent.com/full-bars/urnetwork-3.23-fix/main/docs/hub-dashboard-preview.png)

A live fleet monitoring dashboard that aggregates bandwidth reports from all provider nodes in real time. The hub is a standalone binary (`hub/main.go`) — build and deploy it once on a monitoring server; all nodes report to the same URL.

**Architecture:** Each provider sends a periodic POST to the hub's `/api/report` endpoint (configurable via `URNETWORK_REPORT_URL`). The hub persists state to `hub.json` and renders an HTML dashboard at the root path.

**Key features:**
- **Per-node traffic rates**: RX/TX Mbps calculated as delta between consecutive reports, shown as In/Out Mbps columns
- **Billable vs total traffic**: Each proxy reports both total wire bytes and billable bytes. Dashboard shows both in summary bar, node rows (total above, billable in muted `b` text), and per-proxy detail tables (dedicated Bill RX/Bill TX columns)
- **Per-proxy drilldown**: Click any node row to expand its full proxy list with individual status, clients, age, RX/TX, and billable traffic
- **Auto-refresh**: 30s countdown with toggle checkbox
- **Sortable columns**: 12 columns with numeric-aware sorting and direction indicators
- **Status badges**: Color-coded up/connecting/degraded counts per node
- **Heartbeat health**: Green (<2m), yellow (<5m), or red (stale) dot indicator
- **JSON API**: `GET /api/nodes` returns full node state for external tooling

**Running the hub:**
```sh
./hub -addr :8080 -data /var/hub-data
```

**Configuring provider reporting:**
```sh
URNETWORK_REPORT_URL=http://HUB_IP:8080
```

### ⏳ Proxy Startup Pacing & Warmup Monitor (New)

Starting a provider with a large proxy list (500+) no longer causes a thundering-herd against the platform WebSocket endpoint.

**Jittered Stagger:** Each proxy goroutine waits `index × stagger_ms ± 50% jitter` before dialing. Default stagger is 1s per proxy, configurable via `URNETWORK_PROXY_STAGGER_MS`:

```sh
URNETWORK_PROXY_STAGGER_MS=500   # faster startup, higher platform load
URNETWORK_PROXY_STAGGER_MS=2000  # gentler startup, lower platform load
```

**Pace Monitor:** Background goroutine logs warmup progress every 30s:
```
[pace] ⚠ warmup: 47/200 up (24%), 150 connecting, 3 done
[pace] warmup: 142/200 up (71%), 55 connecting
[pace] ✓ warmup: 196/200 up (98%), 4 connecting — done
```

- **⚠ Warning** — fewer than 50% up and >10 still connecting
- **✓ Checkmark** — more than 90% up and <5 still connecting
- Plain status for everything in between

### 🔧 Stability & Improvements

**Port upstream proxy-fixes2:** Backported [upstream PR #184](https://github.com/urnetwork/connect/pull/184) (OOB provide-ack and ping-companion-contract). This improves provider reliability during backend outages by ensuring OOB control messages are properly acknowledged.

**Bandwidth Reporter:** Now posts to `/api/report` on the hub (not the raw URL), skips empty reports, and includes the connecting proxy count in each submission.

**Proxy Health Snapshot:** Extended to return `connecting []string` alongside up/dead/degraded — enables better visibility into warmup state.

**Pulse Logging:** Hourly pulse now includes connecting count:
```
[pulse] waking stalled transports: down=3 dead=2 degraded=1 connecting=15
```

**Native Direct Proxy Fix:** `proxyIndex()` now correctly returns `index=0, ok=true` for native direct transports, fixing downstream routing.

**Unit Tests:** 18 tests added for hub handlers, store logic, rate calculation, and HTTP endpoints — run in ~13ms in CI.

---

### ⏪ Breaking Changes

- `ProxyHealthSnapshot()` now returns 5 values instead of 4. The 5th return value is `connecting []string` (proxy addresses currently in connecting state). All in-repo callers have been updated.
