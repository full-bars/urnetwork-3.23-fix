# v3.23.0-fix.30.9 — 2026-09-04

> [!NOTE]
> This release brings comprehensive security hardening, data-plane reliability, and operator tooling upgrades across the provider runtime and urnet-tools. Major additions include TCP-return packet retention across ack timeouts, bulk proxy ingestion via proxy paste, SSRF guards on operator-supplied proxy URLs, dynamic direct connection toggling (provider direct), upstream production DNS-over-HTTPS (DoH), and client JWT hot-restart continuity. Rebuild and redeploy provider nodes, and update urnet-tools and urnet-docker, to pick up the fixes.

## 1. Overview & Highlights

v3.23.0-fix.30.9 represents a major hardening and stability milestone for the fork:
- **Data-Plane Retention & Earnings Protection**: In-flight TCP return packets are now retained across ack timeouts instead of being prematurely dropped, protecting relay session continuity and operator billing credit during transient network stalls.
- **Bulk Proxy Ingestion (proxy paste)**: Added interactive and piped proxy loading supporting multiple raw formats (host:port, socks5://, user:pass@host:port, CSV), complete with strict format validation, credential protection, and automated signal-based cleanup of temporary files.
- **SSRF Hardening**: Operator-supplied proxy list URLs (proxy add-source and proxy paste) are strictly verified at dial time and during HTTP redirects to reject dials to loopback, link-local metadata (169.254.169.254), private RFC1918, IPv6 ULA, and multicast addresses.
- **Dynamic Direct Transport Toggle (provider direct)**: Operators can toggle the provider native direct IP egress on and off at runtime without restarting the process or disrupting active SOCKS5 proxies.
- **Fleet Management Security Audit Remediation**: Comprehensive security audit fixes across urnet-tools and urnet-docker, including bounded subprocess timeouts, session bundle encryption, safe file ownership chowning, and Go build info version inspection.
- **Production DNS-over-HTTPS (DoH)**: Ported upstream production DoH engine featuring a persistent server-scored cache, serve-stale fallback (RFC 8767), staggered query launching, and bounded 3s timeouts.
- **Client Identity Hot-Restart**: Client JWTs are automatically renewed and snapshotted before restarts, preventing cold re-authentication storms across service updates.
- **Subnet 25 Telemetry & Miner Dashboard (`sn-status`)**: Added first-class Bittensor Subnet 25 telemetry commands across `urnet-tools`, `urnet-docker`, and `provider`, surfacing live global rank, top-200 tier eligibility, verified bandwidth provided, coldkey registration, epoch lifecycle blocks, and merkle pool payout share.

## 2. Data-Plane Reliability & Billing Precision

### TCP Return Retention Across Ack Timeouts (PR #506, #521)
During periods of asymmetric packet latency, the provider previously dropped TCP return packets once the acknowledgment timeout expired. This prematurely aborted user connections and forfeited billable transfer credit.
- **Retention State Machine**: Return-path packets are retained beyond the initial ack deadline and resent when the connection stabilizes.
- **Memory Backstop**: Retention is bounded by `MaxRetainedBytes` to prevent buffer bloat under prolonged downstream partition.
- **Flow Teardown Drainage**: In-flight retained buffers are cleanly drained upon receiving connection resets (`rstFlow`).
- **Billing Contract Precision**: Fixed `unack()` debit rounding to ensure packets discarded at the backstop ceiling are never erroneously credited as acknowledged billable transfer.
- **Health Telemetry**: Retention ack and drop events are logged to the persistent health log through a buffered, thread-safe writer.

## 3. Proxy Management & Ingestion

### Bulk Proxy Ingestion via `proxy paste` (PR #502, #520)
Operators managing hundreds of rotating proxies can now stream raw lists directly into the provider:
- **Automatic Format Normalization**: Ingests bare `host:port`, `socks5://host:port`, `user:pass@host:port`, and CSV formats. Strips extraneous URI components (such as trailing URL paths on SOCKS5 lines).
- **Strict Validation**: Rejects unsupported protocols (HTTP/HTTPS/SOCKS4), colon-in-credential corruption (which corrupts the `host:port:user:pass` delimiter contract), out-of-range ports, and pseudo-IPv6 syntax.
- **Signal-Safe Temp Cleanup**: Normalization writes to an unprivileged temporary file (`proxy-paste-*.txt`, mode `0600`). A dedicated signal handler catches `SIGINT` (Ctrl+C) and `SIGTERM`, unlinks the temporary file immediately, restores the default signal disposition, and re-raises the signal using cross-platform process signaling.

### SSRF Guard for Proxy Sources (PR #522)
Operator-supplied URLs passed to `proxy add-source` or `proxy paste` now traverse a hardened HTTP client:
- **Dial-Time Protection**: Resolves target hosts and rejects non-global unicast addresses at the dialer before TCP handshakes initiate.
- **Redirect Validation**: Follows up to 3 redirects, validating each intermediate and terminal target against the SSRF filter.
- **Blocked Ranges**: Loopback (`127.0.0.0/8`, `::1`), link-local metadata (`169.254.0.0/16`, `fe80::/10`), private RFC1918 (`10/8`, `172.16/12`, `192.168/16`), IPv6 ULA (`fc00::/7`), and multicast.

> [!CAUTION]
> Proxy list URLs pointing to internal services, cloud instance metadata endpoints (`http://169.254.169.254/`), or private networks will be refused with an SSRF guard error. Source URLs must resolve to globally-routed public addresses.

## 4. Network Control & Operator Tooling

### Dynamic Direct Connection Toggle (`provider direct`) (PR #510, #514, #516, #517)
- Added `provider direct on|off` to enable or disable native direct IP transport on demand.
- Persists state to `~/.urnetwork/direct_override` using atomic temporary file replacement.
- Direct transport reloader dynamically spins down native interfaces while keeping existing SOCKS5 proxies active.
- Goroutine lifecycle safety: Implemented compare-and-delete CAS and synchronized map deletions to prevent orphaned cancellation tokens or wedged reload loops.

### `choose_network` Presets (PR #504)
- Added first-class presets for `choose_network` (`main` and `beta`), allowing operators to re-target control-plane endpoints without manually entering full URLs.

### Usage & Accounting Engine (`urnet-tools usage`) (PR #507, #521)
- Added structured accounting distinguishing billable relay traffic from control-plane protocol overhead.
- Generates rolling time-series breakdowns (`24h`, `7d`, `30d`, `lifetime`).

### Subnet 25 Telemetry & Miner Observability (`sn-status`) (PR #528)
Bittensor Subnet 25 operators can now inspect end-to-end node ranking and mining telemetry directly from the CLI:
- **Comprehensive Dashboard**: Renders global rank, public leaderboard status, tier qualification (Tier 1 Elite, Tier 2 High-Volume, Tier 3 Active, or distance below Top 200 cutoff), net bandwidth provided (MiB/GiB), registered coldkey (SS58 and raw hex), current subnet epoch blocks (start and finalize), smart contract address with chain ID, and finalized epoch merkle pool payout share (basis points and percentage).
- **Three-Way CLI Parity**: Available across `urnet-tools sn-status`, `urnet-docker sn-status`, and `provider sn-status`.
- **JSON Telemetry Mode**: Adding `--json` (`-j`) outputs machine-parsable JSON for integration into automated monitoring stacks, Prometheus exporters, and alerting tools.
- **Operations Documentation**: Added `docs/Bittensor-Operations.md` detailing Subnet 25 mining mechanics, coldkey registration (`provider wallet set`), epoch timeline, validator verification criteria, and claim operations.

## 5. Security Audit Remediation & Hardening

### `urnet-tools` & `urnet-docker` Security Fixes (PR #497, #498, #499, #505, #509)
- **Privilege Separation**: Version detection inspects embedded Go build info (`runtime/debug.ReadBuildInfo`) first; only falls back to bounded subprocess execution (`--version`) on vetted binary paths when build metadata is stripped.
- **Bounded Subprocesses**: Added non-blocking execution with strict timeouts (5s for discovery, 10s for systemctl commands) to prevent wedged child processes from hanging the management CLI.
- **Safe State Directory Chowning**: Created state files and session directories are chowned to the provider user rather than remaining root-owned.
- **Path Traversal & Session Bundle Verification**: Hardened session export/import with PBKDF2/AES-256 validation; sanitized root search paths against ancestor symlink TOCTOU vulnerabilities.
- **Uninstall Guards**: `uninstall` refuses deletion of well-known system root paths (`/home`, `/etc`, `/var`, `/usr`).

### Core Runtime Memory & Concurrency Bounds (PR #505, #508, #513, #521, #523)
- **`pathTable` LRU Eviction (ip.go)**: Multi-hop route table bounded with size caps, mutex locking, and LRU pruning to eliminate unbounded memory growth under high peer churn.
- **DNS Negative Cache Pruning**: Replaced unbounded negative caching with periodic sort-based pruning.
- **Message Pool Concurrency**: Converted pool metrics `sizeDistMu` to `sync.RWMutex` and added bounds checking against buffer counter underflows/overflows.
- **WebRTC & WebSocket Bounds**: Implemented inbound WebSocket frame limits and bounded WebRTC signal coalescing queues.
- **CFAA Blocklist Sync (PR #511)**: Synchronized Computer Fraud and Abuse Act IP blocklists with upstream definitions.

## 6. Upstream DNS-over-HTTPS (DoH) & JWT Hot-Restart

### Persistent Production DoH Resolver (PR #495, #496)
- **Persistent Cache**: Resolver metrics and server scores persist to `~/.urnetwork/doh_cache.json`, preventing cold resolution penalties on service restart.
- **Optimized Selection**: Features server scoring, RFC 8767 serve-stale behavior during upstream outages, staggered request launching, and single-flight coalescing.
- **Bounded Latency**: Capped resolution queries at 3 seconds with early cancellation of lagging servers once a winner responds.

### Client JWT Hot-Restart v2 (PR #494)
- Pre-emptively renews expired client JWTs during startup.
- Snapshots identity tokens to local state before graceful restarts, eliminating cold authentication storms across provider upgrades.

### Warm Proxy Priority & Accelerated Stagger (PR #526)
- **Startup Latency Elimination**: Evaluates local client JWT store on boot and prioritizes warm, previously-authenticated proxies during pool selection to optimize validator probe responsiveness.
- **Accelerated Startup Stagger**: Reduces connection launch stagger from 2 seconds to 100 milliseconds for known-warm proxies, dramatically slashing cold-start ramp times.
- **Network ID Conflict Guard**: Hardens `AnyNetworkID` against mismatched network identity state, ensuring strict network identity consistency.

### CLI Parity, Idle-Update, & Docker Hardening (PR #525)
- **Go-Native `idle-update`**: Implemented `urnet-tools idle-update` and `urnet-docker idle-update` polling billable throughput to apply updates during traffic quiet windows with a configurable timeout ceiling.
- **Path Ergonomics**: Added tilde (`~`) expansion across all proxy CLI commands on both host and Docker.
- **Multi-Target Proxy Ingestion**: `proxy add` accepts multiple files or straight URLs in a single command.
- **Docker Isolation & Security**: Bounded vnStat default ports to `127.0.0.1:9001` and documented container config volume isolation rules (`ur_config_1`, `ur_config_2`) to protect state databases.
