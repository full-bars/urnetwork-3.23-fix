# v3.23.0-fix.30.9 — 2026-08-30

> [!NOTE]
> This release hardens the urnet-tools management utility against privilege-escalation and safety
> findings from a comprehensive security review, makes provider updates reliable and verifiable, and
> upgrades the DNS-over-HTTPS resolver to the production-grade implementation. Rebuild and redeploy
> provider nodes, and update urnet-tools and urnet-docker, to pick up the fixes.

## 1. The story of this release

The urnet-tools utility is the operator's control plane. It discovers providers, manages their systemd
units, updates their binaries, and drives their lifecycle. A review of that code surfaced privilege-
escalation and safety issues: one path executed a discovered binary just to read its version, another
self-owned a state directory it had just created, and several subprocesses ran without timeouts. On a
box run with sudo this is the difference between a controlled tool and an arbitrary-code-execution
vector.

This release narrows those gaps. The utility now reads versions from the binary's Go build info where
the version is recorded, and only falls back to executing the binary (with a 3s timeout, on an
already-vetted path) when build info is unavailable, chowns state it creates to the provider's user,
bounds discovery and status-path subprocesses with a timeout,
and guards destructive operations against bad paths. A parallel thread made provider updates
trustworthy: the restart is verified after it runs, stale binaries are detected, and the reinstall
path no longer fails silently.

Separately, the DNS-over-HTTPS resolver matured from a stopgap to the upstream production implementation
with a persistent cache, server scoring, and serve-stale behavior. And client JWTs are now renewed and
snapshotted across hot restarts so a provider restarts with a working identity instead of re-authenticating
from scratch.

## 2. urnet-tools security audit remediation

- **Version reads use build info first, not a blanket exec ban** — version strings are read from the Go
  build info when it is recorded. Executing a discovered binary is NOT fully removed: when the build
  info carries no version (e.g. `-trimpath` builds), the tool still runs the binary with `--version`
  as a fallback, under a 3-second timeout on a discovery-vetted path. The residual risk is reduced,
  not eliminated.
- **State directory ownership fixed** — `set`/`fast-auth`/`self-heal` create files the provider must
  read. These are now chowned to the provider user instead of staying root-owned.
- **Subprocess timeouts everywhere** — every discovery and systemctl call is bounded (5s/10s) so a hung
  process cannot wedge the tool. An unbounded `id`/`chown`/`getent` call cannot stall an update.
- **Uninstall path guard** — `uninstall` refuses to delete well-known system directories; it no longer
  removes arbitrary absolute paths.
- **Hub install verifies the binary** — the downloaded hub binary is checked against the release digest
  before install, and the download goes to an exclusive temp file (no symlink-preemption).
- **restart safety** — a bare process is no longer SIGINT'd (which killed it permanently); the tool asks
  the operator to restart the unit instead. Restart scope (user vs system) is resolved via systemctl,
  not filesystem guesswork.
- **update confirm no longer hangs** — the non-TTY confirm path returns an error instead of blocking on
  stdin forever (cron/CI-safe).
- **Architecture detection** — the tool uses `runtime.GOARCH`, not a `$GOARCH` env var that a stray
  environment could override, so it installs the correct-architecture binary.
- **Drop-in writes are atomic** — transient read errors no longer wipe operator overrides, and writes
  use temp+rename.

## 3. Reliable, verifiable provider updates (#497)

- **Post-restart verification** — the update restart is checked after it runs instead of assumed.
- **Stale-binary detection** — a running process whose on-disk binary was replaced is flagged for a
  redundant reinstall rather than trusted.
- **Provider version in `status`** — `urnet-tools status` shows each provider's actual running version.
- **Reinstall fixed** — the reinstall path no longer fails silently with a missing staging directory.

## 4. Production DNS-over-HTTPS upgrade

- **Persistent DoH cache (#496)** — cached resolutions and per-server scores survive restarts, so a
  reboot does not cold-start DNS.
- **Upstream DoH optimizations P1-P3 (#495)** — server scoring, serve-stale (RFC 8767), staggered
  launch, single-flight coalescing, memory budget, TLS resumption, and warm-up on resolver failure.
- **Bounded DNS resolution** — DNS lookups are capped at 3s and abort on the winning server instead of
  waiting for losers.

## 5. Client JWT hot-restart across restarts (#494)

- **Renew before restart** — expired client JWTs are renewed on startup so a provider never restarts
  with a dead identity.
- **Snapshot before restart** — identities are snapshotted before the restart and reused, eliminating
  the cold re-authentication storm.
- **Network compatibility check** — identity reuse is gated on the target network matching.

## 6. Removed: unreliable outage watcher

- The alert-webhook outage watcher was removed (parity with meso-miner). It produced false outage
  signals and the webhook references are gone.
