### **v3.23.0-fix.26.6 — Upstream Sync: IPv4 Fragment Guard, SCTP/WebRTC Tuning, Proto Reconciliation, Memory Bound**

This release is a focused upstream sync of four changes from `urnetwork/connect` (commits
`e05ecee0`, `aee94774`, `45357960`) — the pieces that are genuinely applicable to a
provider binary. Everything mobile-only, Android-gated, or blocked on fork prerequisites
was deliberately left out (see *Out of scope* below). Highlights: a packet-safety fix that
drops fragmented IPv4 packets before misparse, SCTP/WebRTC reliability tuning (correct
receive MTU, faster congestion recovery, a half-open-data-plane watchdog), a
`sender_generation_id` proto field plus a repair of silent proto source drift, and a
hard cap on a diagnostics map that was growing without bound on long-running providers.

### **Highlights**

> [!IMPORTANT]
> **Fragmented IPv4 packets are now dropped in `parseIpv4`** (#311). A non-first
> fragment has no transport header, and a first fragment has a truncated payload —
> without this check both were misparsed as if a transport header were present,
> reading garbage bytes as ports/flags. The fork had zero fragment handling before
> this; now any packet with the MF bit set or a non-zero fragment offset is rejected
> before transport parsing. DF-only and unfragmented packets are unaffected. Ported
> from upstream `e05ecee0` (the guard only — not the ICMP echo path, which a
> SOCKS-relay provider doesn't use).

> [!NOTE]
> **SCTP/WebRTC reliability tuning** (#312). Three corrections ported from upstream
> `aee94774`: `ReceiveMtu` is now 1500 (it's a per-packet demux buffer, not the SCTP
> receive window — the old 4 KiB value only inflated scratch buffers); `SctpCwndCAStep`
> is now 4 MTUs for faster recovery from independent loss on higher-latency paths; and
> a new lazy SCTP progress watchdog detects a blackholed association where ICE consent
> stays healthy but the data plane is dead, tearing it down instead of hanging.

### **Fixes and hardening**

* **`resultDestinationCounts` now bounded** (#314): `SecurityPolicyStatsCollector`'s
  destination-count map had no cap — on a long-running provider relaying to arbitrarily
  many distinct destinations, every unique (protocol, ip, port) tuple got a permanent
  map entry. Now capped at 1024 destinations per result with the final slot reserved as
  an overflow bucket ("other destinations"), and unrecognized result values share one
  unknown-result bucket instead of opening their own uncapped one. Zero-count updates
  are ignored. Ported from upstream `45357960`.
* **`sender_generation_id` proto field** (#313): added to `ExchangeSignals` to
  disambiguate a delayed initial `WaitingForSdpOffer` from a newly restarted passive
  association. Inert until the peer-connection generation-reset logic lands, but
  additive and wire-compatible with peers that don't set it. Ported from upstream
  `45357960` (field only).
* **Proto source drift repaired** (#313): commit `ccada52` (Jul 11) had regenerated
  `transfer.pb.go`/`frame.pb.go` from a different upstream `.proto` during an earlier
  port without landing the matching source changes. Running the documented
  `make build` regen against the stale `.proto` sources would have silently deleted
  `NetworkPeer`, `NetworkPeersReset`, `NetworkPeersUpdate`, and the two
  `TransferNetworkPeers*` enum values — all live types used by
  `transfer_peer_manager.go`. The missing definitions were reconstructed from the
  already-shipping generated code and added back to `transfer.proto`/`frame.proto`;
  `make build` in `protocol/` is safe to run again.

### **Out of scope (deferred, with reasons)**

* **ICMP echo path** (`e05ecee0`): client-facing (end-user pings through NAT); the
  provider relays TCP via SOCKS. Only the fragment-drop guard was ported.
* **Android/cellular P2P work** (`759a5a7d`, `aee94774` Android bits): mobile-gated;
  the fork lacks the `ProviderStreamPolicy`/`DegradedMode` prerequisites the
  cellular fix builds on, so the bug it fixes can't occur here.
* **Lifecycle/budget overhaul** (`45357960` beyond the proto field, `fe8dee32` full
  perf split): needs a dedicated diff session against the fork's divergent
  `message_pool.go`/`memory_budget.go` implementation; not bolted onto this release.
* **Pion dependency bumps**: not needed — `SetSCTPCwndCAStep` verified present at the
  fork's vendored `pion/webrtc` v4.2.15.

### **Upgrade notes**

* No manual action required. Protocol changes are additive and wire-compatible.
* If you've been running the fork for a long time, the `resultDestinationCounts` cap
  only applies going forward — existing unbounded map state from before this release
  is not retroactively compacted (the map is in-memory diagnostics; a restart clears it).

### **Verification**

* Fragment guard: 9 new tests (`ip_fragment_drop_test.go`) — MF-set, non-zero offset,
  max fragment offset, DF-only, reserved-bit-only, DF+reserved combo, unfragmented,
  zero-value return, and a header-builder round-trip; existing `parseIpv4` tests
  unaffected. Includes CodeRabbit-generated tests added after the initial port.
* SCTP/WebRTC: 8 new unit tests (`transport_p2p_webrtc_sctp_settings_test.go`) —
  default settings, watchdog no-op when disabled, real P2P connection under a 2 s
  watchdog timeout passing 64 KiB without false-positive teardown, nil/fresh SCTP
  progress accessors, `SetSCTPCwndCAStep` application, and watchdog/coalescing
  behavior — plus the existing WebRTC suites, all under `-race`.
* Proto: 14 new tests (`protocol_generation_id_test.go`) — marshal/unmarshal
  round-trips for `sender_generation_id` (with/without it set, full round-trip,
  nil-safety, empty field), `NetworkPeer` variants (with/without disconnect time,
  multiple provide modes), `NetworkPeersReset`/`NetworkPeersUpdate` (incl. empty
  peers), frame message-type enum pinning and string names, and a frame carrying
  network-peers message — proving wire serialization, not just compilation.
* Stats bound: 11 new tests (`ip_security_stats_bound_test.go`, 438 lines) — cap
  holds at 1050 distinct destinations, unknown results share one bucket, zero-count
  no-op, per-result independence, overflow `String()`/increment behavior, concurrent
  add safety, and `AddSource`-path bounding.
* All four PRs compile and pass `test-and-lint` + `dash-compat` + `build-and-push` CI.
  CodeRabbit review nitpicks (test-margin robustness on #312, test-aggregation
  assertions on #314) were both addressed before merge; #311/#313 had no actionable
  findings.
