### **v3.23.0-fix.15.2 — README Standardization & Identity Refinement**

This point release finalizes the README overhaul, standardizing all Docker deployment examples with optimized sysctls and automatic identity reporting, while refining the dashboard logic for better privacy and readability.

### **Highlights**

• **Full README standardization** ensures all Docker Run and Compose examples are production-ready and high-performance by default.
• **Deduplicated dashboard identity** logic removes redundant `IP @ IP` strings and messy suffixes.
• **Improved "Safe" copy-pasting** in documentation using hardcoded container names and dynamic volume variables.

### **Fixes and hardening**

• **Refined Dashboard Identity**: Optimized the reporting logic to avoid redundancy. If no manual name or host hostname is provided, the provider now reports **only** the redacted public IP (e.g., `69.x.x.96 [Version]`).
• **Suffix Removal**: Completely removed the `(docker)` and `(binary)` suffixes from labels to keep them short and ensure the version string is never cut off on the dashboard.
• **Correct Metadata**: Updated the environment variables table to accurately reflect the current identity fallback logic and documented the `HOST_HOSTNAME` variable.

### **Documentation**

• **Standardized Docker Examples**: Every `docker run` and `docker compose` example now includes the **optimized conntrack sysctls** and automatic hostname detection flags.
• **Volume Portability**: Switched volume definitions to use `${NAME:-urfix}_config` syntax, making examples safe to run as-is while remaining fully dynamic for multi-node users.
• **Standardized Proxy Paths**: Reverted all proxy volume paths to the standard `/path/to/proxy.txt`.

### **Verification**

Verified the identity logic end-to-end on the Detroit Node. Confirmed that the new deduplicated format `69.x.x.96 [v3.23.0-fix.15.2]` reports correctly and that passing `-e HOST_HOSTNAME=$(hostname)` correctly identifies the host as `UR313`.
