# v3.23.0-fix.30 — 2026-08-16

> [!NOTE]
> Operators do not need to redeploy for the core network path. The provider binary, the Go tools, and the Docker image all change. Fleet nodes should update to this release when convenient.

## 1. Summary

This release completes the cross-platform story for the Go management tools. Auto-start and auto-update now work on Windows through Task Scheduler and on macOS through launchd. Windows discovery and uninstall are fixed. The Docker tool gains host-side proxy commands. The release also replaces the test droplet with runner-based functional testing.

## 2. Cross-Platform Lifecycle

### Windows

Auto-start and auto-update use Task Scheduler instead of the legacy startup-folder shortcut. The weekly default runs Sunday at midnight. The monthly default runs on the first of the month. Uninstall removes the scheduled tasks and deletes the JWT properly. The state directory now matches where the provider stores data. A safety bug meant uninstall could never delete a binary or state directory on Windows. The guard now accepts absolute Windows paths and rejects volume roots.

### macOS

The tool previously had no macOS implementation. Auto-start and auto-update now use launchd agents. The weekly default runs Sunday at midnight. A headless fallback covers servers without a login session. Discovery uses pgrep because macOS has no /proc.

### Linux

Auto-update uses the systemd user timer. The timer is disabled on uninstall. A previous bug let the timer keep firing for a removed provider. Discovery now filters cgroup-derived unit names. A provider inheriting the runner cgroup can no longer target the wrong unit.

## 3. urnet-docker Proxy Commands

The Docker tool gains host-side proxy commands. Add, clear, remove, add-source, remove-source, refresh, and remove-dead run from the host. The exec plumbing is hidden. For example, `urnet-docker proxy add ~/proxies.txt` copies the file into the container and adds the proxies. One container is automatic. Multiple containers use an interactive picker or target flags. Without a TTY, an untargeted command refuses rather than guessing.

The in-container wrapper now supports add-source and remove-source. The clear mapping is corrected. The proxy clear command maps to remove-all because the provider has no clear subcommand. The remove-all mapping drops flags that break argument parsing.

## 4. Testing and CI

### Runner-Based Functional Tests

The test droplet is no longer needed for tool testing. Functional smoke tests run real auth and real providers on free Linux runners. A native job and a Docker job run in parallel. Both verify the provider authenticated before proceeding. The tests fail loudly instead of swallowing errors.

### Soak Tests

A native provider and a containerized provider each run a three-hour soak. The proxy pool is capped at 25 URL-sourced proxies. The soak exercises pool stabilization, restart cycles, client-ID reuse, and a remint cycle. Both soaks pass.

### Multi-Container Tests

Three containers run in three modes. The modes are turbo-v8, auto, and lowmem. The test verifies untargeted commands refuse and flagged commands target correctly. The compose file uses the documented multi-node pattern.

### CI Reliability

The build cache flake that stalled image builds is fixed. Go test retries with a cold cache between attempts. The gofmt gate caught formatting drift; the code is now formatted. CI is green.

### Image Tags

The Docker tag model is explicit. `latest` means the last tagged release. `main` tracks the current code. CI tests pull `main`. Operators who want the stable image pull `latest`.
