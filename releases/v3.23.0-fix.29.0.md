# v3.23.0-fix.29.0 — 2026-08-13

## What's Changed

### 📊 Grades hit the dashboard, and probing finally knows who to trust (PRs #360, #357)

Two changes land together because they're really one story: the fleet
dashboard now shows the A-F grade the provider already computes for every
proxy, and the provider now spends its probe budget in proportion to how
much a proxy actually needs watching.

Provider reports have carried per-proxy grades internally for a while, but
they stopped at the process boundary — the hub never saw them. This release
adds `score`/`graded`/`failed`/`tier`/`last_graded` to the report payload
(all `omitempty`, so older providers keep working unchanged), a new
`proxy_grades` store on the hub (latest-wins per node+proxy, rolled up
hourly, 7-day retention), and a color-coded Grade column on the dashboard
that sits next to — and is deliberately distinct from — the existing
traffic-composite Score column. Grade timestamps are now honest too:
`LastGraded` only advances on a genuine stage-1 grading pass, not on every
report tick. Tiers are sanitized to A-F and HTML-escaped at render time,
closing a stored-XSS path where a malformed tier string from a compromised
or misbehaving node could have executed in an operator's browser.

With grades now visible, the probe scheduler stopped treating every proxy
the same. Paid proxies move to a much wider stale window than free/URL
proxies (6h calm / 3h hot, versus 3h / 1h for URL-sourced proxies) — call it
roughly a third of the previous paid probe volume. A proxy with a positive
billable delta in the last 15 minutes is treated as self-evidently alive and
skipped entirely (measured per-address, not against a cumulative counter, so
a quiet address can't hide behind a busy sibling). A 24h ceiling still
forces a probe regardless of earn-skip, and anything never graded is always
probed — the fast path only kicks in once a proxy has *earned* the benefit
of the doubt. URL proxies also get a 20s startup cooldown, so a
crash-looping box doesn't hammer its proxy list with re-fetches and
re-probes on every restart.

### 🔒 URL proxies now have to prove they aren't lying about who they are (PR #359)

Free URL proxy sources are scraped from the open internet, and some of them
are MITM interceptors presenting a self-signed cert instead of relaying
traffic honestly. This release adds a third admission stage: after the
existing SOCKS5 and API-reachability checks, a TLS handshake is performed
*through the proxy tunnel* with `ServerName` pinned to the real API host.
An interceptor with a self-signed cert fails this handshake and is
classified `probeTLSFailed` — it is never admitted to the pool in the first
place. A proxy that was good at admission time but turns hostile later is
caught by the existing reaper: failure counts accumulate normally and the
proxy is demoted into the standard blacklist/cooldown lifecycle. There's no
new config knob — this simply mirrors the TLS verification the provider
already does for its own auth traffic, applied to the proxies it relays
through.

### Also in this release

- **urnet-tools / urnet-docker are real downloadable binaries now** (#362):
  `release.yml` builds both tools for the full platform matrix and attaches
  them as standalone release assets. Linux/macOS installers fetch and
  sha256-verify the Go binary; docker-only environments get a dedicated
  `install-urnet-docker.sh`. The tools can now self-update
  (`update`/`self-update`), with platform-aware binary format checks
  (ELF/Mach-O/PE) to catch a bad download before it's installed over a
  working copy.
- **Encryption handshake retry** (#361): a failed handshake epoch used to be
  treated as permanently in-flight, so it never got a second attempt.
  `restartHandshake` now retries on a 5s cooldown and frees the parked
  handshake worker instead of leaking it.
- **Eight-PR resource-leak hunt** (#364, #367–#374): source-count refcount
  deduplication (phantom `(dest, source)` entries no longer accumulate),
  four separate stranded-goroutine fixes (parked handshake worker on
  timeout, update-context teardown goroutine, teardown-vs-supersede race
  guard, zombie PQE sessions with `refs==0` via a sane `IdleTimeout`
  derivation), a pooled-buffer leak on `SendEncryptedControl` cancellation,
  a missing receive-callback unsubscription in `Cancel()` that `Close()`
  already had, and two CI flake fixes (window-stats bucket timing,
  paid-grade test literal-IP DNS-cache bypass). Every fix here is
  mutation-proven and was independently reviewed before merge — see
  progress.md for the individual review write-ups.
- **urnet-tools gauntlet fixes** (#376): the first live field-testing pass
  against the beta network on a real droplet turned up eight bugs — a
  missing `version` command, non-functional `report`/`hot-restart`
  implementations, a `hot-restart` path that could restart a unit without
  going through the confirmation gate, an argv bug in the systemd unit-name
  resolution, `summary` not nesting correctly under `proxy`, missing
  `proxy add-source`/`remove-source` subcommands, `refresh --force` not
  being forwarded, and `proxy help` only working in the first argument
  position. All eight are fixed in this release.

## Notes

- **Kill switch**: none of the grade/probe/TLS-admission changes introduce
  a new env var or config flag — they activate automatically on upgrade.
  If paid-proxy probe cadence needs to be reverted for any reason, that
  requires a code-level rollback to fix.28.0, not a runtime toggle.
- **Deploy impact**: the dashboard grade column and probe-cadence changes
  only take effect once provider nodes are redeployed to fix.29.0 — until
  then the hub will simply show no grade data for those nodes (dashboard
  degrades gracefully, no crash). TLS-verified URL proxy admission and the
  leak fixes are also provider-binary changes and need a redeploy to take
  effect on a given node.
- **urnet-tools users**: if you're currently on the shell-script installer,
  the new Go binaries are opt-in via the updated install scripts — nothing
  changes for existing installs until you re-run install or invoke
  `self-update`.
