This release focuses entirely on throughput performance: raising conservative defaults, eliminating bottlenecks, and adding adaptive behavior that scales with available hardware.

---

## Performance Improvements

### Default Throughput Ceilings Raised

| Setting | Before | After | Impact |
|---------|--------|-------|--------|
| TransportBufferSize | 1 | 16 | Removes in-flight message bottleneck |
| TCP MaxWindowSize | 1 MiB | 4 MiB | ~160→640 Mbps ceiling at 50ms RTT |
| UDP MaxWindowSize | 1 MiB | 4 MiB | Parity with TCP window |
| ContractTransferByteSeqScale | 4 | 2 | Full contract size in 2 seqs vs 4 |

**`applyTier3` (performance auto-tier)** now applies actual performance settings instead of doing nothing. Nodes with 4GiB+ RAM running `URNETWORK_PROFILE=auto` get 4 MiB TCP window, 256-depth IP buffers, and 4 MiB transfer queues.

### Auth Rate Limiter Relaxed

| Setting | Before | After |
|---------|--------|-------|
| Min rate | 1 req/s | 20 req/s |
| Max rate | 10 req/s | 200 req/s |
| Burst | 3 | 50 |

New env var: `URNETWORK_AUTH_UNLIMITED=true` bypasses the limiter entirely. The server-side ConnectionRateLimit already caps auth connections per IP hash, so the client-side limiter was unnecessarily serializing fleet warmup.

### MultiRaceClientCount Scales with CPU

| Cores | Race Count |
|-------|-----------|
| 1-2 | 4 |
| 3-4 | 6 |
| 5-8 | 8 |
| 9+ | 12 |

Races more providers for initial packet delivery on multicore machines. The race cost is purely transient (connection-establishment only), so multicore servers absorb it easily.

### Dynamic ContractFillFraction

Contract fill fraction now adapts to observed transfer RTT:
- Low RTT (≤100ms) → fill 0.85 (fill close to capacity, refills are fast)
- High RTT (≥1000ms) → fill 0.50 (more headroom, avoids pipeline stalls)
- Linear interpolation between
- Falls back to static settings value (0.7) when no RTT data available

### Sharded Packet Dispatch

The single-goroutine packet dispatch loop in `LocalUserNat` is replaced with N shard goroutines (one per CPU, capped at 16). Packets are routed via deterministic FNV-1a flow hash of the IP 4-tuple, ensuring per-flow affinity for consistent TCP window tracking.

## Deployment Notes

- **No breaking changes**. All settings are safe defaults that can be overridden.
- **No config migration needed**. Existing `URNETWORK_PROFILE` settings continue to work.
- **Memory impact**: ~3 MiB additional per TCP connection (larger window buffer). Nodes with <2 GiB RAM should use `URNETWORK_PROFILE=lowmem` or `auto`.
- **`URNETWORK_PROFILE=auto` now applies real performance tuning** on 4GiB+ nodes.

  -v urnetwork-vnstat:/var/lib/vnstat \

  -e URNETWORK_AUTH_CODE=<your-auth-code> \

  ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.24
