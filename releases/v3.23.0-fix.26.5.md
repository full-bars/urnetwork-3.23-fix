### **v3.23.0-fix.26.5 — Ghost-Proxy State Fix, Idle Update, Hub Security Hardening**

This release closes a real production incident on a live fleet node: `proxy remove-dead` correctly cleaned up the running fleet and its source config, but `proxy.state` silently accumulated hundreds of ghost entries that could never be cleared — re-reported as "removed" on every subsequent run, forever. It also ships `idle-update` (wait for a quiet traffic window before applying a provider update), a round of hub security hardening, and a message-pool leak fix.

### **Highlights**

> [!IMPORTANT]
> **`proxy.state` ghost-entry fix.** `ProxyReloader.reload()` only pruned `proxy.state` for addresses that were both currently running and no longer desired — but a dead/offline proxy's goroutine has usually already exited by the time it's removed, so it was never in the "running" set to begin with, and its ghost entry was never deleted. Confirmed on a live production node: `remove-dead` reported removing 722 proxies and the config/live fleet updated correctly, but `proxy.state` kept 857 entries — 711 of which existed in neither the config nor the running set. `reload()` now reconciles `proxy.state` against the full desired set (config/file + URL cache) instead, fixing this for `remove-dead`, plain `proxy remove`, and give-up eviction alike. Validated on a fresh test deployment: an explicit `remove-dead` run and a spontaneous URL give-up/eviction cycle both pruned exactly the expected entries with zero left behind.


> [!NOTE]
> **Hub security hardening.** v2 node credentials are now bound to their owning node (a valid credential for node A can no longer act on node B's data), `X-Forwarded-For`/`X-Real-IP` are only honored from configured trusted proxies instead of trusted unconditionally, and `onboard.sh`'s Host header is validated before being interpolated into the generated install script.

### **New features**

* **`urnet-tools idle-update`** (#301): Waits for billable traffic to drop below a threshold (default 5 KiB/s) and stay there for a sustained window (default 5 min) — verified with a second, tighter polling pass — before applying a pending provider update, instead of updating immediately and cutting off whatever's in flight. `--threshold`/`--window` are configurable; `--window 0` updates immediately. Fails closed (treats the node as "not idle") if `billable_rate` isn't available yet, and rejects out-of-range values that could otherwise defeat Bash's integer comparisons. See [Idle Update](../docs/Docker-Deployment.md#-idle-update).
* **Cloudflare Worker sources versioned in-repo** (#304): `dl`, `dl-fullbars`, `geo`, and `provider-redirect` — previously dashboard-only or partially untracked — are now checked in under `workers/` with their `wrangler.jsonc` configs, hardened (GitHub-bound header allowlisting, install-script download-failure handling, response cache-control) and documented in `workers/README.md`. Deploys remain a manual `wrangler deploy` step; nothing here is wired into CI.
* **Node-bound hub credentials + trusted-proxy XFF** (#302): See Highlights above. New `URNETWORK_HUB_TRUSTED_PROXIES` env var — see [Hub Setup](../docs/Hub-Setup.md#trusting-the-reverse-proxys-forwarded-ip).
* **Upstream a2b144c port** (#298): `WindowType`/`OverrideAllowDirect`/PQE/peer-identity support ported from upstream `urnetwork/connect`, plus a fix for a `forceAllowDirect(nil, true)` regression that pinned `WindowTypeQuality` instead of leaving it auto.

### **Fixes and hardening**

* **`proxy.state` ghost-entry pruning** (#305): The core fix described in Highlights. Guards against a related regression risk found in review: if `proxy_url.json` fails to read mid-cycle (corrupt file, transient I/O — not the normal "no URL sources" case), the prune pass is skipped entirely rather than deleting state for still-desired URL proxies over a transient hiccup.
* **Pooled-buffer leaks on backpressure/error** (#303): `tcpSend` could double-return a pooled packet on certain nil-sequence paths; UDP backpressure drops and RST-buffer sharing are now leak-free under load. GCM seal count is now capped per key. Includes a deterministic regression test for the backpressure path (previously flaky).
* **Docker in-place update process handling** (#299): The update path now kills the correct process and respawns it properly — a prior version could target the wrong PID or fail to restart cleanly.
* **`--window`/`--threshold`/rate values out of Bash's int64 range** (#301): `billable_rate` is a Go `uint64`; a value or configured flag above Bash's signed-int64 max previously made comparisons error out silently. Now validated and rejected/treated as unknown up front.
* **Docker worker hardening** (#304): `dl-fullbars`'s GitHub proxy now allowlists outbound headers instead of forwarding everything from the client; the `curl | sh` install dispatcher now fails the install if the script download fails instead of silently running an empty script; `geo` worker's RTT fields use explicit null checks and the response is marked `Cache-Control: no-store` since it echoes the requester's IP.
* **Docs**: Tiered (beginner/intermediate/advanced) setup guides (#297).
* **Ramlog redirect scoped to `provide`/`auth-provide`** (#306): `URNETWORK_RAMLOGS=1` was redirecting stdout/stderr into `/dev/shm/urnetwork.log` for *every* invocation of the binary, not just the long-running `provide` process — one-shot CLI subcommands run via `docker exec` (`proxy remove-dead --preview`, `proxy summary`, etc.) produced no visible output at all. Found while validating the `proxy.state` fix on a live test container. Now scoped to `provide`/`auth-provide` only; one-shot subcommands print directly to the terminal again.

### **Upgrade notes**

* **New & existing installs**: No manual action required. `proxy.state` self-heals on the first `reload()` after upgrading — no need to manually clear it.
* If you've been seeing `remove-dead` report the same proxies removed on every run, or `proxy.state` growing without bound, this release fixes it going forward. Existing ghost entries are cleaned up automatically on the next hot-reload.
* `URNETWORK_HUB_TRUSTED_PROXIES` is opt-in and empty by default — hubs not behind a reverse proxy need no changes. Hubs behind Caddy/nginx should set it to the proxy's own address to keep PAKE join rate-limiting keyed correctly (see Hub Setup docs).

### **Verification**

The `proxy.state` fix was root-caused from a live incident report (config/state divergence on a production node) and validated end-to-end on a fresh test deployment: 500 proxies sourced from three public URL lists, confirmed `remove-dead` prunes state to exactly match what's left (500 → 486, zero ghosts), and separately observed the same reconciliation firing organically during a give-up/eviction cycle before `remove-dead` was ever run. Covered by three new regression tests (ghost pruning; backoff-window URL proxy preservation; URL-cache-read-failure guard) plus the full existing `provider` package suite. Hub and message-pool fixes covered by their own unit test suites.
