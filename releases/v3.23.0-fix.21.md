```sh

```

**Updating an existing install:**

**Docker:**

## What's New

### 🎛️ Hub Dashboard Setup Simplification

Three new `urnet-tools hub` commands for effortless bandwidth hub configuration without manual systemd edits or compilation:

**Set up hub reporting:**
```sh
urnet-tools hub set http://your-hub-host:8080
```

Works with https too (e.g., behind Caddy reverse proxy):
```sh
urnet-tools hub set https://hub.example.com:8080
```

**Disable hub reporting:**
```sh
urnet-tools hub off
```

**Install & run the hub binary as a systemd service:**
```sh
urnet-tools hub install
```

Hub binary is automatically downloaded from the release and runs as a user systemd service. Gracefully handles systems without systemd.

### 📊 Hub Dashboard Polishing & Precision Sorting

We smoothed out the remaining rough edges on the bandwidth dashboard to make managing large fleets completely seamless:

- **Flawless UI State Tracking:** Expanding a proxy list now tracks the exact server ID instead of its numerical row index. This fixes a glitch where expanding a node's proxy list would suddenly jump to a completely different server when the dashboard auto-refreshed and the servers shifted positions.
- **Smart Natural Sorting:** Replaced the crude sorting mechanism with a data-aware engine. The dashboard now natively parses Bytes (KB, MB, GB), Network Speeds (Mbps), and Time Strings. It also implements standard natural lexicographical sorting (so `proxy[3]` correctly sorts before `proxy[29]`), resulting in mathematically perfect columns.
- **Persistent Sort Directions:** Your custom column sorts (e.g. sorting by memory or clients) now flawlessly persist through the 30-second DOM auto-refreshes.
- **Billable Traffic Highlighting:** Billable traffic is now explicitly styled in red underneath the total traffic numbers for instant visibility.
- **Math Guardrails:** Added a delta-time division guard to prevent extreme speed reporting anomalies (e.g. `2153297604415 Mbps`) when a provider resets its internal byte counters mid-heartbeat.

### 🔍 Clearer Authentication Error Messages

Fixed misleading auth failure logs. When proxies timeout connecting to the auth API, the log now correctly reports `"network error reaching API"` instead of suggesting JWT expiry. This makes it easier to distinguish between network issues and credential problems during troubleshooting.

### 🩺 Per-Proxy Failure Diagnostics

Dead and degraded proxies in the `[health][proxies]` log now include an inline failure breakdown, making it faster to triage which proxies are struggling and why — without grepping separate log files.

Before:
```
dead: proxy[12] (203.0.113.45:1081), proxy[47] (198.51.100.12:3128)
```

After:
```
dead: proxy[12] (203.0.113.45:1081) [timeout:8, last_err:"context deadline exceeded"]
      proxy[47] (198.51.100.12:3128) [auth:3, drops:1, last_err:"connection refused"]
```

Failure counters are split into three categories automatically:

| Counter | Meaning |
|---------|---------|
| `auth:N` | Auth API returned a non-timeout error (bad credentials, 4xx) |
| `timeout:N` | Auth API was unreachable within the deadline |
| `drops:N` | Transport connection was lost after a successful auth |

The `last_err` field shows the raw error string from the most recent failure, giving concrete context without requiring verbose logging.

### 🔧 Internal: Logger Interface Migration (glog → Logger)

All 357 direct `glog.*` call sites across 21 core files have been migrated to the `Logger` interface, matching the upstream `urnetwork/connect` codebase. This is a zero-user-visible change that:

- Eliminates merge conflicts on every upstream rebase touching core data-plane files
- Enables structured logger injection via `Settings` structs (`Log Logger` field)
- Makes the codebase ready for the planned `ip.go` gVisor rewrite (prerequisite for #62)
