# v3.23.0-fix.35.4

Previous release: [v3.23.0-fix.35.3](https://github.com/full-bars/urnetwork-3.23-fix/releases/tag/v3.23.0-fix.35.3).

@Ryanmello07 contributed UDP relay support for proxied clients. You can also capture diagnostics from a running provider without a restart. I improved proxy maintenance, uninstall safety and Windows lifecycle commands.

Legend: **[redeploy]** needs the new provider, tool or container image. **[installer]** needs the updated installer or script. **[no redeploy]** covers documentation, CI and tests.

## Quick start

Install on Linux or macOS:

```sh
curl -fSsL https://install.fullbars.xyz | sh -s -- install
```

On FreeBSD, run the installer as a non-root service account with sudo:

```sh
fetch -qo - https://install.fullbars.xyz | sudo sh -s -- install
```

On Windows, use PowerShell:

```powershell
irm https://dl.fullbars.xyz/install-win.ps1 | iex
```

Run the provider in Docker with a persistent volume and a single-use auth code from https://ur.io:

```sh
docker run -d --name urfix --pull always --restart unless-stopped --cap-add NET_ADMIN --cap-add NET_RAW --sysctl net.ipv4.ip_forward=1 -e AUTH=authcode -e AUTHCODE='YOUR_AUTH_CODE_HERE' -v urnetwork_data:/root/.urnetwork ghcr.io/full-bars/urnetwork-3.23-fix:latest
```

This release is the provider line. For miner setup, use the separate miner release and its instructions; this workflow does not publish a miner image.

## What changed

### Networking and proxies

- **Proxied client UDP uses the proxy's SOCKS5 UDP relay** **[redeploy]** ([#1042](https://github.com/full-bars/urnetwork-3.23-fix/pull/1042)). A failed relay check or a known TCP and UDP exit mismatch refuses the flow. If the check is unknown, including when it times out or cannot determine the TCP exit, the flow may use an unverified exit. It never falls back to the host address. IPv6 destinations are refused because the check proves only IPv4. Proxied UDP flows close when either sends or replies are idle for 120 seconds.
- **Degraded URL proxies retire after a down window** **[redeploy]** ([#1031](https://github.com/full-bars/urnetwork-3.23-fix/pull/1031)). Degraded eviction is off unless `degraded_cleanup_threshold` is set. Trim-held proxies are protected, and time frozen by a trim does not count. Invalid thresholds warn and leave degraded cleanup off.
- **Proxy refresh previews use the reloader's desired set** **[redeploy]** ([#1040](https://github.com/full-bars/urnetwork-3.23-fix/pull/1040)). The preview includes cached URL proxies, so it no longer lists retained proxies as removals.
- **Proxy list fetches and probes report progress** **[redeploy]** ([#1044](https://github.com/full-bars/urnetwork-3.23-fix/pull/1044)). Logs name the source and report download and probe progress, with a heartbeat during long checks.
- **Windows IPv6 egress binding uses the socket family** **[redeploy]** ([#1039](https://github.com/full-bars/urnetwork-3.23-fix/pull/1039)). An embedding caller that sets an egress interface receives a binding error instead of a silent IPv6 pin failure. H3 logs a failed UDP bind and still attempts the connection. This provider tree does not set an egress interface index itself.
- **A shared UDP socket no longer leaks during registration** **[redeploy]** ([#1038](https://github.com/full-bars/urnetwork-3.23-fix/pull/1038)).

### Diagnostics and provider

- **`urnet-tools diag` captures a running provider without a restart** **[redeploy]** ([#1034](https://github.com/full-bars/urnetwork-3.23-fix/pull/1034)). It saves a heap profile, goroutine stacks, a summary and, when available, a 30-second CPU profile. It requires 512 MiB of free space and keeps five bundles. Bundles can contain sensitive data. The change was not exercised end to end against a live provider in the original PR.
- **H1+ handshake failures are reported by cause** **[redeploy]** ([#1032](https://github.com/full-bars/urnetwork-3.23-fix/pull/1032)). Use the class metrics or the existing total, not both together.
- **The client JWT store skips unchanged writes** **[redeploy]** ([#1033](https://github.com/full-bars/urnetwork-3.23-fix/pull/1033)). Completed writes report their cause and counts. The amount of disk I/O saved depends on how often content is unchanged.
- **Metrics disable values override saved state** **[redeploy]** ([7e377fca1](https://github.com/full-bars/urnetwork-3.23-fix/commit/7e377fca1)). Set `URNETWORK_METRICS` to `off`, `false`, `no`, `0` or `none` to disable the listener. A live enable cannot override the environment.
- **The proxy health line no longer repeats the down count** **[redeploy]** ([#1030](https://github.com/full-bars/urnetwork-3.23-fix/pull/1030)). The `dead` and `degraded` counts remain.
- **The TUI clears clipped wide characters at the left edge** **[redeploy]** ([#1038](https://github.com/full-bars/urnetwork-3.23-fix/pull/1038)).

### Install, update and lifecycle

- **Uninstall stops the provider before removing files** **[redeploy]** ([#1043](https://github.com/full-bars/urnetwork-3.23-fix/pull/1043)). On Unix, a failed stop or a provider that still answers prevents removal. On Windows, uninstall also checks for other processes that may share the profile and refuses unsafe removal. The PowerShell uninstaller waits for the provider to exit before deleting files **[installer]**. Its wait logic was tested with a harness, not a full uninstall.
- **Windows lifecycle commands protect shared profiles** **[redeploy]** ([#1043](https://github.com/full-bars/urnetwork-3.23-fix/pull/1043)). Normal stop and restart refuse when another process may share the profile. Force stop bypasses that check but keeps a socket that still has a live listener. Update and tune now restart a running provider through the Windows stop and start path. They leave a stopped provider stopped.
- **Windows start avoids launching a second provider** **[redeploy]** ([#1043](https://github.com/full-bars/urnetwork-3.23-fix/pull/1043)). It checks for running provider processes and the control socket first. If the process list fails, it warns and checks the socket only.
- **Linux binary swaps restore the extender bind capability** **[redeploy]** **[installer]** ([#1036](https://github.com/full-bars/urnetwork-3.23-fix/pull/1036), [#1044](https://github.com/full-bars/urnetwork-3.23-fix/pull/1044)). The updater and installer attempt to restore `cap_net_bind_service` and warn if they cannot verify it. The container image includes the required capability tools. Its updater skips setting the capability when the container's bounding set excludes it, because the binary would otherwise fail to start. The extender remains a work in progress and does not activate for clients.
- **FreeBSD fallback PID scans detect a starting provider** **[redeploy]** **[installer]** ([#1038](https://github.com/full-bars/urnetwork-3.23-fix/pull/1038)). The scan includes all users and matches the provider executable and `provide` argument.
- **The macOS wrapper forwards proxy command arguments** **[installer]** ([#1037](https://github.com/full-bars/urnetwork-3.23-fix/pull/1037)). Arguments to `proxy refresh` and `proxy remove-dead` now reach the provider. This includes `--preview`.

### Documentation and maintenance

- **Docker command guidance is corrected** **[no redeploy]** ([#1044](https://github.com/full-bars/urnetwork-3.23-fix/pull/1044)). The image's shell `urnet-tools` does not implement `direct`, `usage`, `rename`, `sn-status` or `metrics`. Run `direct` and `sn-status` through `docker exec <container> provider` instead. The documentation also corrects node naming, FreeBSD service-account guidance, extender details and log examples.
- **SN25 live figures were refreshed** **[no redeploy]** ([7cdc2edc7](https://github.com/full-bars/urnetwork-3.23-fix/commit/7cdc2edc7)). See the [head-tier page](https://github.com/full-bars/urnetwork-3.23-fix/blob/main/docs/Bittensor-Head-Tier.md) for the latest automatically refreshed figures.
- **Formatting and regression coverage were updated** **[no redeploy]** ([#1035](https://github.com/full-bars/urnetwork-3.23-fix/pull/1035), [#1044](https://github.com/full-bars/urnetwork-3.23-fix/pull/1044)).
