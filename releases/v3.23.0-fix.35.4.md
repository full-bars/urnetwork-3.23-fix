# v3.23.0-fix.35.4

**Released:** 2026-11-06.

Previous release: [v3.23.0-fix.35.3](https://github.com/full-bars/urnetwork-3.23-fix/releases/tag/v3.23.0-fix.35.3).

I added UDP relay support for proxied clients and diagnostic captures for running providers. I also improved proxy maintenance, uninstall safety and Windows lifecycle commands.

Legend: **[redeploy]** needs the new provider, tool or container image. **[installer]** needs the updated installer or script. **[no redeploy]** covers documentation, CI and tests.

## Quick start

Install on Linux or macOS:

```sh
curl -fSsL https://install.fullbars.xyz | sh -s -- install
```

On FreeBSD, run the installer as a non-root service account with sudo:

```sh
fetch -qo - https://install.fullbars.xyz | sudo sh -s -- install
```

On Windows, use PowerShell:

```powershell
irm https://dl.fullbars.xyz/install-win.ps1 | iex
```

Run the provider in Docker with a persistent volume and a single-use auth code from https://ur.io:

```sh
docker run -d --name urfix --pull always --restart unless-stopped --cap-add NET_ADMIN --cap-add NET_RAW --sysctl net.ipv4.ip_forward=1 -e AUTH=authcode -e AUTHCODE='YOUR_AUTH_CODE_HERE' -v urnetwork_data:/root/.urnetwork ghcr.io/full-bars/urnetwork-3.23-fix:latest
```

This release is the provider line. For miner setup, use the separate miner release and its instructions; this workflow does not publish a miner image.

## What changed

### Networking and proxies

- **I routed proxied client UDP through the proxy's SOCKS5 UDP relay** **[redeploy]** ([#1042](https://github.com/full-bars/urnetwork-3.23-fix/pull/1042)). A failed relay check or a known TCP and UDP exit mismatch refuses the flow. If the check is unknown, including when it times out or cannot determine the TCP exit, the flow may use an unverified exit. It never falls back to the host address. IPv6 destinations are refused because the check proves only IPv4. Proxied UDP flows close when either sends or replies are idle for 120 seconds.
- **I added a down window for retiring degraded URL proxies** **[redeploy]** ([#1031](https://github.com/full-bars/urnetwork-3.23-fix/pull/1031)). The default is six hours. Trim-held proxies are protected, and time frozen by a trim does not count. Invalid thresholds warn and disable degraded cleanup.
- **I aligned proxy refresh previews with the reloader's desired set** **[redeploy]** ([#1040](https://github.com/full-bars/urnetwork-3.23-fix/pull/1040)). The preview includes cached URL proxies, so it no longer lists retained proxies as removals.
- **I added progress reporting for proxy list fetches and probes** **[redeploy]** ([#1044](https://github.com/full-bars/urnetwork-3.23-fix/pull/1044)). Logs name the source and report download and probe progress, with a heartbeat during long checks.
- **I fixed Windows IPv6 egress binding to use the socket family** **[redeploy]** ([#1039](https://github.com/full-bars/urnetwork-3.23-fix/pull/1039)). An embedding caller that sets an egress interface receives a binding error instead of a silent IPv6 pin failure. H3 logs a failed UDP bind and still attempts the connection. This provider tree does not set an egress interface index itself.
- **I fixed a shared UDP socket leak during registration** **[redeploy]** ([#1038](https://github.com/full-bars/urnetwork-3.23-fix/pull/1038)).

### Diagnostics and provider

- **I added `urnet-tools diag` to capture a running provider without a restart** **[redeploy]** ([#1034](https://github.com/full-bars/urnetwork-3.23-fix/pull/1034)). It saves a heap profile, goroutine stacks, a summary and, when available, a 30-second CPU profile. It requires 512 MiB of free space and keeps five bundles. Bundles can contain sensitive data. The change was not exercised end to end against a live provider in the original PR.
- **I added cause reporting for H1+ handshake failures** **[redeploy]** ([#1032](https://github.com/full-bars/urnetwork-3.23-fix/pull/1032)). Use the class metrics or the existing total, not both together.
- **I stopped the client JWT store from writing unchanged data** **[redeploy]** ([#1033](https://github.com/full-bars/urnetwork-3.23-fix/pull/1033)). Completed writes report their cause and counts. The amount of disk I/O saved depends on how often content is unchanged.
- **I made metrics disable values override saved state** **[redeploy]** ([7e377fca1](https://github.com/full-bars/urnetwork-3.23-fix/commit/7e377fca1)). Set `URNETWORK_METRICS` to `off`, `false`, `no`, `0` or `none` to disable the listener. A live enable cannot override the environment.
- **I removed the repeated down count from the proxy health line** **[redeploy]** ([#1030](https://github.com/full-bars/urnetwork-3.23-fix/pull/1030)). The `dead` and `degraded` counts remain.
- **I fixed clipped wide characters at the left edge of the TUI** **[redeploy]** ([#1038](https://github.com/full-bars/urnetwork-3.23-fix/pull/1038)).

### Install, update and lifecycle

- **I made uninstall stop the provider before removing files** **[redeploy]** ([#1043](https://github.com/full-bars/urnetwork-3.23-fix/pull/1043), [#1046](https://github.com/full-bars/urnetwork-3.23-fix/pull/1046)). On Unix, a failed stop or a provider that still answers prevents removal. On Windows, uninstall also checks for other processes that may share the profile and refuses unsafe removal. The PowerShell uninstaller waits for exit, recognizes the legacy install path and refuses removal when another provider is running or process checks fail **[installer]**. Its wait logic was tested with a harness, not a full uninstall.
- **I made Windows lifecycle commands protect shared profiles** **[redeploy]** ([#1043](https://github.com/full-bars/urnetwork-3.23-fix/pull/1043)). Normal stop and restart refuse when another process may share the profile. Force stop bypasses that check but keeps a socket that still has a live listener. Update and tune now restart a running provider through the Windows stop and start path. They leave a stopped provider stopped.
- **I made Windows start avoid launching a second provider** **[redeploy]** ([#1043](https://github.com/full-bars/urnetwork-3.23-fix/pull/1043)). It checks for running provider processes and the control socket first. If the process list fails, it warns and checks the socket only.
- **I added extender bind capability restoration after Linux binary swaps** **[redeploy]** **[installer]** ([#1036](https://github.com/full-bars/urnetwork-3.23-fix/pull/1036), [#1044](https://github.com/full-bars/urnetwork-3.23-fix/pull/1044), [#1046](https://github.com/full-bars/urnetwork-3.23-fix/pull/1046)). The updater and installer attempt to restore `cap_net_bind_service` and check the process bounding set before applying it. They remove a blocked file capability only when unrelated capabilities will not be lost. The container image includes the required capability tools. The extender remains a work in progress and does not activate for clients.
- **I made FreeBSD fallback PID scans detect a starting provider** **[redeploy]** **[installer]** ([#1038](https://github.com/full-bars/urnetwork-3.23-fix/pull/1038)). The scan includes all users and matches the provider executable and `provide` argument.
- **I fixed the macOS wrapper to forward proxy command arguments** **[installer]** ([#1037](https://github.com/full-bars/urnetwork-3.23-fix/pull/1037)). Arguments to `proxy refresh` and `proxy remove-dead` now reach the provider. This includes `--preview`.
