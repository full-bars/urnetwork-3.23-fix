# v3.23.0-fix.28.0 — 2026-08-12

## What's Changed

### 🔑 Provider JWT renewal (the big one — PR #356)

The beta backend (and mainnet's new token format) now mints 24-hour JWTs.
Previously each proxy's client JWT was minted once at startup and never
renewed in-process, so after ~24h of uptime every proxy's token expired,
all audit/contract/transport auths returned 401, and providers silently
became black holes: registered, proxies up, but no contracts and earnings
decayed to zero.

This release adds in-process renewal of each proxy's client JWT, preserving
the client_id identity (server-side reliability reputation is kept):
- Renews 12h before expiry, retries hourly, and renews immediately on a 401
- Works through the same /network/auth-client path with the existing
  ClientId, so the server re-signs the SAME identity
- A process-wide mutex + shared auth rate limiter prevent API stampedes on
  boxes with many proxies; failed renewals keep the old token and retry
- No-op on backends still issuing long-lived tokens — existing deployments
  are unaffected

### Also in this release
- urnet-docker exec flag forwarding + ramlogs container-name resolution
- EncryptionMode tri-state port (Off/Opportunistic/Required)
- Bounded per-peer TLS establishment (60s handshake timeout default, was
  unbounded) — prevents worker/goroutine retention against departed peers
- window-stats test flake fix under -short (deterministic bucket span)
