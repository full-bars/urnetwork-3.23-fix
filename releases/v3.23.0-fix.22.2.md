**Docker:**
```sh
docker pull ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.22.2
```

```sh
docker run -d \
  --name=urfix \
  --restart=unless-stopped \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  -e URNETWORK_AUTH_CODE=YOUR_AUTH_CODE \
  -e HOST_HOSTNAME=$(hostname) \

  -v urfix_config:/root/.urnetwork \
  ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.22.2
```

## Highlights

### 🛡️ Proxy Reachability Probing & Auth Rate Limiter Protection
A URL-sourced proxy list can contain mostly dead entries. Each dead entry's auth timeout was feeding into the shared auth rate limiter and getting misclassified as the API being overloaded, throttling the rate for every other proxy too — so a list full of dead entries could stall warmup for everyone, not just the proxies that were actually dead.
- **Probe before merge**: a fetched proxy list is now checked for plain TCP reachability before any entry is added to the candidate pool. Dead entries never get an auth attempt in the first place.
- **Probe before auth**: the auth retry loop checks a proxy's reachability before spending a slot on the shared rate limiter. A dead proxy's failure no longer reports to the limiter, so it can't drag down the rate for live proxies. Only a confirmed-reachable proxy's actual auth failure still counts as a real signal.
- No new caps or automatic cleanup involved — already-cached proxies and ones that simply haven't had a turn yet are untouched.
