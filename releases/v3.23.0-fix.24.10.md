## What's New

### URL-sourced proxies no longer spam logs on dead addresses

URL-sourced proxies that connect but fail auth (e.g. a live SOCKS5 endpoint behind a stale password) used to retry on a flat 15-minute cycle forever — keeping the auth rate limiter busy and filling logs with give-up messages for hopeless entries.

Now each address gets an escalating backoff:

| Give-up | Delay |
|---|---|
| 1st | 15m (±3m jitter) |
| 2nd | 30m (±6m) |
| 3rd | 1h (±12m) |
| 4th | 2h (±24m) |
| 5th | 4h (±48m) |
| 6th | 8h (±1.6h) |
| 7th | 16h (±3.2h) |
| 8th+ | 24h (±4.8h, capped) |

After **10 give-up cycles** the address is **evicted permanently** — written to a blacklist in `proxy_url.json` that survives provider restarts. A hopeless proxy can never re-enter the auth lottery.

Also fixes a concurrent bug where the health heartbeat's prune step silently wiped failure/give-up counters during the wait window between cycles, resetting the backoff progress.

### File-based proxies start before URL-sourced proxies on boot

`runProxyURLFetcher` and `runProxyURLCleanup` goroutines were launched before the proxy-file reloader was ready — URL proxies would race ahead of operator-curated file proxies and fill auth slots with less-reliable addresses. Both goroutines now launch after `reloader.StartWatcher(ctx)` ensures the file proxy list is loaded first.

## Under the Hood

- `proxyFailureHistory.giveUps` map tracks per-address give-up cycles separately from per-attempt failure counters. `Reset` and `Prune` extended to cover both maps.
- `proxyURLGiveUpRetryDelay(giveUpCount)` replaces the flat `proxyURLGiveUpRetryAfter` constant with escalating backoff capped at 24h.
- `ProxyURLState.Blacklist map[string]time.Time` persisted in `proxy_url.json`; `mergeProxyURLEntries` skips blacklisted addresses.
- `evictProxyURLAddress()` removes from cache, writes blacklist entry, triggers proxy reload.
- `currentDesiredProxyAddresses()` returns file/internal + URL cache addresses (independent of live health registration) — used by `Prune` instead of `report.Bandwidth` so counters aren't wiped during give-up wait windows.
- `paceMonitor` goroutine now exits after printing the warmup completion line instead of re-emitting it every 30 seconds indefinitely (PR #122).
