# v3.23.0-fix.35.9

**Released:** 2026-11-11.

Previous release: [v3.23.0-fix.35.8](https://github.com/full-bars/urnetwork-3.23-fix/releases/tag/v3.23.0-fix.35.8).

This release adds OpenBSD support (build, installer, service management, release assets) and fixes proxy health event output and extender sysctl handling.

Legend: **[redeploy]** needs the new provider, tool or container image. **[installer]** needs the updated installer or script. **[no redeploy]** covers documentation, CI and tests.

## Quick start

Install on Linux or macOS:

```sh
curl -fSsL https://install.fullbars.xyz | sh -s -- install
```

On FreeBSD, run the installer as a non-root service account with sudo:

```sh
fetch -qo - https://install.fullbars.xyz | sudo sh -s -- install
```

On OpenBSD, choose an existing non-root service account and replace `urnet` with its name:

```sh
ftp -o urnet-install.sh https://dl.fullbars.xyz/install-openbsd.sh
doas env SERVICE_USER_OVERRIDE=urnet sh urnet-install.sh install
```

On Windows, use PowerShell:

```powershell
irm https://dl.fullbars.xyz/install-win.ps1 | iex
```

Run the provider in Docker with a persistent volume and a single-use auth code from https://ur.io:

```sh
docker run -d --name urfix --pull always --restart unless-stopped --cap-add NET_ADMIN --cap-add NET_RAW --sysctl net.ipv4.ip_forward=1 -e AUTH=authcode -e AUTHCODE='YOUR_AUTH_CODE_HERE' -v urnetwork_data:/root/.urnetwork ghcr.io/full-bars/urnetwork-3.23-fix:latest
```

This release is the provider line. For miner setup, use the separate miner release and its instructions; this workflow does not publish a miner image.

## What's changed

### Added

- **OpenBSD build support** (`sysmem_openbsd.go`, `diag_disk_openbsd.go`, `internal/urnettools/discover_openbsd.go`, `internal/urnettools/lifecycle_openbsd.go`, `internal/urnettools/jwt_read_openbsd.go`, `scripts/Provider_Install_OpenBSD.sh`, `docs/OpenBSD.md`). The provider and `urnet-tools` build for OpenBSD. Process discovery, physical memory and disk diagnostics use OpenBSD interfaces. An OpenBSD installer, `rcctl` service setup, cron auto-update and release assets are available. `urnet-tools start`, `stop`, `restart` and `update` use `rcctl`, and `uninstall` stops and disables the service. The `rc.d` start command and the update path are untested on a real OpenBSD host. `urnet-tools optimize` is not supported. See the [OpenBSD guide](docs/OpenBSD.md) for limitations.

### Fixed

- **Proxy health event output is bounded** (`internal/urnettools/legacy_cmds.go`, `internal/urnettools/proxy_health_output_test.go`). The `proxy health` event log output is now capped, preventing unbounded growth. A new test proves the bound.
- **Extender sysctl route applies once for several providers** (`internal/urnettools/extender_setup.go`, `internal/urnettools/extender_sysctl_multi_test.go`). When multiple providers share a host, the sysctl route is applied once instead of per-provider.
- **OpenRC restart verification does not run the image** (`internal/urnettools/update.go`, `internal/urnettools/update_verify_openrc_test.go`). The updater verifies an OpenRC restart without executing the image, improving safety.

### Changed

- **Release pipeline includes OpenBSD** (`.github/workflows/release.yml`). The build matrix now produces OpenBSD amd64 and arm64 artifacts, per-platform tarballs, and VirusTotal scan entries.
- **Cloudflare worker serves the OpenBSD installer** (`workers/dl/src/index.js`). `https://dl.fullbars.xyz/install-openbsd.sh` and `https://install.fullbars.xyz` auto-detect OpenBSD hosts.

## Known limits

- OpenBSD runtime (rcctl start/check/stop/boot, syslog, hw.physmem 64-bit, doas rule permissions) has not been verified on a real OpenBSD host. The rc.d script uses the default rc_start with rc_bg=YES, which is version-independent across OpenBSD 7.x.
- `urnet-tools optimize` is not supported on OpenBSD.
- Some installer cleanup and ZRAM package and service errors remain suppressed (carried from 35.8).
