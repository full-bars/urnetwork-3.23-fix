# v3.23.0-fix.34.3

**Released:** 2026-10-22. Base tag `v3.23.0-fix.34.2`.

Legend: **[redeploy]** needs the built artifact redeployed. **[installer]** needs the installer or unit refresh. **[no redeploy]** docs, CI or tests only.

## Security

- **The IP blocker table now syncs with CFAA** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/947>). The scheduled sync only pulled the CFAA file, so the blocker table drifted with no PR to show it. The current gap was 163,972 to 164,212 blocked hosts, and the CFAA prefixes were behind too (42,642/542 against 46,733/597). Nothing compared that file, so CI would not have caught it. The fetch step now reads both, and a check fails when either drifts.

## Reliability

- **`docker stop` now reaches the provider** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/940>). The entrypoint execs a shell, and a shell as PID 1 has no default action for SIGTERM. The provider never heard the stop, so Docker SIGKILLed the container at the grace timeout and the shutdown path was skipped. Every release since 34.0-rc2 showed a 10 to 11 second stop in the shakedown. The supervisor now forwards the signal and waits for the successor before it exits.
- **The nightly tarball picker uses this platform's asset** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/940>). The update path could select another platform's tarball. It now matches the architecture before it picks.
- **A test proves the stop trap signals a hotswap successor** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/943>). The missing case was a successor that is not this shell's child. The harness can now run against a private app path, so the case cannot signal a real provider on the host.
- **The stop path waits for a draining successor before PID 1 exits** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/949>). The stop branch returned as soon as the tracked child was reaped, so a container whose hotswap successor was still draining reached exit and Docker SIGKILLed the successor at the grace timeout. The exit hands over to the successor wait, which is bounded below the stop timeout.
- **`urnet-tools` will not pick a release it cannot install** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/949>). A stable release that carries only the fat tarball was selected and then had no `linux-<arch>` asset, so an untagged update exited without installing anything and without an error that named the cause. Releases without a per-arch asset are skipped when one is needed.
- **An api failure no longer reads as a missing tag** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/949>). `curl -s` returns success with an error body on 403 or 500, and the empty `tag_name` was reported as a tag that does not exist. The http status is checked and the real failure is named, so a rate limit, a revoked token and a genuinely absent tag are told apart.

## Observability

- **The `[pqe]` line counts handshake stages and negotiated curves** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/944>). A zero classical count used to mean either "no session" or "nothing measured". The line now reports attempts, tls_ok, verified and identity_failed, plus a per-curve histogram. A peer that falls back to a classical group appears in the histogram by name.
- **The same counters reach `/metrics` and the dashboard** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/946>). New families are `urnet_sessions_handshake_total{stage=...}` and `urnet_sessions_curve_total{curve=...}`. The curve family stays absent until a handshake completes. Two dashboard panels show both rates.
- **Lifetime counters survive a proxy exit** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/946>). Each proxy owns its encryption manager, and the manager was dropped on exit, so a `_total` could go backwards and `rate()` read it as a reset. A departing manager's lifetime counts now fold into a provider-wide accumulator first.

## Documentation

- **SN25 costs come from the chain** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/941>). The head-tier page now shows the live cost table. A scheduled job regenerates it between markers, so the numbers do not age into guesses.
- **Four Bittensor claims are corrected** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/945>). v1 and v2 claim triggers are described separately. The signed challenge quotes the message, because an unquoted copy breaks verification. The stopped-daemon answer now says unsigned v1 claims still expire. The consent is scoped to one URnetwork account.

## Deploy notes

- **The provider needs a redeploy for the counters and the stop fix.** The old binary keeps the old behaviour. The counters stay at zero on an old process.
- **The dashboard panels need the new build before they show data.** The panels exist now, but a provider that runs 34.2 sends none of these series.
- **No installer change is required.** The unit files and the install flow are unchanged in this window.

## Caveats

- The stop fix is proven by a unit test and by the shakedown, not by a live fleet stop. Watch the first few upgrades.
- The curve histogram names only what this node negotiated. Traffic that is forwarded through the node never opens such a session here, so it is not counted.
- The blocker table sync depends on the upstream feed. A missing upstream file fails the job rather than writing a partial table.
