This release ships the universal dashboard identity reporting and streamlined multi-node scaling work, together with a full pre-merge hardening pass. Verified live on a test node.

### Highlights
- Every provider now identifies itself on your Client Manager as `NodeName @ redacted-IP [Version]`, so you can tell nodes apart at a glance.
- Run multiple nodes from a single auth code with a shared config volume.
- Authenticate via the `URNETWORK_AUTH_CODE` environment variable, including codes that start with a dash.

### New features
- **Dashboard identity reporting (always on):** The provider fetches its public IP (via `ip.me`, 5 second timeout) and reports `NodeName @ first.x.x.last [Version]` to the backend, with the IP redacted to its first and last octets. No configuration needed.
- **Environment-variable auth:** `URNETWORK_AUTH_CODE` supplies the first-run auth code without command-line parsing issues, so dash-prefixed codes work. It is ignored once a JWT exists on the volume.
- **Shared-JWT multi-node scaling:** A documented 3-in-1 `docker-compose.yml` runs several nodes from one auth code and a shared config volume. The first node authenticates; a healthcheck plus `depends_on` makes the others wait for the shared JWT instead of crash-looping on first boot.
- **`ENABLE_IP_CHECKER` retained as a separate opt-in:** The full-IP startup diagnostic stays available (default off), distinct from the always-on redacted dashboard reporting.

### Fixes and hardening
- **Shared-volume crash safety (jwt build):** The restart loop no longer deletes the JWT after repeated crashes. In the shared-config model that would have deauthenticated the whole stack with no recovery (the auth code is single-use). The container now exits for Docker to restart it with the session intact.
- **Restart loops actually retry now:** Fixed exit-code handling across the jwt, stable, nightly, and pelican entrypoints, where `provide || true` (or a bare `provide` under `set -e`) had silently disabled the in-script crash and backoff logic.
- **Nightly watcher:** Fixed an unexpanded shell variable in the process check that made the auto-update watcher relaunch a duplicate provider every cycle.
- **Provider binary:** `URNETWORK_AUTH_CODE` no longer overrides an explicit command-line auth code, and the redacted IP is parsed with `net.ParseIP` so a stray port cannot leak into the label.
- **Graceful ZRAM handling:** Hosts whose kernels lack zram support complete `optimize` cleanly (zram is skipped with a warning; other tuning continues).

### Upgrade notes
- No action required for existing single-node deployments. Identity reporting turns on automatically; set `URNETWORK_NODE_NAME` to control the label.
- The full-IP diagnostic stays off unless you set `ENABLE_IP_CHECKER=true`.
- For multi-node hosts, see the updated 3-in-1 scaling guide in the README.

### Verification
Built natively (amd64) and run as an isolated container on a live test node: the environment auth-code path writes the JWT and starts `provide`, and the dashboard label rendered correctly as `<name> @ <redacted-ip> [version]`. `go build`, `go vet`, and shell syntax checks all pass.
