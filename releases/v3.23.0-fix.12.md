## Eco mode + lowmem contract floor fix

### Eco mode (new in fix.12)

Providers on RAM-constrained systems (1-2 GiB) were accumulating cold Go heap pages that the OS had to swap out, causing latency spikes and swap pressure without any corresponding benefit. Standard lowmem mode addressed this by shrinking buffers, but that came at a throughput and earnings cost.

Eco mode takes a different approach: GC tuning only, no buffer changes.

- **`URNETWORK_PROFILE=eco`**: at startup, sets GOMEMLIMIT to 75% of the detected memory ceiling (cgroup-aware — reads cgroup v2/v1 limits so Docker `--memory` containers get the correct value, not the host's total RAM) and sets `GOGC=50` as a baseline. An explicit `--max-memory` flag or `GOMEMLIMIT` env var always takes precedence.
- **`runEcoMemoryMonitor` goroutine**: watches available memory every 30 seconds and dynamically tightens GC pressure when RAM is low — `GOGC=25` under pressure (<300 MiB available), `GOGC=10` at critical (<150 MiB) — then relaxes when headroom recovers. Hysteresis between the pressure and recovery thresholds prevents oscillation. Inside Docker containers, uses cgroup headroom rather than host `MemAvailable` so pressure detection fires correctly regardless of host RAM.
- **`urnet-tools eco <on|off>`**: toggles eco mode on the systemd provider service with cgroup-aware GOMEMLIMIT calculation. Merges eco-specific env vars into the existing `override.conf` rather than overwriting it, so settings like ramlogs are preserved.

Buffers, contract sizes, and proxy behavior are unchanged — throughput and earnings are unaffected.

### lowmem contract floor fix

- **`lowmem` initial contract size raised from 16 KiB to 256 KiB**: the 16 KiB floor forced constant contract renegotiation that hurt throughput and earnings on every proxy connection without meaningfully reducing RAM usage. 256 KiB matches the fork's established optimized minimum. The other lowmem constraints (sequence buffer depth 16, TCP window 32 KiB) are unchanged.
