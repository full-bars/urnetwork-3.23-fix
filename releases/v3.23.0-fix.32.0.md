# v3.23.0-fix.32.0

> [!NOTE]
> **The hub subsystem is removed in this release.** Hub mode was deprecated in the 31.x series; v32.0 ships without it. Hub operators should migrate to Prometheus metrics (`urnet-tools metrics on`) and the monitoring bundle for fleet visibility. The generic `report` command and HTTP POST reporting are unaffected.

## What's Changed

### Removed

- **deprecate: remove hub subsystem** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/634>) — The entire hub fleet-dashboard subsystem is gone: the `hub/` package (24 files, ~9,700 lines — CA bootstrap, TLS pinning, hub token auth, SSE broadcaster, PAKE handlers, SQLite store), all `urnet-tools hub *` CLI commands, hub build/packaging/scan CI steps, the hub CA bootstrap and TLS fingerprint pinning from `bandwidth_reporter.go`, hub test scripts and shakedown sections, and the hub documentation. **Preserved:** the Prometheus `/metrics` endpoint and all metrics infrastructure, `urnet-tools metrics on|off`, the generic `report` command (HTTP POST to any configured `report_url` or `URNETWORK_REPORT_URL`), and the Grafana monitoring bundle.

### Bug Fixes

- **fix(transfer): order selective acks and wake the ack path on provable holes** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/643>) — Selective acks were written in map iteration order, so a partial batch could prove the neighbours of one real hole lost and trigger needless resends. Selective acks now leave in ascending sequence order. The ack compression wait also ends early when a hole becomes provable to the sender or when the head ack advances past selectively acked items, with each reason waking at most once per compression interval so the in-order ack rate is unchanged. With `AckCompressTimeout=0` (the default) acks remain per-packet and the in-order rate is unchanged. Port of upstream urnetwork/connect PR #213 fix 2 (measured on their rig: 8 flows 600 -> 709 Mb/s, head-blocked 20% -> 5%, duplicates ~0).

### CI Fixes

- **fix(ci): align docker shakedown checks with current release state** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/644>) — The Docker shakedown suite was failing against the current provider storage layout: the proxy-cap check (W5) now reads proxy state from `proxy.state` (with a `proxy_url.json` fallback) and parses the proxies dictionary; the eco and lowmem profile checks (W6) read `/dev/shm` ramlogs since those profiles redirect stdout to memory; and the compose down/up check (Y5) handles ramlog client_id capture with adaptive deadline polling and one retry on initial timeout.

### Maintenance

- **chore(security): sync CFAA blocklist from upstream** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/645>) — Refreshed the content filtering blocklist.

### Changed

- **fix: auto-select jwt build mode when an auth code is supplied** (<https://github.com/full-bars/urnetwork-3.23-fix/commit/8f2f700c>) — The Docker entrypoint defaulted to `BUILD=stable` and asked for `USER_AUTH` and `PASSWORD` even when the caller passed a JWT auth code as the positional argument (or set `URNETWORK_AUTH_CODE`). That case now selects jwt mode automatically; an explicit `BUILD=` still overrides.

## Deploy Notes

1. **Hub operators must migrate.** The `urnet-tools hub *` commands no longer exist. Use `urnet-tools metrics on` plus the Prometheus/Grafana monitoring bundle for fleet visibility; the generic `report` command still posts to any configured `report_url`.
2. **Lossy routes recover faster.** The selective-ack ordering fix removes needless resends and head-of-line ack blocking under packet loss.
3. **Docker JWT auth needs no explicit `BUILD`.** Passing the auth code positionally (or via `URNETWORK_AUTH_CODE`) is enough; an explicit `BUILD=jwt` still works.
