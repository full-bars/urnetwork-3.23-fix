# v3.23.0-fix.29.1 — 2026-08-14

> [!NOTE]
> Operators must redeploy provider nodes for the TCP change. The hub does not change in this release.

## 1. Summary

This release ports the RFC 7323 TCP stack work from upstream perfvar. It adds timestamps, MSS negotiation, and initial-window warmup to the provider's TCP path. This is the only provider code change in this release. The rest of the work builds out the release pipeline. It adds VirusTotal and ClamAV scanning of release binaries, fixes a hanging DoH test, and finishes the pre-release shakedown workflow that exercises a fresh install end to end before a tag ships, then bulletproofs the workflow's runner-to-droplet lifecycle.

## 2. TCP Stack Port

PR #380 ports RFC 7323 timestamps, MSS negotiation, and initial-window warmup from upstream perfvar. It replaces the old window-scale-only option parser with one unified parser that reads MSS, window scale, and timestamp options together.

Timestamps are now negotiated from the peer's SYN and emitted on every non-RST segment. This covers the SYN-ACK, data segments, pure ACKs, and the FIN-ACK. A monotonic clock and a reorder guard back the timestamp logic.

Segmentation is now peer-MSS-aware. DataPackets clamp their payload to the peer's advertised MSS, using RFC 879 and RFC 6691 data-only semantics, with a 536-byte floor.

A new InitialWindowSize setting scales with the memory budget. It is power-of-two and clamped between 4 KiB and 128 KiB. Per RFC 7323, the SYN advertises the literal unscaled window. The post-handshake ACK then jumps to the warmup window.

The fork keeps its existing 4 KiB to 4 MiB low-RAM window profile. Upstream moved to a 64 KiB to 16 MiB profile, but this fork does not follow that change.

ReadBufferByteCount now accounts for the timestamp option. This stops full IPv6 reads from splitting into a short runt tail segment.

The port went through multiple independent review passes. New tests cover the window-scale table across 9 cases, MSS and timestamp extraction, malformed-tail parsing, SynAck layouts, timestamp byte handling, PureAck TSopt handling, and DataPackets timestamp segmentation. All existing tests still pass.

## 3. Pre-Release Shakedown

PRs #384 through #390 build out an automated pre-release shakedown workflow. The workflow was previously called the gauntlet; it is renamed to shakedown in this range.

The shakedown runs on a disposable 1 CPU, 1 GB DigitalOcean droplet. It performs a full install, then tests the proxy path, the URL source path, and the docker path. Cleanup is guaranteed through a trap plus a job timeout.

Later fixes in the range add an apt-get update step before the docker install, skip URL checks when auth fails, and add a report review step. Two more fixes post the run verdict to a Discord webhook, add a preflight connectivity gate so a dead internet or API connection fails fast, require a public IPv4 address before SSH, and fix the auth-check window to read the full journal. One fix annotates the Wacatac.C!ml antivirus flag as a confirmed false positive in the scan report. Another folds in review fixes: exit-status-first assertions, a self-test phase, and a Q4/Q5 restructure. PR #390 adds hub coverage for both systemd and docker, and completes the gauntlet-to-shakedown rename.

PR #391 bulletproofs the shakedown's runner-to-droplet lifecycle. The first real run exposed a flaw. The test script finished in 76 minutes, but the SSH session stayed open because backgrounded child processes held the pipe open. The watchdog killed the session, the exit code was lost, and the run showed green.

PR #391 fixes this. The script now runs detached, through systemd-run --no-block, so the SSH session returns right away. The exit code is preserved through a sentinel file written by atomic rename. A deterministic gate then maps exit codes 0, 1, 75, and 124 to PASS, RELEASE_BLOCKED, ENV_BLOCKER, and HARNESS_CRASH. A crash before any FAIL line can no longer show as a false green.

A new sweeper workflow runs on its own 15-minute schedule. It destroys shakedown-ci droplets older than 3 hours and reaps stale SSH keys. This is the backstop for the one path where a droplet could still leak, a runner eviction or a force-kill. The droplet is tagged at create time. Cleanup retries delete-by-id and delete-by-tag, verifies the list is empty afterward, and the trap covers EXIT, INT, TERM, and HUP.

Polling is now bounded, the report streams on every poll, a heartbeat detects a stalled script, and a concurrency group queues runs instead of cancelling them.

The bulletproofing went through six rounds of independent design and verification review. Every finding from those rounds was applied, and the flow was verified end to end before this release shipped.

The shakedown covers a fresh install on the regular-person path, auth, the Go tool, the full proxy lifecycle, URL sources tested against real free proxies, the admission pipeline, docker, the hub under both systemd and docker, hot-restart identity, the update --tag path, self-update, a long observation phase with resource sampling, and a clean shutdown. Tier-1 failures exit non-zero and fail the job. Tag-triggered runs test the exact release being cut. A full run takes about 2 hours; a watchdog and a job timeout bound that.

## 4. Release Pipeline

PR #381 adds a VirusTotal scan of release binaries before they publish. The gate has two tiers. Zero to two detections pass; this is the known band for stripped Go binary false positives. Three to ten detections still ship but are flagged for review in the scan receipt. Eleven or more detections block the release. The scan writes a report receipt with a per-artifact PASS/REVIEW/FAIL table and VirusTotal permalinks. On a tag run, the scan fails the release if the VirusTotal API key secret is missing. A security gate must not silently disable itself.

PR #383 adds a ClamAV scan of release binaries as a second, quota-free opinion. It runs an EICAR self-test, then scans all 20 release binaries after the VirusTotal scan completes.

PR #382 fixes the DoH tests, TestDohQuery and TestDohCache, so they are hermetic. The old tests queried live public DoH servers for a hostname that does not resolve, so the retry loop hung. A local httptest server now serves canned Google-style JSON DoH responses, and the tests fail fast instead of retrying forever.

## 5. Deploy Notes

The provider binary changes in this release because of the TCP port. Operators must redeploy provider nodes to pick up the change.

The hub does not change in this release.

The CI pipeline changes, including VirusTotal, ClamAV, the shakedown workflow, and the sweeper, do not need any fleet action.
