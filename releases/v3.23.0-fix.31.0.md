# v3.23.0-fix.31.0 — Draft / Unreleased

> [!NOTE]
> v3.23.0-fix.31.0 is a milestone release delivering architectural decoupling and operational high availability across the URNetwork Connect provider runtime. The flagship focus of this release is **Provider Daemonization**: a dedicated control-socket IPC plane, an offline pending-configuration queue, and consolidated systemd override keys, together with **Zero-Downtime HotSwap** for in-place binary updates and a round of **urnet-tools multi-provider UX smoothing**. Rebuild and redeploy provider nodes, and update `urnet-tools` and `urnet-docker`, to adopt the new daemon architecture.

## 1. Overview & Highlights

- **Provider Control Plane & Daemonization (Flagship)**: Decoupled provider settings from brittle external file writes and process restarts into an in-process control state, with a local Unix domain socket (`~/.urnetwork/provider.sock`) as the live control plane and an offline fallback queue for seamless runtime reconfiguration.
- **Zero-Downtime HotSwap**: In-place binary handover between a running provider and a verified candidate, transferring the control socket and live listeners with a mandatory ACK-then-yield drain. Eliminates the standard 20–60s upgrade stall; the provider binary can be swapped with 0s downtime.
- **Control Socket IPC & Offline Pending Queue**: Replaces brittle systemd file edits and process restarts with a live control protocol (`urnet-tools set`). Settings changed while the provider is stopped or restarting are queued in `~/.urnetwork/pending_overrides.json` (flock-guarded across processes) and merged atomically on boot.
- **Systemd Key Convergence**: Migrates legacy `override.conf` keys (`URNETWORK_PROFILE`, `URNETWORK_RAMLOGS`, `GOMEMLIMIT`, `GOGC`) into the unified control-socket runtime state.
- **Public IP Autodetection & Dynamic Renaming**: Automatic detection of external IPv4 address via a cached background resolver with 60s TTL and concurrent-request deduplication; an operator can disable it with the `~/.urnetwork/disable_ip_autodetect` marker or `urnet-tools ip-detect off`. `urnet-tools rename` sets the dashboard display label without a restart.
- **urnet-tools Multi-Provider UX (One provider per OS user)**: `urnet-tools status`/`logs`/`summary` and `start`/`stop`/`restart` now resolve to the current OS user's provider by default and re-exec themselves under sudo for another user's provider; `providers` shows your providers and `providers --all` (as root) lists the whole box. `-y`/`--yes` aliases `--force`, `optimize` self-elevates and applies atomically, and manage-time refusals point at concrete next steps.
- **JWT Auto-Refresh Transfer Stats Telemetry**: Step 3/3 of JWT rotation now parses `paid_bytes_provided` and `unpaid_bytes_provided` from `GET /transfer/stats`, reporting account balances inline in human-readable units (`unpaid: X, paid: Y`).
- **Android IPv6 ICE Egress Guard**: Synthetic IPv6 host candidates are gated behind `egressIPv6Usable()` send probes to prevent dead routes from blackholing cellular/VPN WebRTC traffic.
- **Automated CFAA Blocklist Synchronizations**: Continuous synchronization of Computer Fraud and Abuse Act IP blocklists with upstream definitions.

## 2. Provider Control Plane & Control Socket

### Control Socket
The provider owns a single Unix domain socket at `~/.urnetwork/provider.sock` (owner-only 0600) through which `urnet-tools` sends live `set`/`clear`/`get` commands. There is no Windows named-pipe transport — the provider listens on a Unix domain socket on all platforms the provider runtime supports.

- **Single owner, single writer**: the provider process is the only writer of `~/.urnetwork/provider_state.json` (atomic temp-file + rename). The socket is how `urnet-tools` safely asks it to change a setting, instead of two processes editing a shared override file.
- **Cross-process safety**: both the Go CLI and the install script's shell helpers flock `pending_overrides.json.lock` (and the provider adopts it during merges), so a queued override written while the provider is mid-startup can never be dropped.
- **Atomic set/clear**: a socket `set`/`clear` runs its read → apply → persist → rollback as one locked unit, so concurrent connections cannot interleave and clobber each other or leave memory and disk disagreeing.

### Offline Pending Configuration Queue
When an operator issues a configuration command while the provider is offline, `urnet-tools` persists the instruction to `~/.urnetwork/pending_overrides.json`:
- **One-Shot Startup Consumption**: on boot the provider merges the queue atomically, applies runtime side effects (memory limits, GC percentage), and clears the file.
- **Zero Configuration Drift**: eliminates race conditions between configuration tooling and the service supervisor startup hook.

### Systemd `override.conf` Migration
Configuration keys previously requiring static systemd drop-ins are now managed directly through the control socket:
- **`profile` & `ramlogs`**: seeded into the early execution environment before logging initialization.
- **`gomemlimit` & `gogc`**: applied dynamically via Go runtime debug APIs (`debug.SetMemoryLimit`, `debug.SetGCPercent`) both on boot and during live operation.

## 3. Zero-Downtime HotSwap

HotSwap is fully implemented in this release (not a later milestone): the provider can hand off live service to a verified candidate binary without cycling the unit.

- **Candidate pre-flight**: the candidate verifies its tokens, DoH, and API reachability before taking over, then announces READY.
- **Listener & state handover**: the active control-socket listener and coordinator session are yielded to the promoted candidate only after it confirms a mandatory TAKEOVER ACK — there is never a window where neither process holds them.
- **Graceful drain**: the retiring process stops accepting new work, flushes retained events, and exits once the candidate is live.
- **SIGUSR2 trigger**: `urnet-tools hotswap` / a HotSwap-capable `urnet-tools update` signals the running provider (version-gated to avoid signaling a pre-HotSwap binary). Docker providers do an in-place PID-1 `syscall.Exec`; systemd providers use `Type=notify` handoff and `NOTIFY_SOCKET` isolation.
- **Automatic rollback**: `urnet-tools update` rolls the on-disk binary back if the candidate fails to take over, and never claims "live provider retained" after ownership has actually transferred.

## 4. Node Identity, Telemetry & Operator Tooling

### Public IP Autodetection & Dashboard Display Label (PR #534)
- **Automatic IPv4 Discovery**: resolves the provider's public egress IP at boot and on a 60s TTL, automatically appending `@ <RedactedIP>` to the dashboard identity string.
- **Concurrent Request Deduplication**: only one external fetch runs per TTL window; concurrent callers share the in-flight result or the cached value.
- **Operator Opt-Out**: creating `~/.urnetwork/disable_ip_autodetect` or running `urnet-tools ip-detect off` disables public IP querying (there is no `--disable-ip-autodetect` flag).
- **Dynamic Node Renaming**: `urnet-tools rename <name>` sets the dashboard display name without modifying the hostname or restarting the service.

### urnet-tools Multi-Provider UX (one provider per OS user)
The tool now treats the OS user as the primary implicit scope:

- **Implicit current-user scope**: an unprivileged `urnet-tools command` with no target resolves to the provider owned by the current OS user, silently. Other users' providers are not enumerated on every command.
- **`providers` / `providers --all`**: the one place multi-user inventory lives. `providers` lists your providers; `providers --all` (as root) lists every provider on the box.
- **Cross-user self-elevation**: targeting another user's provider (`status --user bob`, `start --unit <unit>`) re-executes the command under `sudo <full binary path>` — so the binary-on-a-per-user-path problem never surfaces as a "command not found" or a manual `sudo /long/path` hunt. `start`/`stop`/`restart` carry `-f`/`--yes` through so the elevated child doesn't re-prompt; a dry run never elevates.
- **`-y`/`--yes`**: aliases `--force` — `urnet-tools restart -y` skips the confirm prompt just like `-f`.
- **`optimize` self-elevates and is atomic**: `urnet-tools optimize` re-executes under sudo with its own resolved binary path, snapshots the current sysctl values, applies the live set, persists `/etc/sysctl.d/99-urnetwork.conf`, and rolls the live keys back on any failure — no more half-success ("settings are live but will not survive reboot") and no `sudo urnet-tools` "command not found".
- **Actionable manage-time refusals**: when more than one provider is in scope and no target is given, the refusal points at `--unit`, `default set --network <name>`, and `providers --all` instead of a manual sudo hunt.
- **Control-socket liveness in `status`**: the status output reports whether the provider's control socket is actually bound — a running PID can exist with no reachable socket (startup failure or a same-user collision).

### JWT Auto-Refresh Transfer Stats Telemetry
- **Inline Accounting Output**: during step 3/3 of JWT rotation, the verification response from `GET /transfer/stats` is parsed for `paid_bytes_provided` and `unpaid_bytes_provided`:
  ```text
  🔑 [jwt] refresh → step 3/3: verifying new token against https://api.bringyour.com/transfer/stats...
  🔑 [jwt] refresh → step 3/3 ok: verification passed (HTTP 200, unpaid: 500.0 MB, paid: 1.0 GB)
  ```
- **Robust Error Handling**: JSON parsing errors or schema variations fall back gracefully to status-code reporting without interrupting token renewal.

## 5. Security & Platform Hardening

### Android IPv6 ICE Egress Guard
- Dialing synthetic IPv6 interfaces on Android previously succeeded on connect-only UDP dials due to default cellular routes, but blackholed traffic once outbound packets traversed the VPN tunnel.
- ICE host candidates are now guarded by an explicit `egressIPv6Usable()` send probe, preventing Pion WebRTC from advertising unreachable IPv6 routes and stalling ICE negotiation.

### Automated CFAA Blocklist Synchronization (PR #540, #542)
- Synchronized Computer Fraud and Abuse Act IP blocklists with upstream definitions:
  - PR #540: Updated IPv4 definitions to 43,479 entries and IPv6 to 438 entries.
  - PR #542: Updated IPv4 definitions to 43,809 entries and IPv6 to 469 entries.
