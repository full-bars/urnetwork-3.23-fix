# v3.23.0-fix.31.0 — Draft / Unreleased

> [!NOTE]
> v3.23.0-fix.31.0 is a milestone release delivering architectural decoupling and operational high availability across the URNetwork Connect provider runtime. The flagship focus of this release is full **Provider Daemonization**, establishing an unprivileged background daemon supervisor, dedicated control socket IPC, and offline pending configuration queues. In parallel, architecture for **Zero-Downtime HotSwap** (in-place binary updates eliminating the typical 20–60s upgrade downtime to 0s) is in flight, with hot swap moving to a secondary cadence behind the daemonization milestone. Rebuild and redeploy provider nodes, and update `urnet-tools` and `urnet-docker`, to adopt the new daemon architecture.

## 1. Overview & Highlights

- **Provider Daemon Architecture (Flagship)**: Decoupled provider process execution from interactive user terminals and foreground wrappers into an independent background daemon. Includes local IPC via Unix domain socket (and Windows named pipes) and an offline fallback queue for seamless runtime reconfiguration.
- **Zero-Downtime HotSwap / In-Place Updates (In Flight)**: Eliminates node restart penalty during binary updates. An in-place handover protocol transfers active listeners and relay connections from the existing instance to the incoming candidate process, transitioning the standard 20–60s downtime to 0s downtime without severing active client sessions.
- **Control Socket IPC & Offline Pending Queue**: Replaces brittle systemd file edits and process restarts with a live control protocol (`urnet-tools set`). Settings changed while the daemon is stopped or restarting are queued in `~/.urnetwork/pending_overrides.json` and merged one-shot on boot.
- **Systemd Key Convergence**: Migrates legacy `override.conf` keys (`URNETWORK_PROFILE`, `URNETWORK_RAMLOGS`, `GOMEMLIMIT`, `GOGC`) into the unified control-socket runtime state.
- **Public IP Autodetection & Dynamic Renaming**: Automatic detection of external IPv4 address via cached background resolver with 60s TTL, concurrent request deduplication, and `--disable-ip-autodetect` opt-out; introduced `urnet-tools rename` to modify dashboard labels dynamically.
- **JWT Auto-Refresh Transfer Stats Telemetry**: Step 3/3 of JWT rotation now parses `paid_bytes_provided` and `unpaid_bytes_provided` from `GET /transfer/stats`, reporting account balances inline in human-readable units (`unpaid: X, paid: Y`).
- **Android IPv6 ICE Egress Guard**: Synthetic IPv6 host candidates are gated behind `egressIPv6Usable()` send probes to prevent dead routes from blackholing cellular/VPN WebRTC traffic.
- **Automated CFAA Blocklist Synchronizations**: Continuous synchronization of Computer Fraud and Abuse Act IP blocklists with upstream definitions.

## 2. Provider Daemon Architecture & Control Socket

### Background Daemon Execution
The provider previously operated primarily as a foreground process tied to the launching session or container entrypoint:
- **Process Decoupling**: The provider now runs as a persistent background daemon, maintaining its own lifecycle independent of interactive shells or CLI callers.
- **Unified Control Protocol**: Exposes a local Unix domain socket (`~/.urnetwork/provider.sock`) on Linux/macOS and named pipes on Windows. Operators manage settings through `urnet-tools` without signaling, killing, or restarting the daemon.

### Offline Pending Configuration Queue
When an operator issues a configuration command while the provider daemon is offline, `urnet-tools` automatically persists the instruction to `~/.urnetwork/pending_overrides.json`:
- **One-Shot Startup Consumption**: Upon startup, the daemon inspects the pending queue, merges the queued overrides atomically, applies runtime side effects (such as memory limits and GC percentages), and clears the file.
- **Zero Configuration Drift**: Eliminates race conditions between configuration tooling and service supervisor startup hooks.

### Systemd `override.conf` Migration
Configuration keys previously requiring static systemd drop-ins are now managed directly through the control socket:
- **`profile` & `ramlogs`**: Seeded into the early execution environment prior to logging initialization.
- **`gomemlimit` & `gogc`**: Applied dynamically via Go runtime debug APIs (`debug.SetMemoryLimit`, `debug.SetGCPercent`) both on boot and during live operation.

## 3. High-Availability Upgrades: Zero-Downtime HotSwap

> [!TIP]
> **HotSwap Priority Note**: While the core HotSwap handover protocol is established, daemonizing the provider was prioritized to establish stable IPC and process boundaries first. HotSwap is advancing on the secondary track to deliver zero-downtime updates on top of the daemon foundation.

### Eliminating the 20–60s Upgrade Stall
Standard binary upgrades require stopping the systemd service or Docker container, downloading or swapping the executable, and restarting from scratch. This introduces a 20–60 second downtime window, aborts live client connections, and forfeits active relay traffic earnings:
- **In-Place Binary Replacement**: The new provider candidate launches alongside the running provider.
- **Listener & State Handover**: The active listener socket and session tracking are transferred directly to the candidate process without closing file descriptors.
- **Graceful Drain Protocol**: The retiring process ceases accepting new proxy connections, drains existing in-flight flows cleanly, and yields execution once the candidate signals ready.
- **Zero-Downtime Result**: Node upgrades occur with 0s downtime, preserving client relay sessions and node reputation scores.

## 4. Node Identity, Telemetry & Operator Tooling

### Public IP Autodetection & Dashboard Display Label (PR #534)
- **Automatic IPv4 Discovery**: Resolves the provider's public egress IP at boot and periodic renewal, automatically appending `@ <RedactedIP>` to the dashboard identity string.
- **Concurrent Request Deduplication**: Prevents concurrent proxy initialization bursts from issuing redundant external IP queries; only one fetch occurs per 60s TTL window.
- **Operator Opt-Out**: Creating `~/.urnetwork/disable_ip_autodetect` or running `urnet-tools ip-detect off` disables public IP querying entirely.
- **Dynamic Node Renaming**: Added `urnet-tools rename <name>` to adjust dashboard display names without modifying hostnames or restarting services.

### JWT Auto-Refresh Transfer Stats Telemetry
- **Inline Accounting Output**: During step 3/3 of JWT rotation, the verification response from `GET /transfer/stats` is parsed for `paid_bytes_provided` and `unpaid_bytes_provided`:
  ```text
  🔑 [jwt] refresh → step 3/3: verifying new token against https://api.bringyour.com/transfer/stats...
  🔑 [jwt] refresh → step 3/3 ok: verification passed (HTTP 200, unpaid: 500.0 MB, paid: 1.0 GB)
  ```
- **Robust Error Handling**: JSON parsing errors or schema variations fall back gracefully to status code reporting without interrupting token renewal.

## 5. Security & Platform Hardening

### Android IPv6 ICE Egress Guard
- Dialing synthetic IPv6 interfaces on Android previously succeeded in connect-only UDP dials due to default cellular routes, but blackholed traffic once outbound packets traversed the VPN tunnel.
- ICE host candidates are now guarded by an explicit `egressIPv6Usable()` send probe, preventing Pion WebRTC from advertising unreachable IPv6 routes and stalling ICE negotiation.

### Automated CFAA Blocklist Synchronization (PR #540, #542)
- Synchronized Computer Fraud and Abuse Act IP blocklists with upstream definitions:
  - PR #540: Updated IPv4 definitions to 43,479 entries and IPv6 to 438 entries.
  - PR #542: Updated IPv4 definitions to 43,809 entries and IPv6 to 469 entries.
