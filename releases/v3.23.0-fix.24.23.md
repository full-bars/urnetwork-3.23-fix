## Highlights

### 🐛 Fix: `urnet-tools` Broken on Every Subcommand (PR #161)

v3.23.0-fix.24.23 (first attempt) had a critical bug: the `$0` path check ran **before** argument parsing, so `urnet-tools update`, `urnet-tools fast-auth on`, `urnet-tools --help` — every command — immediately showed help and exited.

**Root cause**: The path check was placed at line 112, before the option parsing loop consumed `$1`. The installed binary path matched, so it always short-circuited to help.

**Fix**: Moved the check to after `operation=$1` is set. Also removed the tarball `cp` overwrite (the original regression cause from v24.18) and replaced the `URNETWORK_TOOLS_MODE` guard with the same `$0` path check.
