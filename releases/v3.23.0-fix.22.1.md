## Installing / Updating

**Binary (bare metal / VM) — Fresh install:**
```sh
curl -fSsL https://raw.githubusercontent.com/full-bars/urnetwork-3.23-fix/refs/heads/main/scripts/Provider_Install_Linux.sh | sh -s -- install
```

**Updating an existing install:**
```sh
urnet-tools update
```

**Docker:**
```sh
docker pull ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.22.1
```

```sh
docker run -d \
  --name=urfix \
  --restart=unless-stopped \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  -e URNETWORK_AUTH_CODE=YOUR_AUTH_CODE \
  -e HOST_HOSTNAME=$(hostname) \
  -e PROXY_URL='https://example.com/your-proxy-list.txt' \
  -v urfix_config:/root/.urnetwork \
  ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.22.1
```

## Highlights

### 🔁 Live-Reloadable Hub Reporting & Outage Alerts
`URNETWORK_REPORT_URL` and `URNETWORK_ALERT_WEBHOOK` were only read once at process start, so turning hub reporting or outage alerting on, off, or pointed at a different target meant restarting the provider — losing warmup on every proxy in the process for a config change that has nothing to do with proxy health.
- **`~/.urnetwork/report_url`**: write a hub URL here to start/stop/repoint bandwidth reporting; the reporter re-resolves it every tick (default 60s). Falls back to `URNETWORK_REPORT_URL` when the file doesn't exist, so nothing changes for existing deployments.
- **`~/.urnetwork/alert_webhook`**: same pattern for the outage watcher's Discord/Slack/ntfy webhook, re-resolved every 30s poll. Falls back to `URNETWORK_ALERT_WEBHOOK`.
- Found while bringing a production node's hub reporting up to parity with the rest of the fleet — it had no way to turn reporting on without a restart.
