## Installing / Updating

**Binary (bare metal / VM) — Fresh install:**
```sh
curl -fSsL https://raw.githubusercontent.com/full-bars/urnetwork-3.23-fix/refs/heads/main/scripts/Provider_Install_Linux.sh | sh -s -- install
```

**Updating an existing install:**
```sh
urnet-tools update
```

**Docker:**
```sh
docker pull ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.22
```

```sh
docker run -d \
  --name=urfix \
  --restart=unless-stopped \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  -e URNETWORK_AUTH_CODE=YOUR_AUTH_CODE \
  -e HOST_HOSTNAME=$(hostname) \
  -e PROXY_URL='https://example.com/your-proxy-list.txt' \
  -v urfix_config:/root/.urnetwork \
  ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.22
```

`PROXY_URL` is new in this release (see below) — drop it if you're sticking with a static `proxy.txt`. See [Proxy URL Sources](docs/Proxy-URL-Sources.md) for `PROXY_URL_REFRESH`, `PROXY_URL_MAX`, and combining it with a mounted `proxy.txt`.

## Highlights

### 🌐 Proxy URL Sources
Point the provider at a live proxy list URL instead of, or alongside, a static `proxy.txt`.
- **`--proxy_url` / `PROXY_URL`**: comma-separated list of URLs, fetched on an interval (default 15m).
- **Live merge**: New entries flow into the existing hot-reload pipeline without disturbing already-warmed-up proxies.
- **Scoped auto-cleanup**: `--proxy_dead_cleanup_scope=url|all|none` lets a noisy public list self-prune dead entries without touching hand-curated ones.
- **Auto-retry**: A URL-sourced proxy that exhausts its auth retries now automatically retries again 15 minutes later, instead of waiting for the hourly pulse that only file/manually-added proxies get.

See [Proxy URL Sources](docs/Proxy-URL-Sources.md) for full configuration.

> [!TIP]
> **Multiple URLs in Docker:** there's no `PROXY_URL_2`/`PROXY_URL_3` — put every source in one comma-separated `PROXY_URL`. Repeating `-e PROXY_URL=...` just overwrites itself (Docker env vars aren't additive). The repeatable `--proxy_url=<url> --proxy_url=<url>` form only works on the binary/CLI side.

### 🚦 Global Adaptive Auth Rate Limiter & 429-Aware Backoff
Built and live-tested against a 1,600+ proxy free list hammering a fragile auth API.
- **Shared rate limiter**: Every proxy's auth attempt — first try and retry alike — now waits on one process-wide token bucket before calling the API, instead of relying on uncoordinated per-proxy backoff to bound aggregate request rate.
- **Self-tuning (AIMD)**: Starts at 10 req/s (burst 15), halves on any 429 anywhere in the process (floor 1 req/s), climbs back by 1 req/s after 20 consecutive clean attempts (ceiling 10 req/s). Logs `[proxy][authrate]` adjustments for visibility.
- **Per-attempt backoff now scales with the 429 itself**: a rate-limited retry waits `attempt × 5s + jitter` (capped at 60s) instead of the flat jitter used for ordinary timeouts.
- **HTML error bodies collapsed**: A 429 from an upstream proxy returning an HTML error page used to dump the whole page into the log; now collapsed to `<html error page, N bytes>`.
- **Timeouts now trigger backoff too**: the limiter originally only backed off on a literal `429`/`Too Many Requests` error string. Under real load the API doesn't always answer with an explicit 429 — it can just stop responding in time — and that fell through to the "clean success" path, creeping the rate *up* during an outage instead of away from it. Timeouts and connection failures now drive the same backoff as a 429.

### 🔁 Proactive Weekly JWT Refresh
JWT tokens now refresh automatically every 7 days, regardless of expiry.
- **48-hour fallback**: If the periodic refresh fails, an expiry-based fallback still catches it with a 48-hour recovery window.
- **Fleet-friendly**: 0–9 minute startup jitter desynchronizes refresh attempts across a fleet.
- **Works everywhere**: All auth modes (`BUILD=jwt`, `stable`, `nightly`) via JWT-to-JWT renewal. Last refresh timestamp persisted to `~/.urnetwork/jwt_last_refresh` so it survives restarts.

### 🛡️ Security: QUIC Memory Exhaustion Fix
Bumped `quic-go` to `v0.59.1`, resolving a vulnerability where an unauthenticated remote attacker could cause excessive memory allocation during the QUIC handshake. Operators using QUIC-based transports (H3) should update promptly.

### 📊 Expanded RAMLOGS, Docker CLI Parity & Hot-Reload Visibility
- **5MB RAMLOGS**: Capacity increased from 1MB to 5MB. `urnet-tools logs all` streams the full buffer; `urnet-tools logs dump` saves it to `~/urlogs.txt`.
- **Docker CLI parity**: `urnet-tools` is now available inside the container — same commands as bare-metal (e.g. `docker exec -it <name> urnet-tools proxy health`).
- **Hot-reload added-proxy visibility**: A reload that adds proxies now prints the same `Using N proxy servers:` listing used at startup, not just removals — so a `proxy refresh` or `--proxy_url` pickup is easy to confirm.
- **Production-ready Docker example**: README now documents the recommended `PROFILE=auto` + `URNETWORK_RAMLOGS=1` + persistent-volume deployment pattern.

### 🔄 Reliability Fixes
- **`proxy refresh` false failure**: Fixed `FATAL [exit 51]: provider does not appear to be running` on first startup with an empty proxy list — the provider now unconditionally writes `proxy.state` at startup, and the heartbeat self-heals a zero startup timestamp if it's ever read that way.
- **Installer/update broke under `dash`**: `Provider_Install_Linux.sh` passed raw GitHub API JSON to `jq`/`python3` via `echo`, which interprets backslashes natively on Debian/Ubuntu's default `/bin/sh` and silently corrupted escape sequences. Switched to `printf "%s"`, added a silent-failure fallback to the script's scraping path, and made the test suite POSIX-clean.
- **Sub-hour durations logged as `0h Nm`**: Now prints `15m` instead of `0h 15m`.
