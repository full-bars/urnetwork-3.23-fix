### **v3.23.0-fix.26.4 — Outage Resource Safety, Download Hardening**

This release closes a real production incident: providers running `turbo-v8` on RAM-constrained boxes could exhaust memory and start swapping during a sustained backend outage, with nothing in place to stop it. It also hardens the provider update/download path against a symlink-based TOCTOU vulnerability and tightens the recently-added mirror download logic.

### **Highlights**

> [!IMPORTANT]
> **Outage memory-exhaustion fix.** During a live backend outage, a `turbo-v8` provider with thousands of degraded proxies could climb to several GiB of RSS and start swapping — turbo profiles never set a `GOMEMLIMIT`, so nothing capped growth. A new degraded-proxy reaper now reclaims resources from the worst-contributing degraded proxies while the outage persists, without ever touching the best performers or the native/direct connection.

> [!NOTE]
> **Provider downloads are now atomic and TOCTOU-safe.** The update path no longer downloads to a predictable temp path — a local symlink at that path could previously redirect the extraction to overwrite an arbitrary file.

### **New features**

• **Degraded-proxy reaper**: A background reaper runs every 3 minutes during sustained outages, ranks degraded proxies by lifetime contribution (traffic moved + contracts won), and cancels the worst-contributing half — while always keeping at least half alive so the fleet can detect recovery immediately. `direct`/native mode is permanently exempt from reaping.
• **GOMEMLIMIT for turbo profiles**: `turbo-v4`/`turbo-v8` now set a memory ceiling (80% of available RAM) when the operator hasn't set `--max-memory` or `GOMEMLIMIT` explicitly, matching the safety net `eco` mode already had.
• **logThrottle consolidation** (#296): Six hand-rolled atomic rate-limiters in `transfer.go` consolidated into three `logThrottle` instances, removing ~50 lines of duplicated boilerplate.
• **Explicit GOGC for tier3** (#296): `applyTier3` now calls `debug.SetGCPercent(100)` to match the convention of the other three tiers (behavior unchanged — 100 is Go's default).

### **Fixes and hardening**

• **Outage memory safety**: Universal `GOMEMLIMIT` for turbo profiles, plus the degraded-proxy reaper described above — the core fix for the ATL2 outage incident.
• **TOCTOU tmpfile vulnerability**: Provider update downloads now use `mktemp`-generated unpredictable paths instead of a hardcoded `/tmp/urnetwork-update.tar.gz`, closing a symlink-race (CWE-377) that could let a local user redirect the extraction to overwrite an arbitrary file.
• **Atomic provider binary installation**: The update path now stages the new binary and only atomically replaces the live one on full success, with cleanup on any failure path.
• **Download reliability (dl.fullbars.xyz)**: Provider updates now route through `dl.fullbars.xyz` first with automatic GitHub fallback. Two follow-up fixes: `curl` now fails on HTTP error responses, and the Windows primary/mirror URL selection logic was corrected.
• **Restart flags**: Added `-y`/`-f` flags to skip the interactive confirmation on restart.
• **Dashboard contract feed** (#294): Fixed a copy-paste bug where the "Recent Contracts" dashboard feed matched `"[contract] acquired"` twice instead of also matching `"[contract] denied"`. Removed dead `activeProxies` capture left over from an unfinished feature.
• **BusyBox httpd docroot**: Restricted to `/app/www` via symlink across all Docker startup scripts, closing unauthenticated access to the full `/app/` directory on port 8080.
• **JWT NetworkId claim key** (#295): `ParseByJwtUnverified` previously read `claims["network_name"]` for both `NetworkName` and `NetworkId` (copy-paste bug). `NetworkId` now correctly reads `claims["network_id"]`.
• **authBytes message-pool leak** (#295): `runH3` was missing the `defer MessagePoolReturn(authBytes)` that `runH1` has, leaking one pool buffer per H3 auth handshake.
• **Division-by-zero guard** (#296): `contractByteCount()` guards against `ContractTransferByteSeqScale=0`, returning `max(StandardContractTransferByteCount, minByteCount)` instead of panicking.
• **SequencePeerAudit error logging** (#296): `Complete()` no longer silently swallows `SendControl` errors — the empty `func(...){}` callback was replaced with an `Errorf` that logs the error.
• **.gitignore hardening** (#296): Added `hub/hub_bin`, `hub.db`, `prs.json` to prevent accidental commits.
• **CI flake** (#290): Fixed a test that still used a hardcoded 45s deadline PR #286 had bumped elsewhere.

### **Upgrade notes**

• **New & existing installs**: No manual action required.
• If you're running `turbo-v4`/`turbo-v8` on a RAM-constrained box, this release adds real protection against the failure mode above — no configuration change needed to benefit from it.

### **Verification**

Root-caused live on a production node mid-outage (confirmed via `urnet-tools self-heal status`, health logs, and direct process inspection) before the fix was designed. All reaper logic covered by unit tests (ranking, floor-rounding, the direct-mode exemption, and the stale-decision recheck race) rather than manual reproduction, since the underlying outage can't be safely re-triggered on a production box for testing.
