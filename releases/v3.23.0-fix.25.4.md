# 🔐 v3.23.0-fix.25.4 — Status Server Resilience, JWT Refresh Rewrite + Hub Best Proxies

> **TL;DR** Status server crashes no longer bring down the provider. JWT refresh rewritten to mint network tokens instead of orphaning clients. Exit logging added so you can see why a provider shut down. Heartbeat metrics corrected. Hub gets a "Best Proxies" all-time leaderboard plus three dashboard bug fixes (reset zoom, request-sequencing race, fleet-wide leaderboard performance). No breaking changes — drop-in upgrade.

This release addresses two production issues on the provider side — mystery provider crashes caused by the status server's error handling, and the JWT self-refresh feature that was silently minting new client identities on every 7-day cycle instead of renewing the existing network token — plus a round of hub dashboard fixes and a new fleet-wide proxy leaderboard.

---

## 🛡️ Status Server Self-Healing

> **🐛 The bug:** The status server (used by `urnet-tools status`) had `defer cancel()` in its goroutine. ANY error from `ListenAndServe()` — port conflicts, bind failures, transient network errors — cancelled the main provider context, triggering a clean shutdown cascade → `os.Exit(0)`. No error was logged at the exit path, so the crash appeared unexplained.

**🔧 The fix:**
- Status server now **retries with 30s backoff** instead of crashing the provider
- Only `http.ErrServerClosed` (graceful shutdown) stops the retry loop
- Exit-reason logging added at 4 key points so you can see exactly why a provider shut down

| Before | After |
|---|---|
| Status server error → provider dies silently | Status server error → log warning + retry in 30s |
| Exit with no trace in journal | `[provider] shutting down: main context cancelled` + `[provider] exiting` |
| Signal during auth → silent exit | `[auth] exiting: signal received during login` |

**Impact:** Providers on LA1 and similar servers will no longer crash due to transient port issues. Any future shutdown now logs exactly what triggered it.

## 🔑 JWT Refresh Rewrite

> **🐛 The bug:** The JWT self-refresh feature (`runJWTRefresher`) was calling `/network/auth-client` — a client-provisioning endpoint, not a token-renewal endpoint — with no `ClientId`. The server unconditionally minted a brand-new client_id on every call. On success, the refresh overwrote the disk network JWT with a client JWT bound to the new throwaway client. Every 7-day cycle orphaned one more client+device pair server-side. The original network-token species was gone from disk permanently after the first refresh.

**🔧 The fix:** Rewritten to use the same flow `provider auth` uses at initial login — `/auth/code-create` → `/auth/code-login` — which returns a fresh **network JWT** of the same species originally written to disk.

| Before | After |
|---|---|
| Calls `/network/auth-client` (client-provisioning) | Calls `/auth/code-create` + `/auth/code-login` (token renewal) |
| Mints new client_id every 7 days | Returns network JWT (no client_id) |
| On-disk token changes species after first refresh | On-disk token stays network JWT |
| ~52 orphan client+device rows per node per year | Zero orphaned clients |

**Impact:** JWT refresh now works as originally intended — a silent, zero-side-effect keepalive. No more silent client churn. The hourly pulse also now includes a 30-second timeout on the verification HTTP client, preventing the refresher from hanging forever on a blackholing API.

## 📊 Heartbeat Metrics Corrections

PR #228 corrects three metrics bugs from PR #226:

1. **Contract utilization scaling** — `contractUtilSum` was being double-scaled to percent (`util*100` stored when `util` was already a percentage). `avg_util` now prints correctly.
2. **Checkpointed contracts excluded** — contract checkpoints (which sample utilization without closing contracts) were counted in both the sum AND the denominator. Now excluded from `contractUtilSum`.
3. **`prevClients` gating** — `prevClients` was only updated inside the throttled log-gate, but the transition check ran unconditionally every tick. The "started" traffic marker could re-fire every tick instead of once per transition.

## 🔧 Upstream Defensive Guards

PR #231 ports defensive improvements from upstream commit `40ccaed7` to `MessagePoolReadAllWithTag`:

- Inner loop: cleaner termination with `for i < len(b)`
- Both loops: `if n > 0` guards prevent counting/appending zero-length reads
- Both loops: `if n == 0 { return }` guards prevent infinite loop on misbehaving readers
- Outer loop: explicit `io.EOF` handling with documented non-EOF error contract

These are belt-and-suspenders guards — the fork already handled the core bug correctly.

## 🏆 Hub: Best Proxies (Hall of Fame)

A new all-time proxy leaderboard, independent of the existing windowed (`7d`/`30d`/etc.) leaderboard. Answers "which proxies have been reliably good, ever" without picking a time window first.

- **Ranking**: composite score `win% × ln(1 + traffic)` — reliability is the dominant factor, traffic breaks ties without letting the single biggest byte-mover win on volume alone
- **Minimum sample size**: proxies with fewer than 20 total contracts (`acquired + denied`) are excluded, so a lucky 1-for-1 proxy can't crowd out proxies with a real track record
- **Full history retained**: reads `proxy_fleet_daily`, which is never pruned, so proxies that have since gone dead still show up (marked "dead Nd ago") — useful for spotting past standouts worth re-adding to the pool
- **"Hide dead" toggle** in the UI to filter down to currently-active proxies only
- New endpoint: `GET /api/proxies/best?limit=200&hide_dead=false`

## 🐛 Hub Dashboard Fixes

Three bugs fixed in the existing dashboard, plus two caught in review of the Best Proxies addition before it shipped:

1. **Reset zoom button was a no-op** — `makeChart()` wasn't storing the chart instance on its DOM element, so the reset-zoom button had nothing to find and destroy. Fixed.
2. **Proxy table race condition** — switching the node filter dropdown while a slower "all nodes" request was still in flight could let the stale response overwrite the newer, faster filtered one. Fixed with a monotonic request-sequence guard (`proxiesRequestSeq`), also applied to the new Best Proxies table (`bestRequestSeq`).
3. **Fleet-wide leaderboard performance** — the "all nodes" view was scanning the full per-node hourly table (millions of rows). Added a `proxy_fleet_hourly` pre-aggregated rollup so that query now reads a much smaller table. Backfilled asynchronously on first startup; pruned on the same 90-day window as the source table.
4. **Best Proxies nav item was rendered twice** — a duplicated `<div>` in the dashboard template put two identical "Best Proxies" buttons in the sidebar. Removed.
5. **Best Proxies win% was on the wrong scale** — the API returned `win_pct` as a raw 0–1 fraction instead of the 0–100 scale used everywhere else in the hub, so it displayed as e.g. "0.9%" instead of "85.0%" and the color thresholds never triggered. Fixed; regression test added.
