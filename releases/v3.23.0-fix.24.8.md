## What's New

### Hub keeps history now (SQLite-backed storage)

The fleet hub stored only the latest snapshot from each node in a flat `hub.json` that was rewritten in full on every report. There was no history, so the dashboard could only ever show "right now."

The hub now persists to a SQLite database (`hub.db`, WAL mode) with two tiers of retention:

- **`proxy_snapshots`** keeps each node's full proxy list per report as a gzip-compressed blob, retained 7 days. Compression shrinks a large proxy list by roughly an order of magnitude.
- **`node_hourly`** keeps a small per-node, per-hour rollup (cumulative RX/TX, billable, peak clients, sample count), retained 365 days for long-range history.

The dashboard still reads from an in-memory cache, so it stays just as fast, and that cache is rebuilt from the latest stored snapshots on startup, so a hub restart no longer blanks the dashboard.

> [!NOTE]
> Migration is automatic and one-time: an existing `hub.json` is imported into `hub.db` on first boot, then retired to `hub.json.imported`. Nothing to do by hand. WAL mode adds `hub.db-wal` and `hub.db-shm` sidecar files next to the database, which is normal.

New `/api/history` endpoint exposes the hourly rollups:

```sh
curl -s 'http://localhost:8080/api/history?node=la6&hours=168' | jq .
```

### Consistent timestamps on status logs

The fork's own status lines (`[health]`, `[traffic]`, `[report]`, `[proxy]`, and friends) were printed without a timestamp, so they sat un-stamped next to the timestamped library lines in the same stream. They now carry a matching `MMDD HH:MM:SS` prefix:

```
0623 08:51:15 [health] uptime=5h10m0s profile=turbo-v8 heap=437MiB
0623 08:51:15 [report] sending 4001 proxies to http://.../api/report
```

## Under the Hood

- **Report interval default is now 5 minutes** (was 60 seconds) to keep the hub's historical write volume modest across a large fleet. `URNETWORK_REPORT_INTERVAL` still overrides it (minimum 10s); lower it where a more live dashboard matters. Hub freshness colors were scaled to match.
- **Retention runs automatically**: proxy snapshots are pruned after 7 days, hourly rollups after 365 days.
- **Pure-Go SQLite** (`modernc.org/sqlite`, no CGO), so cross-compiled binaries and the Alpine Docker image are unaffected. The resulting `hub.db` is a standard SQLite file readable by any SQLite tool.
- **Wire-compatible**: the provider's report payload is unchanged, so providers and hub can be upgraded independently during a rolling deploy.
