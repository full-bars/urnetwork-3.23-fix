# v3.23.0-fix.30.4

This release restores several urnet-tools commands, adds a new proxy trim command, hardens provider memory and garbage collection, improves observability, and fixes a range of urnet-tools issues. It also ships installer, Docker, security, CI, and documentation updates.

## 1. Restored urnet-tools commands

Several commands existed in the legacy shell tool but were missing from the Go rewrite. They are now back.

Pull request 439 restores the auth, choose-network, fast-auth, and set commands.

Pull request 440 restores session save and session load. These commands export and import an encrypted provider identity bundle. They back up the live state first.

Pull request 441 restores the hub command family. This includes init, link, unlink, test, onboard-cmd, show-password, open-port, and update.

Pull request 438 restores the self-heal on/off/status marker controls and Linux live systemctl status view.

## 2. New proxy trim command

Pull request 442 adds the command `urnet-tools proxy trim <N>`. This command runs on the provider side. It holds the number of running proxies at a cap. It sheds the worst-graded proxies first, using the A to F website-reachability grade. The cap stays in effect until you raise it or clear it. Use this command on an overloaded box.

## 3. Provider memory, garbage collection, and observability

Pull request 427 guarantees a finite memory limit on every provider path.

Pull request 428 consolidates the adaptive garbage collector into one controller.

Pull request 423 adds opt-in, loopback-only profiling hooks for performance diagnosis.

Pull request 425 adds consolidated loopback-only observability. This includes pool metrics and error tracking.

## 4. urnet-tools hardening

Pull request 433 accepts `--flag=value` targeting.

Pull request 434 stops reinstall from calling itself repeatedly. It also fixes correctness issues in proxy remove and dry-run mode.

Pull request 435 discovers the provider_beta binary on Windows and macOS.

Pull request 436 adds a persisted default provider target. It supports default set, show, and clear.

Pull request 409 adds a styled status panel on Windows and macOS.

Pull request 437 restores the clean, emoji-decorated sectioned help menu.

Pull request 446 resolves same-user privilege rejection in journalctl, systemctl, and optimize, decoupling host kernel tuning from provider discovery.

## 5. urnet-docker CLI expansion, Installer, Docker, security, and CI

Pull request 445 expands `urnet-docker` with first-class container lifecycle, auth, config, session, hub, and proxy commands matching `urnet-tools`.

Pull request 408 improves the Windows installer.

Pull request 424 optimizes the Docker image build.

Pull request 412 syncs the CFAA IP security blocklist.

Pull request 432 serves the urnet-docker install script at dl.fullbars.xyz/urnet-docker.sh.

Pull request 430 adds a per-operating-system guide for adding proxies.

Pull request 443 is a test-only fix. It removes a pre-existing data race that the race detector surfaced.

The CI and review workflow changes are pull requests 410, 411, 413, 414, 415, 416, 417, 419, 420, and 431.

The documentation and changelog changes are pull requests 418 and 426.

## Deployment notes

NOTE: Hub binaries for all platforms ship with this release tag. There is no separate hub release channel.

NOTE: Providers must update to pick up the new capability. The fleet is on v3.23.0-fix.30.3 before this release.

must: The provider, urnet-tools, and hub ship as release assets named `urnet-tools-<os>-<arch>` and `urnetwork-hub-<os>-<arch>`.
