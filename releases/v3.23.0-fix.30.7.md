# v3.23.0-fix.30.7 — 2026-08-24

> [!NOTE]
> This release is about trust. The provider can now tell a healthy paid proxy from a dead one. Rebuild
> and redeploy provider nodes to start grading paid and file-list proxies. Update the Go tools for the
> help and restart-scope fixes that ship here.

## 1. The story of this release

A provider's paid and file-list proxies are its paid work. Before this release the provider never gave
them a quality grade. It could not tell a proxy that relays millions of bytes from one that stopped
answering an hour ago. Trimming made its best guess. The proxy summary could not report which paid
proxies were actually healthy.

This release closes that gap. Every tracked paid and file-list proxy is now probed and graded on its
real reachability, measured the same way the provider trusts any proxy. The grade is built from
positive evidence only. A proxy is never ruled unhealthy on silence. From these grades, trimming and
the summary see true health, and the operator finally sees which paid proxies earn their place.

The grading is built to be cheap. Starting small and widening only in the uncertain middle means a
clearly-working or clearly-dead proxy settles almost instantly. A per-tick budget stops any single
sweep from probing hundreds of proxies. And when a sweep genuinely cannot decide, it says so. It marks
the proxy pending instead of inventing a grade.

## 2. Paid and file proxies get real grades

- Every tracked paid and file-list proxy is table-probed and assigned an A-F reachability grade.
- Before this release those proxies were never graded. Trimming and the proxy summary had no health
  signal for them.
- Each graded proxy logs a line: `[proxy][grade] paid <addr> graded <tier>`.
- A sweep summary line reports how many proxies were graded and how many are pending.
- Grades feed proxy trimming and the proxy summary, so shedding and reporting reflect real health.
- The grading is positive-evidence-only. A proxy is only ever demoted on proof of failure, never on
  absence of a probe.

## 3. Adaptive sampling spends bandwidth only where it matters

A probe does not hammer every destination on every pass. It starts small, at `min_sample_width`
(default 6 for the paid grader), and grows toward `max_sample_width` only while a proxy's score stays
borderline, within `pass_bar` plus or minus `border_line_band`.

- A clearly-working or clearly-dead proxy settles at the small width and spends almost no bandwidth.
- A proxy stuck in the uncertain middle gets a wider sample and a more confident verdict.
- The result: probe bandwidth is spent in proportion to uncertainty, not dumped uniformly on the whole
  fleet.

## 4. Honest pending status, no fabricated grades

Sometimes a probe reaches a proxy but cannot decide. This happens when the box's own resolver can
answer too few of the sampled hosts to form a confident verdict. The sweep does not guess.

- Such a proxy is marked pending instead of being assigned a tier.
- A pending proxy is not graded and carries no score.
- The operator sees "could not evaluate from this box" rather than a number that was never earned.

## 5. A per-tick budget keeps each sweep bounded

One 5-minute grading sweep probes at most `max_paid_probes_per_tick` proxies, default 200.

- When more proxies are stale than fit in the budget, the oldest-stale proxies are probed first.
- A concurrent reload that changes an address or its credentials mid-sweep drops the stale result
  rather than applying it.
- A cancelled sweep writes nothing, so a shutdown never mass-marks proxies pending.

## 6. A one-dial liveness gate protects the sample block

Paid proxies get a stage-0 check before any sample block runs: a single SOCKS5 and API reachability
dial. A proxy that cannot greet in one dial is dropped immediately. No sample block is wasted on a
shell that will not answer.

## 7. Configuring the probe

Probe settings live in `~/.urnetwork/proxy_probe.json`. Every field is optional; omitted fields keep
their default, and changes apply within a few seconds without a restart.

- `enabled` (true): the global probe kill switch.
- `sample_width` (12): the intended base width, in destination-table hosts.
- `min_sample_width` (0; the paid grader uses 6): the small width a probe starts at.
- `max_sample_width` (36): the upper bound adaptive growth may reach.
- `pass_bar` (0.6): the reachability grade threshold.
- `preferred_bar` (0.9): the preferred-tier threshold.
- `border_line_band` (0.15): how close to the pass bar counts as borderline.
- `timeout_ms` (4000): per-target dial timeout in milliseconds.
- `max_paid_probes_per_tick` (200): the per-sweep paid probe cap.
- `stage0_liveness` (false; the paid grader uses true): the one-dial SOCKS5 and API gate.
