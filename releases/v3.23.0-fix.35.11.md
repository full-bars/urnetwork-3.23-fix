# v3.23.0-fix.35.11

**Released:** 2026-11-15.

Previous release: [v3.23.0-fix.35.10](https://github.com/full-bars/urnetwork-3.23-fix/releases/tag/v3.23.0-fix.35.10).

This release fixes a hotswap bug that could leave a provider dead after the old process exited. It adds per-carrier statistics and optional discovery for extender hosts, turns on loopback diagnostics by default, and makes `urnet-tools` more reliable on hosts with file capabilities and instance units. A host that runs `Restart=on-failure` gets a restart safeguard during the update.

Update and restart. The hotswap fix is in the process that does the hotswap, so restart once after you update. A hotswap from an older build to this one has no test yet.

Legend: **[redeploy]** needs the new provider, tool or container image. **[installer]** needs the updated installer or script. **[no redeploy]** covers documentation, CI and tests.

## Quick start

Install on Linux or macOS:

```sh
curl -fSsL https://install.fullbars.xyz | sh -s -- install
```

On FreeBSD, run the installer as a non-root service account with sudo:

```sh
fetch -qo - https://install.fullbars.xyz | sudo sh -s -- install
```

On OpenBSD, choose an existing non-root service account and replace `urnet` with its name:

```sh
ftp -o urnet-install.sh https://dl.fullbars.xyz/install-openbsd.sh
doas env SERVICE_USER_OVERRIDE=urnet sh urnet-install.sh install
```

Install on Windows in PowerShell. Windows Defender can flag the one-line form as a false positive, because the script downloads and unpacks a program. The safer way has two steps. Download the script, read it, then run it from disk:

```powershell
irm https://dl.fullbars.xyz/install-win.ps1 -OutFile "$env:TEMP\install-win.ps1"
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\install-win.ps1"
```

The Installation guide lists the Defender labels you may see and what to do about them.

Run the provider in Docker with a persistent volume and a single-use auth code from https://ur.io:

```sh
docker run -d --name urfix --pull always --restart unless-stopped --cap-add NET_ADMIN --cap-add NET_RAW --sysctl net.ipv4.ip_forward=1 -e AUTH=authcode -e AUTHCODE='YOUR_AUTH_CODE_HERE' -v urnetwork_data:/root/.urnetwork ghcr.io/full-bars/urnetwork-3.23-fix:latest
```

This release is the provider line. For miner setup, use the separate miner release and its instructions. This workflow does not publish a miner image.

## What's changed

### Fixed

- **A hotswap on a host with RAM logs no longer kills the new provider. [redeploy]** The new process inherited the old process's log pipe as its error output. When the old process finished draining and exited, the next write to that pipe ended the new process with SIGPIPE. systemd counts SIGPIPE as a clean exit, so a unit with `Restart=on-failure` stayed dead. The old process now passes on the original log destination. A new process that still inherits an orphaned pipe drops it at startup when RAM logs are on, and a later hotswap redirects a `/dev/null` error output back to the RAM log. The long-running `provide` command ignores SIGPIPE.
- **A systemd unit restarts the provider after SIGPIPE. [installer] [redeploy]** The installer writes `RestartForceExitStatus=SIGPIPE` and warns when a restart override defeats it. `urnet-tools update` checks the effective unit settings on existing hosts. If protection is missing, it writes one drop-in file, reloads systemd and checks the result. It does not restart the provider. It writes nothing when the operator blocks SIGPIPE with `RestartPreventExitStatus`, and it says so. `urnet-tools status` shows a warning for an unprotected unit.
- **`urnet-tools update` no longer reports "failed to update" after a good restart. [redeploy]** A provider binary with file capabilities hides `/proc/<pid>/exe`, and the updater took that for a failed restart. It now accepts the restart when the control socket reports the new version on a new or freshly started process, or when the process started after the binary swap and the installed binary carries the new version stamp.
- **`urnet-tools` sees more than `urnetwork.service`. [redeploy]** It lists and updates `urnetwork@*.service` instances. No unit is deleted or disabled.
- **`top` and `status` no longer count trim-parked proxies as down. [redeploy]** A trim cap parks proxies on purpose. The old counts showed these as failed, for example "3041 of 4408 down". The parked count is now shown on its own, and draining proxies keep their active client counts.
- **A UDP readiness shard no longer holds an OS thread. [redeploy]** The shards wait through the Go network poller as goroutines instead of blocking one OS thread per shard in `epoll_wait`. The shards are off by default in this line (`SocketReadShardCount` is 0), and no shipped profile turns them on.
- **OpenBSD service commands keep doas when its configuration cannot be read. [redeploy]** A missing `/etc/doas.conf` still selects sudo. Other inspection errors are left for doas to report.

### Added

- **Per-carrier extender statistics. [redeploy]** The extender counts served and refused requests for `tcp-443`, `udp-443`, `udp-4053` and `udp-53`, with the refusal reason. Refusal log lines name the carrier, and active minutes write one summary line. `urnet-tools extender status` shows a `Carriers:` block, and `/metrics` exports `urnet_extender_carrier_requests_total` and `urnet_extender_carrier_refused_total`. Windows of 24 hours and 7 days are not part of this release.
- **Extender discovery. [redeploy]** The extender can serve the directory feed and join the gossip mesh. It is off by default. Use `urnet-tools set extender-discovery on` or `urnet-tools set extender-discovery feed-only`.
- **Loopback diagnostics are on by default. [redeploy]** The pprof listener starts on `127.0.0.1:6060` so a stuck provider can be inspected without a restart. `urnet-tools set pprof off` turns it off. `urnet-tools set pprof <ip:port>` moves it. An explicit `URNETWORK_PPROF` still decides the address when set. If the port is in use, the listener binds a free loopback port and moves onto the target port when the holder exits.

### Changed

- **ClamAV gates the release and the Docker images. [no redeploy]** The release and image workflows fetch fresh signature definitions with `freshclam` before each scan. A detection, a scanner failure, a stale database or a failed refresh stops the release or the image push. VirusTotal still runs after publication and never gates.

### CI and tests

- The systemd shakedown runs a real hotswap in both RAM log modes and fails on a killed successor. It disables the test unit start limit during rapid restart checks and passes shakedown variables through sudo by name. This hotswap case has not run in CI yet.
- Version-detection tests build their own fixture and no longer depend on inherited build flags.

## Known limits

- The shakedown hotswap case has not run in CI.
- A hotswap from an older build is not covered by a test.
- The carrier statistics have not run on a live extender host.
