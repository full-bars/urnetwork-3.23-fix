# v3.23.0-fix.29.2 — 2026-08-15

> [!NOTE]
> Operators must redeploy provider nodes for this change. The hub does not change in this release.
> Before deploying, confirm that no customer sends plaintext SMTP on port 465. Plaintext 465 is reset after this release.

## 1. Summary

This release ports the SMTP security policy layer from upstream into the fork data plane. Plaintext SMTP and SMTP relay through the tunnel are blocked. Port 25 can never reach a provider. Ports 465 and 587 require TLS, so mail credentials cannot cross the tunnel in the clear.

Encrypted mail submission on port 587 works for the first time. The fork previously dropped all TCP/587 traffic. Two fork divergences from upstream fix real defects found during the port: long TLS mail flows survive past 2 GiB, and a busy provider no longer resets valid sessions at the 1024-flow cap.

## 2. SMTP Policy Enforcement

PR #392 ports upstream's SMTP policy layer. It adds a per-flow guard ahead of the general CFAA policy on every egress path and at the provider ingress.

Port 25 routes locally before CFAA. It can never reach a provider. The provider refuses tunneled port 25 through the general reversed policy.

Port 465 must begin with a TLS ClientHello. Plaintext is reset and dropped.

Port 587 permits only a bounded EHLO/HELO/QUIT/STARTTLS negotiation. The bound is 2 KiB with a 510-byte line limit. Transaction and authentication commands are rejected before STARTTLS. After STARTTLS a ClientHello is required.

The provider ingress applies the same rules. Its per-flow state is namespaced by the authenticated source id.

TCP/587 moves from drop to pass in CFAA. UDP/587 and port 25 stay drop.

Per-flow state is bounded at 1024 flows. Retransmissions are validated. Gaps and stream splices fail closed. A fresh SYN replaces tuple state. An RST clears it. Each rejection emits an RFC 793 reset and a block counter entry.

## 3. Fork Divergences from Upstream

The fork fixes two defects in upstream's SMTP layer. Both are documented in the code and pinned by regression tests.

The secure-phase sequence offset uses unsigned arithmetic. Upstream's signed check reads a flow offset past 2^31 bytes as negative. A TLS flow that advances past about 2 GiB of data is falsely rejected and latched. The fork's version keeps such flows alive. TestSmtpSecureFlowAdvancesBeyondHalfSequenceSpace pins this.

Flow-table eviction prefers rejected or still-negotiating flows. Upstream's sampled eviction can remove an established secure flow. The recreated state then re-inspects opaque TLS data as a fresh negotiation and rejects it. A provider with more than 1024 concurrent SMTP flows would reset valid sessions. The fork's version spares secure flows until the table is made entirely of secure flows. TestSmtpGuardEvictionSparesSecureFlows pins this.

Both defects are filed upstream as issues.

## 4. What's Changed

- fix: enforce SMTP policy on egress (port 25 local-only, TLS-required 465/587) — PR #392, labels: area:core, needs-fleet-deploy, security

## 5. Breaking Changes

- Plaintext SMTP on port 465 is reset and dropped. Mail clients must use TLS.
- Port 25 traffic routes locally. It cannot be sent through the tunnel.
- Port 587 transaction and authentication commands are rejected until STARTTLS and a ClientHello.
