# Release v3.23.0-fix.18.3

**Date:** 2026-06-08  
**Type:** Feature Release  
**Severity:** Normal

## Overview
This release introduces "Hot-Reload 2.0" for seamless CLI-based proxy management and the `[direct]` native connection feature to maximize host utilization.

## ⚙️ Operations & CLI Features
### Hot-Reload 2.0
> [!TIP]
> Adding or removing proxies via CLI now automatically triggers a graceful hot-reload, eliminating the need for manual file edits or `urnet-tools proxy refresh`.

- **Workflow:** Running `urnet-tools proxy add <file>` or `urnet-tools proxy clear` updates the internal database and signals the provider.
- **Behavior:** The provider staggers the startup of new proxies to prevent API rate limiting, while the existing fleet remains fully operational.

### Sample CLI Workflow
```bash
# Add a new proxy list to your running provider instantly
urnet-tools proxy add new_proxies.txt

# Clear all external proxies while keeping the node online
urnet-tools proxy clear
```

## 🔋 Resilience & Earnings
### `[direct]` Native Connection
> [!NOTE]
> The VPS native IP is now unconditionally spawned as `proxy[0]`. This ensures your native bandwidth earns continuously alongside your SOCKS5 proxy fleet.

- **Status:** Integrated into existing `proxy health` and `proxy traffic` telemetry commands.
- **Protection:** Immune to hot-reload deletions; even if you clear your entire SOCKS5 list, the `[direct]` connection remains active.

## 📊 Telemetry & Observability
- **Wider ASCII Tables:** Formatting for `proxy health` and `proxy traffic` updated to improve column alignment on standard terminal widths.
