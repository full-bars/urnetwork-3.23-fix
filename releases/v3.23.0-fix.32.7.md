# v3.23.0-fix.32.7

> [!NOTE]
> This release makes what the provider tells you more accurate and more live. `urnet-tools status` no longer reports an auth outage for normal background retries, and a node stuck in startup no longer reads IDLE. `urnet-tools top` now runs at up to 100ms, shows billable and total traffic, has a graph that scrolls smoothly, and no longer calls a slow provider lost. It also gains a zoom window, a runtime Internals panel, a menu for color themes and graph styles, and a layout that stops reserving room a quiet node does not use. The message pool dump ends with a one line verdict. There are no behavior changes to how the provider relays traffic.

> [!NOTE]
> Known limitation. `urnet-docker top` runs the `urnet-tools` inside the container, so a container shows the new `top` only after its image is rebuilt with this release.

## What's Changed

### Fixed

- **"why idle: auth failing" fired on normal noise** ([#688](https://github.com/full-bars/urnetwork-3.23-fix/pull/688)): the idle hint blamed auth if the failure counter rose at all in the last 10 minutes. A large paid pool always has a few percent of its proxies failing and retrying every minute, so a healthy node read as having an outage, and the check ran before "no traffic offered", hiding the real reason. Auth is now blamed only for a failure wave (a quarter of the pool failing in the last minute, with a floor) or a pool that is mostly not connected while failures are happening. Otherwise the hint says what is true and shows the numbers behind it, for example `no traffic offered (4056/4513 proxies up, ~228 auth retries/min)`.
- **A node stuck in startup read IDLE** ([#688](https://github.com/full-bars/urnetwork-3.23-fix/pull/688)): the state came from uptime alone, while the systemd `STATUS=` line already knew the provider was still resolving proxies. The state now follows the real startup phase: a node still resolving proxies stays `starting` for up to 5 minutes, then reads `degraded` as a stall, and an unreachable or empty proxy source reads `degraded` immediately. A direct-only node settles as soon as startup publishes its zero configured count. A `proxy_url.json` that exists but cannot be read is reported as an unresolved proxy source, not as a settled direct-only node; a missing file still means no URL sources.
- **`degraded` now says why** ([#688](https://github.com/full-bars/urnetwork-3.23-fix/pull/688)): a new optional `state_reason` field, shown as a `why starting` or `why degraded` row in `status` and `top`, names the cause: an unfinished startup phase, `6 of 10 proxies dead or degraded`, or resource pressure.
- **The `top` graph shimmered instead of scrolling** ([#690](https://github.com/full-bars/urnetwork-3.23-fix/pull/690)): a series longer than the plot was averaged into buckets counted from the oldest sample, so once the 10 minute ring was full every second shifted every bucket boundary and re-averaged every column. Buckets are now aligned to the provider's own sample count (a new `history_seq` field, so a sample keeps its place whatever the poll and tick timing do), so a completed column never changes, a young series grows in from the right, and the graph fills its width. The live rate is drawn as its own newest column and never sets the chart's scale.
- **`top` called a slow provider lost** ([#690](https://github.com/full-bars/urnetwork-3.23-fix/pull/690)): on a starved node the provider answers late, and one missed answer flipped the screen to `DISCONNECTED` and wrote `lost the provider` and `reconnected` lines into Events, over and over. A provider that has answered now stays connected through timeouts, with the last data kept on screen and a `SLOW` marker in the header, and is called lost only after 20 seconds of silence. A refused connection or a missing socket, which is what an update or a restart looks like, is still reported at once. While a provider struggles, `top` also asks for less: each missed poll adds spacing to the next snapshot request (2s, doubling to 10s), a reply that takes seconds spaces the following ones by how long it took, and after two misses in a row the light traffic poll stops too. The light `traffic` command gives up after 1.5 seconds instead of holding a socket for 5. Events gets one `provider slow` line for an episode that is more than a blip, and one `responsive again` line when it ends.

### Added

- **Live rates at up to 100ms in `top`** ([#690](https://github.com/full-bars/urnetwork-3.23-fix/pull/690)): `top` polls a new light `traffic` control command, which returns live counter sums without building a snapshot, and derives rates from the deltas over a one second sliding window, like btop. The full snapshot is still fetched at most once a second. The fastest refresh rate is now 100ms, and the newest graph column is the live rate. An older provider without the command falls back to the snapshot's own once-a-second rates.
- **Billable and total traffic** ([#690](https://github.com/full-bars/urnetwork-3.23-fix/pull/690)): the snapshot carries billable and total byte totals for the run, the lifetime billable total, and the total-traffic rate. `top` and `status` show both rates with their 1m and 5m averages and the bytes moved, and `top` stacks a billable graph and a total traffic graph when there is room.
- **Clear logs when URL-sourced proxies are added** ([#690](https://github.com/full-bars/urnetwork-3.23-fix/pull/690)): a URL fetch cycle printed several differently-phrased detail lines and none said plainly what happened to the pool, so the quiet case, every address already known, was buried. Each cycle now prints one line per source saying how many of its proxies were added (`source lists.example.com/http.txt: +8 new of 42 listed (30 already known, 2 rejected, 2 dead)`), labeled by host and path only, so a token in the query string or in the userinfo is never logged (path segments that look like credentials, including JWT-like dotted tokens and a secret with an encoded slash, are shown as `[redacted]`, a URL that cannot be parsed is shown by its host alone, and one whose credentials may hold an unescaped slash is shown as `[unparseable source]`; a short token in an ordinary path segment cannot be recognized, so keep tokens in the query string), and ends with one headline, kept in the important buffer, for example `+12 new to the pool from 2 sources (48 already known, 9 rejected, 3 held for re-probe); pool now 340 qualified of 371 cached`, or `nothing new from 2 sources (60 already known, 0 rejected)`, or `every source failed`. When a reload starts URL-sourced proxies it announces them on their own line, including how many are held until the file proxies finish warming up, and the routine `reloaded: +N added` summary now says where the additions came from, for example `+14 added (url 12, file 2)`. The `reloaded: +N added` prefix is unchanged.
- **A summary line after every message pool dump** ([#689](https://github.com/full-bars/urnetwork-3.23-fix/pull/689)): the per-tag counters are a wall of lines where nothing says which is a problem, and a low return percentage is not a leak, since buffers in flight count as taken but not yet returned. The dump now ends with one line that judges the trend of outstanding buffers over the last 10 dumps (steady growth that is not levelling off is a possible leak; a plateau, a ramp that flattens and jitter are not), flags allocation churn, reports what the pool is holding, and otherwise says all clear. Problems log as a warning naming the pool, tag and call site. The caller label is also sorted now, so a tag keeps one spelling from dump to dump.
- **Zoom in `top`**: `w` zooms both graphs to the last 15 seconds at the refresh rate, one column per poll (150 columns at 100ms), built from the live counters, so it needs a provider with the `traffic` command. Completed columns never change as the window scrolls. `w` again returns to the 10 minute view.
- **A runtime Internals panel and a goroutine list in `top`**: two new light control commands feed a panel with the goroutine count and its trend, heap objects, stacks, the GC goal, the allocation rate, GC cycles and pause p99, the GC share of CPU and scheduler latency p99, all live at the refresh rate (`internals` is a cheap `runtime/metrics` read, cached for 100ms; the pause and latency quantiles are computed over one second windows so they are figures, not noise). `g` swaps the panel for the goroutine profile grouped by where each goroutine is parked, which is how a goroutine leak shows up. The profile stops the world briefly (about 80ms of CPU and a 9ms worst scheduler stall measured at 95,000 goroutines), so the provider takes it at most once every 5 seconds however many viewers ask, and `top` asks only while the list is on screen. Both are dropped first when the provider is struggling.
- **A steady y-axis in `top`**: the axis rises at once, with headroom, when the data outgrows it, and comes back down only after the peak has stayed well under it for 30 seconds, so a burst scrolling off the left edge no longer rescales the whole chart.
- **A menu for color themes and graph styles in `top`**: `m` opens it. Pick a theme (`default`, `nord`, `gruvbox`, `dracula`, `solarized-dark`, `tokyo-night`, `high-contrast` or `mono`) and a graph style (`braille`, `block` or `tty`). Changes apply at once and are saved to `top.conf` in your user config directory. `NO_COLOR` and a dumb terminal still force `mono`.
- **A layout that fits a quiet node**: a pool of three or fewer proxies (a direct-only node has none or one) is one line instead of four bars, the Events panel takes only the rows its events need, and Resources is sized to its figures. The rows given back go to the graphs.

### Changed

- **`-` refreshes `top` faster and `+` slower**, like btop. They were the other way round. The footer now reads `- 100ms +`.

## Deploy Notes

1. **Update and restart, no config changes.** `urnet-tools update` picks up the release. Update the provider to get the new `traffic` command and snapshot fields; a newer `urnet-tools` against an older provider still works and shows the snapshot's own rates.
2. **Compatibility.** `traffic` and `state_reason` are additive optional snapshot fields, and `internals` and `goroutines` are additive control commands. An older `urnet-tools` ignores them, and an older provider renders exactly as before: `top` against it shows no Internals panel, and `w` (zoom) needs the `traffic` command.
3. **The pool summary line needs the per-tag dump.** It appears wherever the per-tag pool dump already does.
4. **Try the new `top` without a provider:** `urnet-tools top --demo --interval 100ms`.
5. **`top` against a busy node.** Update `urnet-tools` on the box you run `top` from; the slow-provider handling is in the client and needs no provider change.
