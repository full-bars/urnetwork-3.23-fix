# v3.23.0-fix.30.3 — 2026-08-19

> [!NOTE]
> Operators must redeploy provider nodes for the docker tag fix. The Go tools change with a critical busybox fix for in-container updates. Nightly-image users must pull the new image; the nightly self-update path is also fixed. The hub does not change in this release.

## 1. Summary

This release fixes a busybox `mktemp` incompatibility that broke every in-container `urnet-tools update`, preserves the full semver docker tag on release pushes, completes the Go tool's default-provider selection with privilege-safe cross-platform logic, and hardens the nightly image's self-update path against the same update-failure class.

## 2. Docker: Busybox-Safe mktemp for In-Container Updates

PR #406 fixes a regression that made `urnet-tools update` fail inside the Alpine-based provider container.

The shell update path used `mktemp /tmp/urnetwork-update-XXXXXX.tar.gz`. Busybox `mktemp` (the only `mktemp` in the Alpine image) requires `XXXXXX` as the **last characters** of the template; the `.tar.gz` suffix caused `Invalid argument` and aborted the update before downloading. The fix creates a temp **directory** with `mktemp -d /tmp/urnetwork-update-XXXXXX` (busybox-safe) and places the tarball inside it. Cleanup is a single `rm -rf`.

The test harness is hardened: a busybox-enforcing `mktemp` stub now rejects any template that does not end in `XXXXXX`, then delegates to the host `mktemp`. This catches regressions on both the tarball path and the staged-provider path. New coverage sections exercise zero-byte tarballs, partial downloads overwritten by the mirror, the `update-pending` marker lifecycle, architecture mapping, and the busybox stub itself.

## 3. Nightly Image Self-Update Hardened

The nightly startup script (`start_nightly.sh`) had the same update-failure class that #406 fixed in the stable path. Its `func_check_update`:

- Reused a shared `/tmp/urn_update` directory (no per-attempt isolation).
- Downloaded with `curl -sL` without `-f`, so a bad HTTP response was written to the archive and could be mistaken for a successful download.
- Had no cleanup on failure paths, leaking the temp dir.
- Touched `update-pending` **before** the download/extraction succeeded, so a failed update left the restart loop believing a new binary was installed.

The function now stages the whole update inside one busybox-safe `mktemp -d /tmp/urnetwork-update-XXXXXX` dir. `curl -sfL` fails on any HTTP error. Every failure path (download, extract, missing binary, install) cleans the temp dir, logs `Update aborted; existing provider left untouched`, and returns without touching `update-pending`. The new binary is staged on the target filesystem and atomically renamed into place, so a failed copy cannot truncate the running provider even when `/app` is a separate mount. The version file and restart-marker writes are checked: the marker is written only after the binary swap and version write succeed, and the `pkill` that restarts the provider runs only after the new binary is in place. The metadata fetch is now guarded so a transient API or network failure cannot trip the script's `set -e` and kill the provider supervision loop; the check simply skips that attempt.

## 4. CI: Full Semver Docker Tag on Release Pushes

PR #405 restores the full semver tag (for example `v3.23.0-fix.30.3`) on release workflow pushes. The workflow previously truncated to the minor segment; the full tag is now preserved so operators can pull the exact release they deployed.

## 5. Go Tools: Default to Current User's Running Provider

PR #404 completes the default-provider selection for `urnet-tools`. The tool now:

- Detects the current OS user on Linux, Darwin, and Windows (`currentUserName` defined cross-platform).
- Discovers the provider running under that user and auto-selects it for read-only commands (`logs`, `status`, `summary`).
- Gates the auto-default behind a real privilege check: root callers never auto-default; unprivileged callers only auto-default when exactly one reachable provider belongs to them.
- Surfaces the selection reason in output (for example `auto-selected: sole provider for user alice (pid 1234)`).
- Falls back to an explicit `sudo <binary>` hint when an unprivileged user has `sudo` available but the target provider is owned by another account.

Test seams cover the privilege guard, the fallback message, and the cross-platform username resolution.

## 7. Deploy Notes

The provider binary itself is unchanged in this release. Operators should redeploy provider nodes to pick up the updated image scripts (the nightly self-update fixes) and the full-semver docker tag behavior on future releases.

The Go tools (`urnet-tools`, `urnet-docker`) change significantly. The busybox `mktemp` fix is **critical**: any provider container running v30.2 or earlier cannot self-update. Rebuild and redistribute the tools, and redeploy containers to unblock in-container updates.

Nightly-image users must pull the new image. The nightly self-update path fix means a nightly container can now update itself reliably, but the image itself must carry the fixed script, so a pull is required once.

The hub does not change in this release.
