## What Changed

### MultiRaceClientCount = 16 (Unconditional)

The CPU-based tier system from v3.23.0-fix.24 (10/14/16 by core count) was unnecessarily conservative. All race goroutines are I/O-bound — they fire a packet and block on network response — so single-core nodes benefit just as much as multicore ones. The actual racer count at runtime is bounded by `min(16, len(healthyProviders), packetBudget)`, so setting it to 16 everywhere just means "race all available providers."

Single-core fleet nodes get the same 16-provider ceiling as their big siblings.

### CI Pipeline Improvements

- **Docker build depends on test success**: `build-and-push` now `needs: test-and-lint`, saving ~3 min of Docker build compute on every failing PR.
- **Go module cache restored**: Re-added `~/go/pkg/mod` cache alongside existing build cache. Saves ~30s per run.
- **Test order optimized**: Go tests (with `-race`) now run before shell installer tests for faster failure feedback.

## Deployment Notes

- **No breaking changes** from v3.23.0-fix.24.
- Single-core nodes now race up to 16 providers instead of 10. Bandwidth cost is ~24 KB per new connection (16 × ~1500 bytes first packet). At gigabit links and typical flow rates, this is noise.
- CI changes affect PR checks only — no runtime impact.

### Quick Install

### Docker
```bash
docker run -d \
  --name urnetwork \
  --restart unless-stopped \
  --cap-add NET_ADMIN \
  --cap-add NET_RAW \
  -v urnetwork-jwt:/root/.urnetwork \
  -v urnetwork-vnstat:/var/lib/vnstat \
  -e BUILD=jwt \
  -e URNETWORK_AUTH_CODE=<your-auth-code> \
  -e URNETWORK_PROFILE=auto \
  -e ENABLE_VNSTAT=true \
  ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.24.1
```
