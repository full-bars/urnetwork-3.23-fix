## What's New

### `urnet-tools update -f` now reliably restarts the provider

Two bugs fixed:

1. **`FORCE` variable mismatch** — `urnet-tools update -f` parsed the `-f` flag inside the subcommand handler (which sets `force_update` for version comparison), but the global arg parser never saw `-f` because "update" matched `*)` and `break`d the loop first. So `FORCE` (uppercase) stayed `0` while `force_update` (lowercase) was `1`. `stop_systemd_units` checks `$FORCE`, so it always took the non-force path: "binary will be updated on disk, restart when convenient". The subcommand handler now also sets `FORCE=1`.

2. **Bootstrap chicken-and-egg** — The script self-update fix from v24.12 (check tarball-bundled `urnet-tools`) was in the script determination code, which the old script never reaches — it just does `cat "$0"` (reads itself from disk). Now a check for `$workdir/urnet-tools` is placed in the **common script-writing section** (after `cd "$workdir"`, before writing), so even the oldest script picks up the bundled `urnet-tools` from a freshly-downloaded tarball on the very first update.
