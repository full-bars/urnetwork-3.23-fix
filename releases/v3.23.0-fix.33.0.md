# v3.23.0-fix.33.0

> **Built from:** `integrate/v33-final` at `1ac535426` (the frozen head for the v33 tag, 2026-10-17: the 2026-10-16 head `26091ee3c` plus the tagged fleet commitment, the fleet publish role refusal and a test-only fix for a flaky H3 test; refresh if a tag-blocking fix moves it).

> [!IMPORTANT]
> **v33 is the Bittensor mainnet release.** Everything a provider needs to take part in SN25 on mainnet is in this build: the signed wallet consent the settlement pays against, hotkey delegation, claiming by hand or with the claim daemons, fleet registration, multi-operator provide, and the transfer-layer capabilities the platform's modern-provider gate looks for. If you run providers and want to be paid through SN25, this is the version to be on.

v33 is also the first stable release of the line that swaps in the upstream platform transport with a dual-stack (IPv4 and IPv6) platform connection, ports the IP layer fixes, and adds ICMP echo and provider-side fragment reassembly. It was soaked on canary nodes through its pre-releases and the dailies that followed the freeze. `urnet-tools update` offers it as the new stable release.

## Bittensor mainnet compatibility

**What changed for mainnet, in the order you will need it:**

- **Resizable transfer windows advertised.** Every Ack the receiver sends carries `receive_window_byte_count`, the out-of-order hold capacity it enforces. The platform's capability probe reads this, together with post-quantum end-to-end encryption, to class a provider as modern. Receive memory is unchanged.

**The command families, in the order you will need them:**

### Wallet consent

Release settlement pays only a wallet whose coldkey signed the network consent. `provider wallet status` shows what is set. `provider wallet sign <coldkey_ss58>` serves one local page where a browser wallet extension signs the consent, and the seed phrase never leaves the extension: run it on your own computer, never on a fleet node. A headless signer can use `provider wallet challenge` and `provider wallet set` instead. A later consent must start at a later epoch than the one it replaces. `urnet-tools wallet` wraps the same commands and refuses the signing forms on a fleet node. See `scripts/wallet-consent/README.md`; check it afterwards with `provider wallet status`.

### Hotkey delegation

`provider wallet hotkey challenge|set|status` delegates the network consent to a hotkey, so the network's payments go to the hotkey's coldkey on every operator that stores the consent. `challenge` prints the exact statement for the coldkey to sign offline, or `set` reads the coldkey seed with `--coldkey_seed_file`; `set` then signs with the hotkey, stores the generation locally and submits the chain and the delegation to the operator this provider resolves (its saved network config, otherwise the default platform URL). A delegation starts two epochs after it is signed and is not retroactive, so sign early if an epoch matters. Setting the same message again resends it and renews the window; run it from each provider you run so every operator you serve stores the chain. Check the operator with `provider wallet hotkey status`: it reports whether it adopts the head.

### Claiming by hand

`provider claim` claims the epochs that hold a payout for one of your client identities, one run each time. It needs the login of a client that served traffic: pass `--store-client=<key>` or `--provider-jwt=<file>` on a provider node, or `--legacy-coldkey=<coldkey_ss58>` for an epoch paid through the legacy network token. The command prints the outcome per credential. The claim calendar is the subnet's own: as of this release, an epoch becomes claimable once its payout root is final on chain, and the command says when there is nothing claimable. `provider snclaim` is the low-level tool beside it: sn's `snclaim` command (`submit`, `status`, `withdraw`, `v2 status|claim|check`) as a subcommand, including `withdraw` to retry a v1 claim credit whose payment was deferred; pass `--help` after `snclaim` for its usage.

### Claim daemons

`provider claim-daemon --config=<file>` (settlement v1) and `provider claim-daemon-v2 --config=<file>` (settlement v2) claim settled epochs as they finalize, so no epoch waits for a hand run. Both require an explicit durable-volume declaration (`--durable-volumes=<path>` with `--durable-volumes-sha256=sha256:<64 hex digits>`) and a private state directory: signed transactions are written before they are broadcast and reconciled after a restart, never replaced. v2 needs no operator credential. `provider claim-daemon-v2 --v1-config=<file>` runs the v1 daemon beside v2 during the transition. They poll on the configured `poll_seconds`. Check the queue file under the state directory for each entry's status.

### Fleet (head tier)

`provider fleet manifest|register|publish|bind|sign|status|revoke` drives the on-chain fleet registration of a head node from one canonical manifest. Keep the write commands and their seed files on a workstation or a locked-down host, not a mining host. `register` is a plan unless `--apply` is given: it reads the live burn, refuses a burn above `--burn_limit_rao`, quotes its fee and broadcasts nothing. Mainnet writes need the reviewed runtime authority pin (`--mainnet-runtime-authority` with its sha256) and a durable-volume declaration, and every broadcast is journaled, so a crashed write is reconciled instead of duplicated. `publish` commits the manifest hash on chain in the tagged `urfleet1` format (the tag followed by the 32-byte hash), the only fleet format the platform's commitment oracle mirrors, closes an unresolved publication recorded in the older untagged format before it writes, and refuses to sign from a validator or subnet-owner hotkey with no override. A fleet whose commitment was mirrored before the tagged format must republish with this release before about block 9,360,673 or its bindings stop. `bind` is the dual-signed member binding through the relayer, `sign` prints the signature for the Top 200 submission page, `status` reads the chain back against the manifest and `revoke` ends a binding at a future epoch. `bind-head` and `unbind-head` are unchanged: the fleet group is additive. Check afterwards with `provider fleet status`.

### Multi-operator provide

`provider operators` lists the published operator list with each operator's credential state. `provide --all-operators` runs one provider per operator from this one command, each with its own home and provider state under `~/.urnetwork/operators/<domain>`. The list is fetched over https (http only for loopback), is size-bounded and its digest is printed; the last good copy is kept, so the commands work while the list host is down. An operator without a network token is reported as awaiting auth and starts on its own once the token is written. `--api_url` is refused with `--all-operators`. Check afterwards with `provider operators`. `provider choose_network --show` prints the network in effect, and `choose_network` warns when a saved URL is unencrypted.

**What to do after upgrading.** Nothing here runs unless you start it, and nothing is required for a node to keep providing. The optional steps, in order:

1. Sign the network wallet consent on your own computer: check with `provider wallet status`, sign with `provider wallet sign <coldkey_ss58>`, never on a fleet node.
2. If you mine through a hotkey, sign the hotkey delegation early: it starts two epochs after you sign it and is not retroactive.
3. Claim settled epochs with `provider claim`, or run `provider claim-daemon-v2 --config=<file>` (with its durable-volume declaration) to claim for you.
4. Fleet registration (`provider fleet ...`) only if you run a head node; read the dry run first.

The wiki pages explain each step with examples: [Bittensor operations](https://github.com/full-bars/urnetwork-3.23-fix/wiki/Bittensor-Operations), [Bittensor claim daemons](https://github.com/full-bars/urnetwork-3.23-fix/wiki/Bittensor-Claim-Daemons), [Bittensor fleet](https://github.com/full-bars/urnetwork-3.23-fix/wiki/Bittensor-Fleet), [Bittensor hotkey delegation](https://github.com/full-bars/urnetwork-3.23-fix/wiki/Bittensor-Hotkey-Delegation), [Multi-operator providers](https://github.com/full-bars/urnetwork-3.23-fix/wiki/Multi-Operator). The same pages ship in `docs/`.

> [!NOTE]
> The platform's modern-provider gate turns on by default at 2026-10-21 00:00 UTC (as of the platform source at the time of this release; the platform can change it). The window-acknowledgement and post-quantum capabilities it looks for are in this build and are covered by tests (the platform's own capability probe could not be pointed at this fork, so the tests are the evidence). Windows cannot run the commands that read private seed files (`wallet hotkey`, `fleet`); run those on Linux or macOS.

## Highlights

- **Dual-stack platform transport.** The direct identity connects over IPv4 and IPv6. Switch live with `urnet-tools set ip-version dual|ipv4|ipv6|legacy`. Per-family counters and log lines are included.
- **Upstream transport swapped in.** DNS and DNS-pump carriers are automatic fallbacks on the direct identity. The `h3` key is `off|direct|on`, a proxy count, or `all`. A SOCKS5 UDP relay and path check carry QUIC for proxied identities. QUIC datagrams are on by default, as upstream.
- **H1+ is on by default again.** The H1 dial is fixed to close losing dials, keep the outage guard, and not fall back on 429 or 5xx. The framed-upgrade rejection cache is scoped to its route.
- **IP layer.** IPv6 extension headers are walked in the parser. A failed upstream dial now answers the source (RST, ICMP unreachable, or nothing on timeout) instead of going silent. An oversized IPv4 UDP reply is fragmented at the IP layer.
- **Fragments reach the NAT.** A provider reassembles fragmented UDP datagrams from tunnel clients before the parse (each client limited to its own share of the cache), applies policy to the whole datagram, and hands the NAT the complete datagram. An unfragmented IPv6 flow behind an extension header keeps its shard.
- **ICMP echo, on by default.** A tunnel client can ping through a provider. It goes through the same security policy as UDP and TCP, uses unprivileged sockets, has fixed NAT-wide flow caps, and switches itself off per address family with one log line when the kernel refuses such sockets. `URNETWORK_ICMP=off` turns it off.
- **Idle DMCA flow entries are reclaimed.** The detector's flow table drops an entry after five minutes without traffic in either direction (`FlowTtl`), so quiet flows no longer wait for the capacity bound. Only destination ports 1024 and above are tracked, as before. `urnet_dmca_flows`, `urnet_dmca_flows_idle_reclaimed_total`, `urnet_dmca_idle_scan_seconds`, `urnet_dmca_verdicts_total{reason,protocol}` and the resumed-after-reclaim counters show the effect.
- **Stream sequences no longer outlive their transport.** A single-ended stream sequence now ends when its P2P transport ends, instead of waiting for a platform close that may never arrive. `urnet_stream_sequences_live` and `urnet_stream_sequences_reaped_transport_ended_total` in `/metrics` show the effect, and the stream and P2P accounting series cover kinds, lifetimes, close reasons, open requests and transport churn.
- **Per-path TLS session resumption.** Each dial path (normal, the proxy path, every resilient mode) keeps its own bounded session cache, so a resumed handshake skips certificate verification and allocates about 57 percent less. A ticket is never offered on another path. `urnet_tls_handshakes_total{path,host,result}` labels every handshake by dial path, target class and result.
- **A long dial backoff tier for dead identities (provider).** After ten consecutive failed dials while the platform answered some other dial, an identity waits 5 to 10 minutes instead of 60 seconds, so a dead proxy stops burning the shared attempt budget. Outage failures never count toward it; success, kick and reset clear it. `URNETWORK_DIAL_LONG_BACKOFF=off` disables it. `urnet_dial_backoff_long_tier_active` and `_entered_total` show it.
- **STUN servers are sampled live.** Sessions draw from the upstream pool of live servers instead of two long-dead ones, and the gather is bounded at 2 seconds, which removes the per-minute timeout recovery churn.
- **`/metrics` is on by default.** The provider serves Prometheus metrics at startup without any switch, on loopback plus the machine's Tailscale address only, never a public interface. `urnet-tools metrics off` turns it off for good and `URNETWORK_METRICS` names an address; a HotSwap candidate never starts one.
- **Client dial-failure gates.** The multi-client uses the provider's dial-failure answers to warn a failing provider, once the strikes span two or more destinations.
- **The credential is renewed when the platform refuses it**, and refusals count toward the revoked-identity safety net.
- **Every `urnet-tools` command has full help text**, with a test that walks the command tree.
- **Optional client key publication opt-out.** Off by default, and refused whenever encryption is on.

## Fixed

- The wallet consent journal's read-modify-write is locked, so concurrent wallet commands cannot lose an entry.
- A transport pin is disabled only once its replacement is up, and upgrade routes are named by identity, not by dialer pointer.
- The client send path no longer drops ordinary traffic: the SMTP guard's "not applicable" verdict was treated as a refusal. Provider nodes were not affected.
- The dual-stack group no longer stays on the legacy transport for a whole launch when the first IPv6 probe fails, concurrent stack changes are serialized, and the group's memory budget follows the transports the stack uses.
- Dual-stack standby and pinned-down counters no longer stay on after a stack change or a group close.
- Windows: refused and timed-out dials are recognised, and the seed file mode rule no longer rejects every seed.
- A disabled transport's early session end is no longer treated as platform evidence.
- The wallet seed file is read through the descriptor that was checked.
- The pre-release shakedown no longer hangs on `urnet-tools proxy health`, re-pins a pre-release target after its restore step, re-registers the URL source before the Phase 2 window, clears systemd's start rate limit around the W3 starts, and its sections T, V1 and Z now test the current tool and the current UX.
- The `control_frames` metric counted a reset's frame as a stream open; opens are counted where the open happens. The P2P connect-failure metric's description now says exactly what it counts.
- DoH connections are bounded per origin (16, or the configured HTTP concurrency), and expired address-association blocks are cleared.
- The proxy address pattern is compiled once instead of per call, and bracketed IPv6 proxy lines (`[v6]:port`, with or without credentials) parse correctly instead of being split into a broken address.
- The pinned root pool is parsed once and shared, as upstream does; nothing in the fork mutates `RootCAs`.

## Known limits

- Transfer-layer upstream work (memory bounds, the reliable lane, subprotocols) is not in this line yet.
- The client send path for ICMP stays off.
- The upstream pure-ACK direct path is not in this release: it is implemented on `perf/pure-ack-upstream-style` and is on one canary; it needs more fleet time on real download traffic before any decision.
- Windows: the Bittensor commands that read private seed files (`wallet hotkey`, `fleet`) refuse to run on Windows by design.
- The upstream UDP shared-socket poller (epoll) is not in this release: ported on `feat/udp-shared-readiness` as v34 preparation. The fleet profile puts the UDP flow layer at about one percent of goroutines, so it is a stack and CPU win, not the memory win.
- The unadmitted-return release is not in: it was shelved (the fork has no unbounded retry to cap, and a false release could drop a live client's flows).
- Updating to this release from a build older than 33 (a 32.10 tool, for example) can print `verification could not confirm the new process is running` and exit non-zero even though the update completed: the takeover and the swap land, then the old tool's confirmation window runs out. Confirm with `urnet-tools version`; run `urnet-tools update` again for a clean exit. The tool in this release does not print it.
