# v3.23.0-fix.24.34 — 2026-07-03

## Installing / Updating

**Binary (bare metal / VM):**
```sh
curl -fSsL https://raw.githubusercontent.com/full-bars/urnetwork-3.23-fix/refs/heads/main/scripts/Provider_Install_Linux.sh | sh -s -- install
```

**Updating an existing install:**
```sh
urnet-tools update
```

**Docker:**
```sh
docker pull ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.24.34
```

```sh
docker run -d \
  --name=urfix \
  --restart=unless-stopped \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  -e URNETWORK_AUTH_CODE=YOUR_AUTH_CODE \
  -e HOST_HOSTNAME=$(hostname) \
  -v urfix_config:/root/.urnetwork \
  ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.24.34
```

## Changes

### Added

**Provider version logged once at process startup**

The binary now emits a single startup line near the top of `provide()` before any proxy work begins:

```
❤️ [startup] provider version=v3.23.0-fix.24.34
```

This fires exactly **once per provider process**, independent of how many proxies are configured. Docker deployments already printed the binary version through the startup scripts (`[INFO] Running UrNetwork build v...`); this change makes bare-metal/binary installs consistent so operators can confirm the running version from logs regardless of deployment type. Existing `client_id` and `instance_id` output is unchanged.

**Goroutine count added to the health heartbeat**

The periodic `[health]` line now includes `goroutines=N`:

```
❤️ [health] uptime=... profile=... heap=...MiB sys=...MiB goroutines=N connections=... proxies=...
```

This makes runaway goroutine growth (for example, the self-wake feedback loop fixed in v3.23.0-fix.24.33) visible in the standard health log instead of requiring `pprof` or manual inspection.

### Changed

**Removed the legacy `WARP_VERSION` environment variable**

`RequireVersion()` previously checked `WARP_VERSION` first and fell back to the linked-in `Version`. The Dockerfile set `WARP_VERSION` to the same value injected via `-ldflags`, so it was redundant and could pin the reported version to the original image version after an in-container `urnet-tools update`. `RequireVersion()` now returns the linked-in `Version` directly, and `WARP_VERSION` has been removed from the Dockerfile.
