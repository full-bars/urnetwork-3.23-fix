## What's New

### 🛠️ Provider Reliability

**Self-heal invalid `Restart=` systemd drop-in**

Found on a fleet node during an outage investigation: a `urnetwork.service.d/restart-override.conf` drop-in set `Restart=yes` — not a valid systemd value (the directive only accepts `no`/`always`/`on-failure`/etc., not a boolean). systemd silently rejected it on every reload and fell back to the base unit's `Restart=no`, leaving the node with **zero auto-restart protection** since at least July 1. A full history search confirmed urnet-tools never generated this file — origin unknown, likely a manual edit. A fleet sweep found the same rogue drop-in on 3 of 31 reachable nodes.

**Fix**: the installer now scans `urnetwork.service.d/*.conf` on every install/update/reinstall and repairs `Restart=yes|true|1` → `Restart=on-failure` automatically.

### 🧠 Core Networking

**Restore correct file:line in log output**

The glog→Logger interface migration (mid-June) added a wrapper frame between call sites and the actual `glog` calls. The verbose (`V(n)`) logging path was updated to account for it; the plain `Info`/`Infof`/`Warningf`/`Errorf` path wasn't. Every plain-level log line in the codebase — the majority of your INFO output — has been reporting `log.go` as its source instead of the real caller since that migration merged.

**Fix**: switched to glog's depth-aware call variants so log lines once again show their true origin (e.g. `message_pool.go:231` instead of `log.go:100`).
