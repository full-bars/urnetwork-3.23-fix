# v3.23.0-fix.30.2 — 2026-08-18

> [!NOTE]
> Operators must redeploy provider nodes for the post-quantum encryption fixes. The provider binary and the Go tools change in this release. The hub does not change.

## 1. Summary

This release makes post-quantum encryption work end to end between an app and a provider. Two fixes land for post-quantum encryption. One fix lands for the Go tool's help text. The provider now enables its encrypted session layer on the serving client. The control channel now routes encrypted handshake messages by handshake generation, which is what the app expects. A provider that carries both fixes accepts an encrypted connection from such an app.

## 2. Provider Enables Encrypted Sessions

PR #400 turns on the provider's encrypted session layer for the connection that serves app traffic.

The provider previously left the encryption mode unset on its serving client. The session layer never started. An encrypted app connection sent a TLS ClientHello. The provider never answered it. The app stalled and eventually gave up.

The provider now sets the encryption mode to Opportunistic. It answers encrypted handshakes when an app starts one. It still serves plaintext connections exactly as before. The mode is Opportunistic, not Required, so a plaintext app is never refused.

The change matches the mode the stock provider build already used. New tests cover the mode switch, the session layer starting, and the safety of repeated setup.

## 3. Control Channel Routes by Handshake Generation

PR #401 ports the handshake-generation routing layer into the control channel. This is the second half of the fix.

An encrypted app connection identifies each handshake with a generation id. The provider previously had no generation layer. It could not recognize which handshake a control message belonged to. It never completed the app's handshake. The connection stalled at the 60-second timeout.

The provider now stamps encrypted handshake and identity-proof control messages with their handshake generation. It routes incoming messages by that generation. An older generation is ignored. A newer generation resets the handshake onto the newer one. A malformed generation id is rejected outright.

The wire format matches the app's own implementation. A provider running this release completes the handshake with an app that has post-quantum encryption turned on. Traffic moves after the handshake.

## 4. Go Tool Usage Text Completed

PR #402 fixes the `urnet-tools` help text. The `usage()` output was missing most of the command surface.

The tool listed only a few core commands. Operators could not discover the tuning, proxy, hub, and maintenance commands from the help text.

The help text now lists the full command surface. It groups commands into core, performance, proxy, hub, and maintenance sections. It shows the target flag and the on/off forms where they apply.
