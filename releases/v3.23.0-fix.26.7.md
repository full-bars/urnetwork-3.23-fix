### **v3.23.0-fix.26.7 — Resilient TLS Fail-Closed, Hot-Path Allocations, Proxy Health Correctness**

This release has two halves. The first is a reliability and code-health pass: it removes a
dead file that was pulling the entire Ethereum/cloud-SDK tree into the *library* package,
fixes two proxy-health reporting bugs (connecting proxies read as degraded, and a connecting
state that could go stale forever), hardens the status server and hub-join client against
hung connections, and zeroes out every `go vet` finding.

The second half is data-plane work. The resilient TLS layer no longer leaks file descriptors
or strands the socket at a modified TTL, and it now fails closed instead of silently
corrupting a TLS stream. The hot-path verbose logging that ran on every packet at `-v=0` is
gone. Resend pacing adopts upstream's capped multiplicative backoff, and a canceled dial is
no longer counted as a backend outage. Roughly 400 lines of contract docstrings landed
across the transfer and routing layers.

### **Highlights**

> [!IMPORTANT]
> **Dependency graph cut by ~21%** (#315). `sn_deps.go` was 4 blank imports of
> `urfoundation/sn` packages — dead since `provider/sn.go` imports them directly. While it
> lived, it pulled go-ethereum, AWS/Azure SDKs, gnark, and more into the **root connect
> library**, so every library consumer (extender, connectctl, bindings) compiled and linked
> the whole tree. Deleting it: `go list -deps .` drops **471 → 370 transitive deps**, and
> `go mod why go-ethereum` now routes via `connect/provider` (the only thing that needs it)
> instead of the root package. `go.mod`/`go.sum` are byte-identical.

>
> [!CAUTION]
> **Resilient TLS: leaked fds, a stranded socket TTL, and a corruptible stream** (#339).
> Both TCP reorder branches in `net_resilient.go` acquired a descriptor via `tcpConn.File()`
> and never closed it, so every failed write leaked one. The socket TTL those branches
> lower to force retransmits was restored **only on the success path**, so a failure left
> the socket at the lowered value for the rest of its life. Separately, a mid-fragment write
> failure returned `0, err` while the buffer still held the full record and earlier fragments
> were already on the wire; a resend re-entered `Write` and re-fragmented from the start,
> duplicating bytes into the TLS stream. `Off()` also discarded any partially buffered record
> instead of draining it.
>
> The fix restores the TTL through `SyscallConn` rather than a dup'd descriptor (no fd to
> leak at all), scopes each restore to the branch that lowered it, drops the buffer and
> disables the layer after an indeterminate write so a retry goes direct, drains on `Off()`,
> and closes the extender connection on failures after the mode switch. This carries
> upstream `connect`'s fail-closed resilient TLS implementation into the fork. Backed by
> 1,138 lines of new tests including an fd-growth assertion over repeated failed writes.

> [!NOTE]
> **Proxy health: connecting proxies no longer read as degraded** (#316, #320, #322).
> `RegisterProxy` reuses the `*proxyHealth` struct on respawn without resetting
> `everUp`/`downSince`, so a freshly respawned instance inherited its dead predecessor's
> state and read as a degraded tier (stale `downSince`). `DegradedProxies()` and
> `ProxyHealthByAddress()` now carry the same `connecting` guard `IsDegraded()` already had.
> Additionally, `connecting` is now **bounded** (`connectingStaleAfter = 65m`): it's cleared
> only by `markProxyUp`/`markProxyDown`, neither of which fires on a failed dial — without
> the bound, a proxy that respawns and can never reconnect would report `"connecting"`
> forever. After 65 minutes (one hourly retry pulse plus margin, matching the provider's
> `deadConfirmDelay` and the ~1h staging window the docs promise operators) a previously
> connected proxy falls back to a degraded tier, while a proxy that never connected at all
> falls back to `dead`, so a hung respawn is distinguishable from a fresh one without mislabeling
> still-staging proxies as dead during the first hour of a deployment.

### **Performance**

* **Hot-path verbose logging no longer allocates** (#329): the provider ships with `-v=0`,
  but an unguarded `V(n).Infof()` still constructs and heap-boxes its arguments on every
  call. The per-inbound-message site in `Client.run` measured **128 B and 5 allocations**
  per message at a disabled level; the per-packet sites in `ip.go` measured 32 B and 1
  allocation. A central fix is impossible (arguments escape at the call site, and `Verbose`
  is an interface), so 35 Tier-1 sites now carry inline `if v := log.V(n); v.Enabled()`
  guards: 17 in `ip.go`, 16 in `transfer.go`, 2 in `ip_remote_multi_client.go`. Guarded
  sites benchmark at **0 B, 0 allocations**. No log level, message text, or format string
  changed; output is byte-identical at any verbosity.

* **Verbose-log gate blind spots closed** (#330): the CI gate protecting the above had two
  holes. A format string shared between a guarded and an unguarded allowlisted site meant
  un-guarding the guarded one would pass silently; the gate now enforces disjointness, so
  the whole class is self-policing. And the extractor's `[^/]` matched across newlines,
  mis-attributing lines and leaving 15 sanctioned formats unchecked entirely (41 allowlist
  entries against a true 55). Both fixed, gate verified in the passing and both failing
  states.

* **Capped multiplicative resend backoff** (#331, upstream port): the fork's resend path
  backed off only while `isBackendDegraded()` and shifted uncapped, reaching 64s at
  `sendCount=6` with a 1s RTT despite a defined-but-ignored `MaxResendInterval` of 8s.
  Upstream's formula backs off on **every** repeated resend, caps at `MaxResendInterval`,
  and starts from the first resend rather than the first transmission. The rationale for the
  unconditional form: when acks are delayed by queueing rather than lost, a flat timeout
  re-sends the whole in-flight window each interval and the duplicates feed the congestion
  that delayed the acks. Extracted into a pure `resendBackoff()` helper so the formula is
  unit-testable.

### **Fixes and hardening**

* **Canceled dials no longer manufacture an outage** (#332): both auth sites counted every
  `connect()` error as a backend failure, including context cancellation from this process's
  own teardown. Closing a multi-client window cancels many transports mid-dial at once, and
  that burst tripped the degraded threshold with fresh timestamps, so the *next* session
  started already gated and skipped its first `CreateContract` per sequence. `RecordProxyAuthFailure`
  sat on the same error, so window teardown was marking healthy proxies as auth-failed and
  feeding them to the dead-proxy reaper. Both now sit behind a `ctx.Err()` carve-out. The
  open-coded failure bookkeeping is replaced with `noteBackendFailure`/`noteBackendSuccess`
  under a mutex, fixing two more defects: the timestamp and counter were separate stores
  (a concurrent success landing between them left a positive count with a zero timestamp,
  which reads as healthy), and an aged-out failure streak was extended rather than discarded,
  so a single new failure could read as a full outage on the strength of two events an hour
  old. This fork keeps the window-expansion gate upstream removed, which made the bug bite
  harder here: a teardown-manufactured outage also blocked the next window from expanding.

* **Contract metrics: three compounding defects** (#328): `provider/contract_metrics.go` had
  no test coverage and three bugs. Every proxy index kept a ~15.4 KB bucket ring forever with
  nothing to free it, and indices are monotonic per unique address, so churn-heavy boxes grew
  without bound. The ring advanced one slot per epoch change regardless of gap size, so an
  idle proxy's stale counts read as recent. And the `24h:` status row was actually 160
  minutes (960 × 10s, clamped). Now: `retire()` on proxy teardown nils the rings while
  keeping the registry entry and lifetime atomics (deleting would zero a returning proxy's
  totals and make a proven-good proxy a reaper candidate), buckets carry their own epoch so
  `window()` stops at the first out-of-range one, and two rings (fine 10s × 420, coarse
  10min × 144) make the 24h row truthful while cutting per-live-proxy footprint from
  15.4 KB to 6.7 KB.

* **Provider status server timeouts** (#317): `ReadHeaderTimeout: 10s` + `IdleTimeout: 120s`
  on the status `http.Server`, matching the hub. A dribbled-header (Slowloris-style) client
  could previously hold connections open indefinitely on the exposed status port.
* **hub-join client hardening** (#317): both PAKE join round-trips now use a 30s-timeout
  client instead of `http.DefaultClient` (a blackholed hub would wedge the CLI forever), are
  context-aware (`signal.NotifyContext` — Ctrl-C aborts a wedged join), and the KE2 decode
  error is checked instead of surfacing as a confusing hex-decode failure later.
* **Stale-connecting bound** (#320, #322): `connectingSince` stamped in `RegisterProxy`; all
  six health-reporting sites treat connecting as active for `connectingStaleAfter` (65 min —
  one pulse cycle, matching `deadConfirmDelay`) and fall back to the degraded tier (or
  `dead`, for proxies that never connected) after. See Highlights.
* **`go vet ./...` fully clean** (#318): removed 12 unreachable `return`s after `panic(err)`
  in `connectctl/main.go` — a permanently-dirty vet was hiding genuinely new findings.
* **hub-join test signature fix** (#321): CodeRabbit's generated tests (landed after #317
  merged) called `doHubJoin` with the old signature, breaking the hub test package build.
* **Hub rollup test flake** (direct to main): the hourly-rollup tests used timestamps that
  could straddle an epoch-hour boundary, failing at the top of the hour. Pinned mid-hour.

### **Documentation**

* **Contract docstrings across the transfer stack** (#333, #334, #335, #336, #338): roughly
  400 lines documenting the invariants that are currently only discoverable by reading the
  implementation. The data plane (`transfer.go`: client, send sequence, receive sequence),
  contract manager lifecycle and provide-key contracts, route manager and multi-route
  selector with transport weights, the RTT window, stream manager and control sync, and the
  net/io message pool, dialing, and framing contracts. No behavior change. The CodeRabbit
  review of #333 is what surfaced the three `net_resilient.go` defects that became #339.
* **`LOG_REFERENCE` refresh** (#327): documents the pulse `connecting` field, hub bootstrap
  lines, and `proxy_health.log` rows.

### **Upstream monitor & CI**

* **PR auto-labeling** (#326, #337): every PR is labeled along two axes, area (from changed
  paths) and type (from the conventional-commit prefix), plus `upstream-port` when the title
  mentions upstream. Porting from `urnetwork/connect` is a recurring category in this fork
  with no way to filter for it before now. `needs-fleet-deploy` and `security` stay manual;
  they are judgement calls, not derivable from a diff. #337 orders the type labeler after the
  area labeler to close a race where the two could overwrite each other. The workflow triggers
  on `pull_request` rather than `pull_request_target`, and the title reaches the script through
  `env:` rather than `${{ }}` interpolation, so an attacker-controlled title cannot be spliced
  into the shell.
* **gofmt sweep and gate** (#324): 29 drifted files formatted (pure alignment, 92 insertions
  / 94 deletions, no semantic change), plus a `Check gofmt` step in `test-and-lint` so
  formatting cannot silently drift back.
* **3-tier AI summaries**: upstream monitor alerts now try the opencode-go gateway
  (`opencode-go/deepseek-v4-flash`) first, DeepSeek API second, Gemini third. Summaries are
  structured (**Architectural Changes / Performance Impact / Breaking Changes**) with a
  `[MUST PORT]` / `[WATCH]` / `[NO ACTION]` portability verdict, and Discord embeds are
  color-coded by verdict.
* **New `monitor-sn-repo` job**: watches `urfoundation/sn` (the Bittensor subnet repo that
  absorbed the old provider code) for commits to `miner/`, `cli/miner/`, `cmd/`, `onchain/`,
  proto, and dependency files, with a portability assessment.
* **Chunked Discord alerts**: alerts over Discord's 4096-char embed limit are now split into
  multiple messages instead of failing silently; every POST's HTTP status is logged.

### **Upgrade notes**

> [!WARNING]
> **Stage #331 on one node before going fleet-wide.** The resend backoff change alters
> pacing on every send, not just during outages, and it is the highest-behavioral-risk item
> in this release. Deploy to a single node, watch `[s]resend` volume and throughput for a
> full traffic cycle, then roll out. Do not bundle it with other data-plane changes when
> validating.

* **This release requires a fleet redeploy.** #328, #329, #330, #331, #332, and #339 are all
  provider binary behavior. Nothing takes effect until nodes are restarted on the new image.
* No configuration changes and no manual action beyond the redeploy.
* The dependency-graph win applies to library consumers; the provider binary size is
  unchanged (it genuinely uses the sn tree).
* If you read `proxy.state` Health during an outage: a proxy that respawns and stays
  `"connecting"` for over 65 minutes now reports a degraded tier again, not `"connecting"`
  forever. A proxy that *never* connected reads `"dead"` once the same bound expires. The
  bound deliberately sits at one full hourly pulse cycle so proxies still staging during the
  first hour are not labeled dead.
* The `24h:` row in provider status now covers a real 24 hours rather than 160 minutes, so
  the number will read higher than before on a busy node. That is the fix, not a regression.
* Proxies previously demoted by the dead-proxy reaper after a window teardown should stop
  being demoted spuriously (#332). No state migration is needed; the reaper re-evaluates on
  its own cycle.

### **Verification**

* Dependency: `go build ./...`, `go build -o /dev/null ./provider/`, `go vet ./...` all
  clean after #315; deps 471→370; go.mod/go.sum byte-identical.
* Proxy health: 10 new/updated tests (connecting excluded from degraded, respawn reads
  connecting, up wins over connecting, stale connecting expires to degraded, stale
  connecting in DegradedProxies, connecting resets on up/down) plus CodeRabbit-generated
  coverage; all pass.
* Resilient TLS (#339): 1,138 lines of new tests over real TCP pairs with a hand-built
  ClientHello that parses into the fragment path, covering TTL restore on both success and
  failure for both reorder branches, buffer drop and layer disable after a mid-fragment
  failure, `Off()` draining a partial record, tail-record failure with content-matched
  injection, and no fd growth over repeated failed writes. Race-clean.
* Backend degradation (#332): 14 tests covering threshold, recency window, immediate
  recovery, the interleaved-success false-positive guard, the stale-streak regression, and
  two concurrency invariants, plus three fork-specific call-site anchors.
* Contract metrics (#328): new `provider/contract_metrics_test.go` with a gap regression
  (confirmed failing against the old implementation), window boundary, ring wrap, 24h coarse
  ring selection, retire-keeps-lifetime-totals, unsubscribe invocation, and concurrent
  add/retire/windowTotals under `-race`.
* Resend backoff (#331): 4 tests including a cap regression confirmed empirically against
  `origin/main` in a throwaway worktree, where the old expression exceeds the 8s cap.
* Logging (#329): `log_alloc_bench_test.go` asserts 0 B / 0 allocations at guarded sites via
  `ReportAllocs`; the CI gate was verified to fail with a single site unwrapped.
* Hardening: `go vet ./provider/ ./hub/` clean; `go test ./hub/ -run TestPake` passes.
* `go vet ./...` reports **0 findings** after #318; `gofmt -l .` prints nothing after #324,
  now enforced in CI.
* govulncheck: 0 vulnerabilities affecting called code (2 non-called advisories remain —
  otel via go-ethereum, x/crypto openpgp).
