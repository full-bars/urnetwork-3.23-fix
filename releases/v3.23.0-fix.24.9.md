## What's New

### `urnet-tools update -f` now stops, updates, and restarts the provider automatically

Previously `urnet-tools update` (even with `-f`) only swapped the binary on disk and printed "Restart the service when convenient." The running provider was never touched, so unattended or scripted updates left the service running the old binary.

Now, when `-f`/`--force` is passed:

1. The running provider is stopped (no confirmation prompt)
2. The binary is replaced
3. The service is restarted automatically

Plain `urnet-tools update` (without `-f`) keeps the original safe behavior — swap binary in place, leave the service running — so auto-update timers are unaffected.

### Hub dashboard shows earning status per node

The hub dashboard now includes an `earning` column (yes/no) for each node, making it easy to spot which nodes are actively carrying billable traffic at a glance.

### New `[profit]` log line: is billable traffic moving right now

A new `[profit] earning=yes|no clients=N rate=X` line ticks every 15 seconds, independent of the 5-minute `[health]` heartbeat — a fast, focused answer to "are we earning right now," distinct from the longer rolling `[earn]` windows. To keep quiet periods from flooding the log, `earning=no` only logs once every 5 minutes (plus immediately on the moment traffic stops, so the exact cutoff is visible).

### `[contract]` lines now show usage, not just acquisition

A new `[contract] closed acked=X allotted=Y util=Z% destination=W` line pairs with the existing `[contract] acquired` line, showing how much of a granted contract actually got used before it closed.

## Under the Hood

- `stop_systemd_units()` now distinguishes between a plain update and a force-update, so `update -f` falls through to the stop-and-restart path previously reserved for `reinstall`.
- `runProfitHeartbeat()` uses `ProxyHealthSnapshot()`, which is safe to call independently of the 5-minute health heartbeat's `ProxyHealthHeartbeat()` call and does not disturb its dead/recovered transition tracking.
