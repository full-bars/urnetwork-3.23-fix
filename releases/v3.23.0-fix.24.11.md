## What's New

### Important Log Buffer — high-value lines survive ramlog flood

New 1 MB `/dev/shm/urnetwork-important.log` secondary RAM buffer holding only high-value lines (`[profit]`, `[earn]`, `[health]`, `[outage]`, `client_id`, `instance_id`, `Permanently removed`, `[proxy][authrate]`) so the earnings/health status survives for hours even when the main 5 MB ramlog floods in ~84s.

```sh
urnet-tools logs -i
```

### URL-sourced proxy give-up backoff is now enforced at launch

The escalating backoff (PR #129) computed a 15m→24h retry delay and scheduled a one-shot reload, but nothing gated relaunch — `reload()` re-added every desired-but-not-running proxy immediately. Dead proxies were relaunched every few minutes regardless of their schedule (proxies reached give-up 9 within 44 minutes of uptime; 70% of log volume was churn). Now `reload()` skips addresses whose backoff window hasn't elapsed and reports `N deferred (backoff)`. Frees auth-rate-limiter slots for live proxies in addition to cutting churn.

### Version drift warning

`urnet-tools -v` now shows **Running version** and **Installed on disk** separately, with a drift warning if the running binary doesn't match what's on disk. Catches the case where `urnet-tools update` installed a new binary but the service hasn't restarted yet.

### Consolidated `[profit]` line

Health heartbeat now prints a single greppable line:

```
[profit] earning=yes reason=- clients=4 rate=2.1 MB/s proxies_up=12 serving=3 idle=9
[profit] earning=no  reason=idle clients=0 rate=0 B/s    proxies_up=12 serving=0 idle=12
```

Reason answers *why* when not earning: `warmup` | `no_proxies` | `idle` | `no_traffic`.

### `[c]ping err` log spam suppressed

Repeated `[c]ping err = Send sequence closed` messages during network outages now aggregate into one line per 5 minutes with `(N suppressed)` count. During the Detroit Hostodo transit outage this was producing 1,992+ identical lines over 2 days.

### Unified `logThrottle`

Four byte-identical rate-limiters collapsed into one reusable type. No behavioral change — makes future rate-limiter changes happen in one place.
