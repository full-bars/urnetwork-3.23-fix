# Next release

**Released:** 2026-11-18.

Previous release: [v3.23.0-fix.35.11](https://github.com/full-bars/urnetwork-3.23-fix/releases/tag/v3.23.0-fix.35.11).

This release redesigns the status command, adds proxy UDP relay coverage sweeps, introduces independent extender carrier controls, and brings the interactive top dashboard to Docker containers. It adds gossip visibility telemetry and removes an unused client window.

Update and restart the provider to use the new binary. Changing extender carrier settings restarts the active extender role.

Legend: **[redeploy]** needs the new provider, tool or container image. **[installer]** needs the updated installer or script. **[no redeploy]** covers documentation, CI and tests.

## Quick start

Install on Linux or macOS:

```sh
curl -fSsL https://install.fullbars.xyz | sh -s -- install
```

On FreeBSD, run the installer as a non-root service account with sudo:

```sh
fetch -qo - https://install.fullbars.xyz | sudo sh -s -- install
```

On OpenBSD, choose an existing non-root service account and replace `urnet` with its name:

```sh
ftp -o urnet-install.sh https://dl.fullbars.xyz/install-openbsd.sh
doas env SERVICE_USER_OVERRIDE=urnet sh urnet-install.sh install
```

Install on Windows in PowerShell. Windows Defender can flag the one-line form as a false positive, because the script downloads and unpacks a program. The safer way has two steps. Download the script, read it, then run it from disk:

```powershell
irm https://dl.fullbars.xyz/install-win.ps1 -OutFile "$env:TEMP\install-win.ps1"
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\install-win.ps1"
```

The Installation guide lists the Defender labels you may see and what to do about them.

Run the provider in Docker with a persistent volume and a single-use auth code from https://ur.io:

```sh
docker run -d --name urfix --pull always --restart unless-stopped --cap-add NET_ADMIN --cap-add NET_RAW --sysctl net.ipv4.ip_forward=1 -e AUTH=authcode -e AUTHCODE='YOUR_AUTH_CODE_HERE' -v urnetwork_data:/root/.urnetwork ghcr.io/full-bars/urnetwork-3.23-fix:latest
```

This release is the provider line. For miner setup, use the separate miner release and its instructions. This workflow does not publish a miner image.

## What's changed

### Added

- **`urnet-tools status` redesign. [redeploy]** Default output is a one-screen health summary showing version, time-boxed cached update availability, proxy pool counts, UDP coverage, extender state, unit health with SIGPIPE restart risk detection, and resource utilization. `--brief` reports warnings and failures with script exit codes (0 healthy, 1 warning, 2 broken, 3 unreachable). A healthy brief result prints nothing. `--json` continues to print the raw provider snapshot. `--json-summary` prints the summary as a stable schema document (`urnet-tools-status/1`) and omits `jwt_expires` when the provider has no token. `--live` (and `-l`) refreshes the summary in place with cursor home on terminals (`--interval` to adjust rate). `--detail` restores the platform status output.
- **Proxy UDP relay coverage. [redeploy]** Status, `top` and metrics report UDP relay coverage for online proxies. Background sweeps check paid and URL proxy sources. A check still running after 20 seconds is treated as unknown and allowed. Proxies are never rejected or graded down for lacking UDP. Only client UDP and QUIC flows are refused through a proxy proven not to relay (`no-relay` or `exit-mismatch`). Turning off the proxy sweep with `urnet-tools set udp-probe off` stops new sweeps at the next tick. A running sweep continues. The probe state file is written in the background at most every 2 seconds during normal operation. Shutdown can request an immediate flush. A remembered TCP exit is reused for at most six hours. The shared source line classifier rejects unbracketed IPv6 lines as `invalid_fields`.
- **Independent extender UDP carrier controls. [redeploy]** Choose the extender's UDP 443, UDP 4053 and UDP 53 carriers independently with `urnet-tools set extender-udp443|extender-udp4053|extender-udp53 on|off`. A setting change restarts the active extender role and persists across reboots. Status identifies disabled carriers.
- **Extender UDP port 53 telemetry. [redeploy]** Extender status reports the UDP port 53 state and bind failure reason (`bound`, `disabled`, `address_in_use`, `permission_denied`, `unknown`, `not_requested`, `pending`). The `urnet_extender_dns53_state` metric exposes the current state.
- **Gossip visibility diagnostics and `extender events`. [redeploy]** The provider records gossip dial metrics (`urnet_gossip_dial_attempts_total` and `urnet_gossip_dial_failures_total`), health transitions, and rate-limited anomaly dumps. `urnet-tools extender events` displays recent mesh events with filtering by `--since`, `--kind` and optional `--json` output.
- **Top display enhancements and Docker support. [redeploy]** The top display includes proxy heatmap dots, a configurable fading afterglow and a UDP coverage row. The container image includes the Go top dashboard. `urnet-docker top` checks for the dashboard, forwards terminal settings and stores preferences on a writable state mount.
- **Linux interface byte counters. [redeploy]** The `internal/nicstat` package reads cumulative interface receive and transmit bytes on Linux systems.

### Fixed

- **Proxy add accepts passwords containing an `@` sign. [redeploy]** SOCKS5 proxy passwords containing an `@` sign are parsed correctly when added from files or command arguments.
- **Status review and cache hardening. [redeploy]** The update check cache does not follow symbolic links. Status honors `--pid` and reports an unavailable or stopped extender cleanly. A healthy `--brief` produces no output.
- **Carrier rollback and gossip cap stability. [redeploy]** A failed control write restores the previous carrier configuration. Gossip cap pressure no longer hides a worse health state.
- **Backend failure state consistency. [redeploy]** The backend failure count and timestamp are published together as a single atomic snapshot.
- **Lossless prefix-bucket host blocker format and Telegram reflector test alignment. [redeploy]** The host blocker generator and decoder support the bucketed table layout with 257 bucket offsets and 5-byte tails, preserving all 48 fingerprint bits while reducing embedded table size.

### Changed

- **Removed the unused FP2 client window. [no redeploy]** No shipped binary used it. Exported Go APIs belonging to the FP2 client window were removed.
- **The CFAA sync commits generated tables directly to main. [no redeploy]** After format and decoder tests pass, the sync workflow commits generated blocklist tables straight to the main branch without opening a pull request.
- **Command help lists real flags and removes unused positional target placeholders. [redeploy]** `status`, `top`, `providers`, `start`, `stop`, `restart`, `update` and `logs` document accepted flags and arguments.

### Operator actions (needs-fleet-deploy)

- **New settings:** Operators can control optional extender carriers (`extender-udp443`, `extender-udp4053`, `extender-udp53`) and the proxy sweep (`udp-probe`) via `urnet-tools set`.
- **Restart behavior:** Changing an extender carrier setting restarts an active extender role.
- **Extender port 53 sysctl threshold:** The port 53 sysctl threshold is not selectable in setup yet. Binding port 53 on Linux still requires `cap_net_bind_service` or manual sysctl configuration.

## Known limits

- The port 53 sysctl threshold is not selectable in setup yet.
- The CFAA sync tables remain bounded by upstream format and test updates.
