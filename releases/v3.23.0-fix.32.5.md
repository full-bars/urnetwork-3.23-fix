# v3.23.0-fix.32.5

> [!NOTE]
> This release fixes HotSwap (zero-downtime update) staying silently unavailable after a node's installer was re-run — `urnet-tools reinstall`, or the documented `curl -fsSL https://install.fullbars.xyz | sh` one-liner — even long after `update` had already migrated that node's systemd unit for HotSwap. Every `update` now self-heals the unit, including a no-op "already on latest" run and the unattended weekly timer, so a stranded node converges on its own without waiting for a new release.

This is a focused hotfix. Its one fix makes `update` fully idempotent about the systemd unit's `Type=`, so it never again drifts back out of sync with what HotSwap needs.

## What's Changed

### Fixed

- **HotSwap silently stranded by a re-run installer** ([#682](https://github.com/full-bars/urnetwork-3.23-fix/pull/682)): the installer's `install_systemd_units()` always writes a unit with no `Type=` line (correctly defaulting to `simple` on a fresh install), with no awareness that `update` may have already migrated that unit to `Type=notify` for HotSwap. Previously, `update` only reconciled `Type=` right after installing a new binary — so a unit clobbered by a re-run of the installer stayed clobbered until a new release shipped, which is not a real convergence story since the installer is user-triggered, not release-tied. `update`'s no-op "already on `<tag>`" path now also reconciles the unit against the binary actually on disk, restarting the provider exactly once when a migration to `Type=notify` needs the running process to pick up `NOTIFY_SOCKET` (never on a demotion, which only protects a future start). No installer changes, no new CLI subcommand.

## Deploy Notes

1. **Update and restart — no config changes.** `urnet-tools update` picks up the fix. If your node's unit was previously stranded on `Type=simple` despite being current, this same `update` run will restart the provider once (briefly) to complete the fix; every `update` after that stays as fast and restart-free as today whenever nothing actually changed.
2. **No action needed for nodes that were never affected.** A node whose unit is already `Type=notify` sees no behavior change at all.
