## Changes

### Fixed

**100% CPU usage on idle providers** (PR [#191](https://github.com/full-bars/urnetwork-3.23-fix/pull/191))

Providers running v3.23.0-fix.24.27 through .32 have been consuming 100% CPU at all times, even with zero proxies and zero clients. No errors, no logs, just pegged cores.

The transport mode selection loop was waking itself up on every iteration. `setActiveMode()` fired a notification even when the mode hadn't changed, which closed the notify channel `run()` was using in its `select`. The loop spun at ~8,000 Hz per core, continuously cloning and sorting the available-modes map. Each notification also woke several worker goroutines that checked and re-parked on the same unchanged state.

Fix: `setActiveMode()` and `setModeAvailable()` now only fire the notification when the mode or availability actually changes. `run()` blocks normally, waiting for real mode transitions.
