# 🔧 v3.23.0-fix.25.14 — Critical Event Log + Crash Diagnostics

> **TL;DR** Disk-based critical event log (`~/.urnetwork/events.log`) that survives restarts — logs startup, signal receipt, exit, recovered panics, and fatal errors. RAM logs no longer wiped on restart (append mode). Recovered panics from any goroutine now logged to disk for post-mortem. Built on the same codebase running successfully for 9h+ on production nodes as `dev-debug`.

---

## 📝 Critical Event Log (`~/.urnetwork/events.log`)

New 1MB capped, auto-rotating file on disk (not RAM) that captures the most important events — so even if the provider exits silently or `/dev/shm` is wiped, there's a permanent forensic trail.

| Event | When |
|-------|------|
| `STARTUP` | Process starts — version, PID, hostname |
| `SIGNAL` | Context cancelled (SIGINT/SIGTERM/SIGQUIT) |
| `PROVIDER EXIT` | Clean shutdown with exit code |
| `PANIC` | Recovered panic in any goroutine |
| `FATAL` | `shmLogFatal` calls |

---

## 🔒 RAM Logs Survive Restarts

`shmLogPath` and `shmImportantLogPath` now open with `O_APPEND` instead of `O_TRUNC`. The previous run's logs are preserved (with a `--- provider restarted at ...` separator) so post-mortem analysis is possible even without the disk log.

---

## 🛡️ Panic Hook in `connect` Package

`connect.CritLogger` / `connect.LogCritical()` — any recovered panic in the core networking library (e.g. in proxy goroutines) now writes to `events.log` instead of being silently absorbed.

---

## 🔍 `GOTRACEBACK=crash` Ready

When set in the override.conf, Go runtime crashes produce full goroutine dumps to stderr. Useful for diagnosing hard crashes. Set via:

```
# ~/.config/systemd/user/urnetwork.service.d/override.conf
Environment="GOTRACEBACK=crash"
```
