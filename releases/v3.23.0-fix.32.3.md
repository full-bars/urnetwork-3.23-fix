# v3.23.0-fix.32.3

> [!NOTE]
> **Update your fleet as soon as you can.** This release fixes a memory leak that grows over time on every node and is confirmed live on the fleet right now. New connections protect themselves as soon as the binary runs. A restart of the provider reclaims the memory the leak already took. The fix ships in every provider started from this release onward. Use the usual `urnet-tools update` path, then restart.

This is a focused release. Its one real fix stops the provider from leaking pooled memory when an upstream connection fails. I also packed in a content-filtering blocklist refresh and a pass that makes the test suite deterministic.

## What's Changed

### Fixed

- **Message-pool buffer leak on connect failure** ([#677](https://github.com/full-bars/urnetwork-3.23-fix/pull/677)): when the provider tries to reach an upstream peer before sending a SYN plus ACK, and that connection attempt fails, the pooled packet was released without giving its byte buffer back to the pool. On a node where many dials fail, the pool quietly grew without bound. The dial-failure branch now returns the buffer exactly once, and a regression test locks that contract down. This brings the fork back in line with the upstream fix, which had never made it into the fork.

### Maintenance

- **Deterministic test suite** ([#675](https://github.com/full-bars/urnetwork-3.23-fix/pull/675)): the reload-trigger and health-registry tests no longer depend on timing or shared state, so they pass the same way every run.
- **Security blocklist sync** ([#676](https://github.com/full-bars/urnetwork-3.23-fix/pull/676)): refreshed the content-filtering blocklist from upstream.

## Deploy Notes

1. **Update then restart to reclaim leaked memory.** The fix stops new leaks the moment the binary runs. A restart returns the memory the old process held. Nothing else is required.
2. **No config or unit changes.** Your existing install works as-is.
