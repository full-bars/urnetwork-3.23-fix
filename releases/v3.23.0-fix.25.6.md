# 🔧 v3.23.0-fix.25.6 — Hub Dashboard Fixes

> **TL;DR** Four hub dashboard fixes from live testing — SSE debounce, sort persistence, composite index, and rate limiter removal. Renamed hub Docker tags to `hub-docker-v*` to clarify they're Docker-only, not binary releases. No provider behavior changes. No breaking changes.

---

## 🐛 Hub Dashboard (PR #240)

Four fixes from live testing:

- **SSE live-update debounced to 5s** — with many nodes reporting, the SSE EventSource was flooding `refreshDashboard()` dozens of times per second, overwriting the DOM mid-interaction and breaking sort.
- **Sort state survives table rebuilds** — `refreshDashboard()` now re-applies the active column sort after every refresh, so sorting by Bill RX (or any column) sticks.
- **Composite index on `proxy_node_hourly(hour, proxy_id)`** — fixes slow "all nodes" leaderboard queries at all window sizes. The planner was picking the wrong single-column index.
- **Rate limiter removed** — custom addition that keyed off `r.RemoteAddr`. Behind Caddy every client collapses to `127.0.0.1`, making the 60 req/min limit a shared global budget shared by fleet heartbeats + dashboard. `/api/heartbeat` was not exempt — fleet heartbeats were getting 429'd, and the dashboard showed "rate limit exceeded" errors. Caddy handles rate limiting at the proxy layer.

## 🏷️ CI

Renamed `hub-v*` Docker-only tags to `hub-docker-v*` — the old naming made it look like a binary release scheme; it's only a Docker image tag.

**None.** This is a drop-in upgrade. No configuration changes required.
