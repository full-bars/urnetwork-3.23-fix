# v3.23.0-fix.35.2

**Released:** DATE TO BE SET AT TAG TIME. **Previous release:** `v3.23.0-fix.35.1`.

This covers everything merged since `v3.23.0-fix.35.1` (PRs 996 to 1021). The one-line-per-change list is the Unreleased section of [CHANGELOG.md](../CHANGELOG.md). The version number in this file name is a placeholder chosen as the next patch after the last tag; rename it if the release is cut under another tag.

This window is mostly installer verification, FreeBSD and macOS correctness, and Docker startup safety. The largest operator-visible changes are that the installers now refuse to install a provider they cannot verify, a FreeBSD host installs with nothing beyond the base system, and every macOS `urnet-tools update` can finish again.

> [!NOTE]
> **The extender is a work in progress.** We are still working on getting it to activate, and as of this release it is not reliable.
> If you turn it on, expect errors in your logs about activation and about carriers not answering. They do not affect the rest of the
> provider.
>
> **Ports, if you want to try it.** `tcp 443` is required and must be free: the extender binds it, so nothing else on the host may hold
> it, a web server included. `udp 443` and `udp 4053` (and `udp 53` on the sn miner) are the optional carriers. They are meant to be
> optional, but today a udp carrier that fails can still refuse the whole activation, so treat them as required if you intend to try.
>
> **If you would rather not open ports, that is a supported choice.** The provider runs and earns normally with none of them open. You
> simply will not have a working extender.

Legend: **[redeploy]** needs the built artifact redeployed. **[installer]** needs the installer or unit refresh. **[no redeploy]** docs, CI or tests only.

## Install and update

- **The installers verify the provider download and keep the live binary when a step fails** **[installer]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1011>). Both the Linux and FreeBSD installers fetch the release metadata first and stop with `refusing to install` when it cannot be fetched or does not list the asset. FreeBSD checks the provider tarball's SHA-256 before extracting and reads the digest without `jq` or `python3`; Linux still needs one of them and warns, then continues, when a release publishes no digest for the asset. A failed backup refuses the replacement instead of overwriting the live binary.
- **The FreeBSD installer refuses an unverifiable `urnet-tools` and a damaged install tree** **[installer]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1010>). The shell fallback is gone; a symlink inside the install tree stops the install with `symlink in install tree; refusing to repair`.
- **A FreeBSD host installs without curl** **[installer]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1002>). The dispatcher and installer try `curl`, then `fetch`, then `wget`.
- **Every macOS update staged the Linux binary and then refused it** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1018>). `urnet-tools update` on a Mac now picks the `darwin/<arch>/provider` entry of the universal tarball. Unit-tested only; not run on a Mac.
- **A FreeBSD update keeps the root-owned tree root-owned** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1019>). Root's auto-update cron line runs the staged copy under `/usr/local/libexec/urnetwork-provider/bin` and logs to `/var/log/urnetwork/auto-update.log`. The rc script's fallback process scan covers only the service user's processes, and the installer's state-directory chown no longer runs in the launch directory.
- **A FreeBSD restart keeps the service log, and a stopped libexec install is found again** **[installer]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1007>, <https://github.com/full-bars/urnetwork-3.23-fix/pull/1005>, <https://github.com/full-bars/urnetwork-3.23-fix/pull/1009>). Discovery also requires an execute permission the invoking user holds.

## Docker

- **Docker startup keeps a valid proxy configuration and redacts echoed credentials** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1014>). A container started without `/app/proxy.txt` keeps the proxies saved on its volume, a mounted file is imported through a staging directory, and `DEBUG=true` login output is redacted. A nightly container also reuses a valid stored JWT and imports `proxy.txt` after the binary has been downloaded.
- **Every image reports a dated `app_version`** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/999>). `:main` and `:sha` images no longer send a raw tag to the backend.

## Provider

- **The provider's proxy state is written under one lock, in one order** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1013>). A concurrent `proxy remove` or reload can no longer be overwritten by an older snapshot, and shutdown no longer waits out a queued reload.
- **The probe asks every address before it convicts a route** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/996>). A v6 target is now encoded as a v6 destination, and a round cut short by the limiter carries no verdict.
- **The URL fetch failure reason, the RAM log trim and an extender source that asks again** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/997>, <https://github.com/full-bars/urnetwork-3.23-fix/pull/1003>). See the changelog for the mechanism of each.
- **The contract log line separates the verb from the proxy** **[redeploy]**. `[contract] acquired | proxy[3] (203.0.113.22:1081) ...`; a script that matched the old `acquired proxy[` text needs updating. Documented in `LOG_REFERENCE.md`.

## Command line

- **`--i-am-on-my-own-workstation` is removed from `urnet-tools wallet`** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1017>). Passing it fails with a message that says it was removed, so an old script stops instead of being silently accepted.
- **The paste prompt names the key that ends input on Windows** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1006>).

## Security data

- **The CFAA and IP blocker tables are refreshed** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1000>, <https://github.com/full-bars/urnetwork-3.23-fix/pull/1004>, <https://github.com/full-bars/urnetwork-3.23-fix/pull/1008>). The CFAA table has 48,764 IPv4 and 539 IPv6 ranges; the IP blocker retains 164,781 blocked-host records.

## Deploy notes

- **Provider nodes need a redeploy** for the provider, CLI and data changes above. Docker nodes need the new image.
- **FreeBSD and Linux nodes pick up the installer changes** the next time the installer runs. No unit change and no new required setting.
- **Linux installs still need `jq` or `python3`** to read the release metadata; the installer now stops without them. FreeBSD does not.
- **Scripts that parse the `[contract]` log line** need the `|` separator.

## Caveats

- None of the FreeBSD changes has been run through a recorded end-to-end install on a physical FreeBSD host. The `FreeBSD verification` workflow ran the execute-permission test as `nobody` on a FreeBSD 14.5 VM.
- The macOS update fix is unit-tested only.
- The Docker scripts were verified by reading and by their shell harnesses, not by a container run for this note.
