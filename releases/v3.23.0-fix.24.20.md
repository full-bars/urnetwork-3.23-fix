## Highlights

### 📊 Hub Dashboard — Complete Overhaul

The hub dashboard has been rewritten across two phases.

**Performance (#155):** Initial page load drops from 8–12 MB to ~50 KB. Auto-refresh bandwidth drops from ~1 GB/hour to ~5 MB/hour.

- Gzip middleware on all responses
- 45,000 inline proxy rows removed — proxies lazy-loaded on demand via `/api/nodes/<id>/proxies`
- Auto-refresh switched from full-page HTML reload to lightweight `/api/nodes` JSON poll with in-place DOM updates
- Single-pass fleet summary (was triple-traversal); N+1 startup query eliminated (was 1+N, now 2)
- Stale node auto-eviction after 15 minutes; orphaned DB rows pruned daily
- Per-IP rate limiting: 60 req/min (exempt: `/api/report`)

> [!NOTE]
> **Breaking change:** `/api/nodes` no longer includes full proxy lists. Proxies available at `/api/nodes/<id>/proxies`. `/api/history` caps `hours` at 168 and now includes `node_id` in unfiltered responses.

**UI (#156):** Visual redesign, no server-side changes.

- Five summary cards: Total Proxies, Healthy, Degraded, Earning, Active Clients with live percentages
- Fleet sparkline (uPlot) showing aggregate RX/TX for the last 24 hours
- Tab navigation: Nodes / History
- Filter bar: text search + status dropdown with real-time filtering
- Slide-out drawer for per-node proxy detail, fetched on demand
- History tab with full uPlot time series chart, 24h/3d/7d range buttons, per-node filter

### 🔬 Dual-Stage Proxy Probe (#152)

URL-sourced proxies now pass a two-stage gate before admission:

| Stage | Timeout | Tests |
|-------|---------|-------|
| 1 | 3s | TCP connect + SOCKS5 handshake |
| 2 | 5s | SOCKS5 CONNECT to `api.bringyour.com:443` through the proxy |

Proxies that pass only stage 1 are cached with `ProbeOK=false` and re-probed every 5 minutes by a background reaper. After 3 consecutive failures they move to a 24-hour blacklist. The blacklist pruner runs every 30 minutes to give expired entries a second chance.

100ms random stagger per probe and a single cached API destination IP prevent thundering herd under concurrent probes.

### 🛠️ New `urnet-tools` Commands

**`proxy summary`** (#151) — fleet overview at a glance:
```sh
urnet-tools proxy summary
```
Shows total/up/connecting/degraded/dead counts, source breakdown, URL cache and blacklist counts, provider start time.

**`report`** (#154) — view or set the hub report URL without editing override.conf:
```sh
urnet-tools report                      # show current setting
urnet-tools report http://hub:8080      # set (takes effect on next restart)
urnet-tools report off                  # remove
```

---

### 🔧 Override.conf Reliability (#153)

All 6 toggle functions (`ramlogs`, `lowmode`, `ecomode`, `automode`, `turbomode`, `do_optimize`) now use two shared idempotent helpers instead of 4 different ad-hoc sed/printf patterns. Running a toggle twice no longer produces duplicate `Environment=` lines.

> [!IMPORTANT]
> **`toggle_lowmode off` regression fixed:** the previous implementation called `rm -rf` on the entire override directory, silently wiping unrelated settings (RAMLOGS, REPORT_URL, etc.). It now removes only the lowmode env vars.
