## 🗂️ What's New

> [!NOTE]
> **Deferred Features:** Upstream's *gopacket removal* (PR #263) and *memory budget enforcement* (PR #264) remain deferred from 26.1 — still pending a stability re-review before merge.

### 🌐 Proxy Management

**Self-Healing Proxy Resource Management** — PR #259
Adds two layers of protection against the dead-proxy-accumulation failure mode that caused a production meltdown (thousands of dead desired proxies → goroutine pile-up → days of 100% CPU):
- **Always-on correctness fixes**, independent of any toggle: `proxy_url_max` now defaults to 500 instead of unlimited; cleanup defaults to scope `"url"` with a 6h base interval (was `"none"`/24h) and an uptime guard so warming proxies are never mass-evicted at startup; dead URL proxies are given up on after ~4h instead of ~6 days; a new reaper pass re-probes stale `ProbeOK=true` entries after 3h so proxies that go dead after passing their initial probe don't silently accumulate; the URL cache now logs when it exceeds its configured cap.
- **An opt-in pressure system**, `URNETWORK_SELF_HEAL=1` / `urnet-tools self-heal on`, **default OFF**: a monitor samples PSI (`/proc/pressure/memory`, `/proc/pressure/cpu`), memory availability, loadavg, and goroutine/heap self-signals every 30s into a smoothed [0,1] pressure score, then proportionally stretches fetch/probe pacing and shrinks cleanup cadence under load — replacing the old binary load-threshold gate. An AIMD controller grows the working proxy pool while pressure is calm and sheds the worst-first (dead → degraded → healthy by ascending traffic) under sustained pressure, always through the normal cache-removal path with a 1h re-admission backoff — shed proxies are never blacklisted and recover automatically once pressure drops.
- With self-heal off (the default), every actuator behaves exactly as it did before this system existed — only the always-on fixes above apply.

> [!TIP]
> **Expect a one-time reaper burst after upgrading.** The new stale-reprobe pass checks every previously-trusted (`ProbeOK=true`) proxy in your existing cache on its first cleanup cycle post-upgrade, something the reaper never did before. On a large existing `--proxy_url` cache this shows up as a brief spike of reaper log lines — it's expected, self-limiting, and doesn't block reloads or fetches. Steady-state ticks afterward are naturally staggered and much quieter.

**ProbeOK Lost on Cache Merge** — PR #274
Fixed `mergeProxyURLEntries` discarding the dual-stage probe's API-reachability result before caching, which defaulted every newly-merged entry's `ProbeOK` to `false` — including proxies that had just passed their API probe. This let the background reaper blacklist proven-live proxies.

**Hub Off/Set Required a Restart** — PR #276
`urnet-tools hub link`/`unlink` already applied changes live via the `~/.urnetwork/report_url` override file the provider polls every report tick; `hub set`/`off` instead wrote to a systemd `Environment=` drop-in that's only read once at process start, forcing an unnecessary restart. All four commands now go through the same override file, and `resolveReportURL` gained an explicit `"off"` sentinel so disabling reporting can't be confused with "no override configured" (which intentionally falls back to any startup env var).

### 🔒 Security

**go-ethereum Dependency Bump** — PR #275
Bumped `github.com/ethereum/go-ethereum` v1.16.7 → v1.17.4, clearing 5 Dependabot alerts. It's a transitive dependency of `github.com/urfoundation/sn` (subnet integration prep, see below) — only client-side packages (`ethclient`, `accounts/abi`, `common`, `core/types`, `crypto`, `rpc`) are used, never the `p2p` package the advisories affect, so exploitability was already effectively zero; this closes the alerts regardless.

### 🛠️ CI/CD & Operations

**Subnet Integration Prep (Phases 1–2)** — PR #272
Pins the `urfoundation/sn` (Bittensor subnet) crypto/chain packages and backports the upstream `Sn*Sync` API client methods (`VerifyKeysSync`, `SnSetWalletSync`, `SnPoolClaimSync`, `SnEpochSync`). Inert in this release — nothing calls these yet; CLI wiring is a separate, stacked PR (#273) not included here.

**Installer Links** — PR #271
Replaced legacy `raw.githubusercontent.com` installer links in `AI.md`/`docs/Installation.md` with the `dl.fullbars.xyz` shortcuts across all supported OS targets.

## ⚠️ Breaking Changes

**(None. Drop-in upgrade.)** Self-heal pressure actuation is opt-in and off by default; the always-on proxy-management defaults changed (see PR #259 above) but are strictly more conservative than before.
