## What's New in v3.23.0-fix.17

### Installing / Updating

**Binary (bare metal / VM):**
```sh
curl -fSsL https://raw.githubusercontent.com/full-bars/urnetwork-3.23-fix/refs/heads/main/scripts/Provider_Install_Linux.sh | sh -s -- install
```

**Updating an existing install:**
```sh
urnet-tools update -t v3.23.0-fix.17
```

**Docker:**
```sh
docker pull ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.17
```
```sh
docker run -d \
  --name=urfix \
  --restart=unless-stopped \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  -e URNETWORK_AUTH_CODE=YOUR_AUTH_CODE \
  -e HOST_HOSTNAME=$(hostname) \
  -v urfix_config:/root/.urnetwork \
  ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.17
```

**Useful commands after upgrading:**

> [!TIP]
> Run these from your host to monitor the provider without entering the container.

```sh
# Live logs
urnet-tools logs                                              # Binary
docker logs -f urfix                                          # Docker (RAMLOGS off)
docker exec urfix tail -f /dev/shm/urnetwork.log             # Docker (RAMLOGS on)

# Proxy health (dead/degraded list + live event stream)
urnet-tools proxy health                                      # Binary
docker exec -it urfix proxy-health                            # Docker

# Proxy health state file (snapshot, no streaming)
cat ~/.urnetwork/proxy_health.state                           # Binary
docker exec urfix cat /root/.urnetwork/proxy_health.state     # Docker

# Proxy health event log
tail -f ~/.urnetwork/proxy_health.log                         # Binary
docker exec urfix tail -f /root/.urnetwork/proxy_health.log   # Docker

# Proxy traffic (bandwidth + active clients per proxy)
urnet-tools proxy traffic                                     # Binary
docker exec urfix cat /root/.urnetwork/proxy_traffic.state    # Docker
```

### 🔄 Proxy Hot-Reload

> [!IMPORTANT]
> Proxies take 8-12 hours to fully warm up on the platform. Previously, removing a single dead proxy required a full restart, wiping the warm state of every live proxy on the machine. That is no longer the case.

The provider can now add and remove proxies from a running instance without a restart. Changes to your proxy list are applied live: dead proxies are cancelled and drained, new proxies are started with a staggered delay to avoid a burst of simultaneous connection attempts at the API.

Proxy slot assignments (`proxy[N]`) are now **stable across reloads.** A proxy's slot number is assigned once and persisted to `proxy.state`. Re-adding a proxy that was previously removed will restore its original slot number.

**Reload from your proxy config:**
```sh
urnet-tools proxy refresh
```
Shows a diff of what will be added and removed, then asks for confirmation before applying.

**Remove dead or inactive proxies interactively:**
```sh
urnet-tools proxy remove-dead
```
Prompts separately for dead proxies (never authenticated) and inactive proxies (long offline), so you can choose what to remove independently.

> [!TIP]
> Triggering a reload that results in an empty proxy list will exit the provider cleanly. This can be used as a controlled shutdown without sending SIGTERM.

### 📋 `urnet-tools logs`

Streams live provider logs to stdout. On RAMLOGS-enabled installs (lowmem, eco, or slow-disk auto-detected) it tails `/dev/shm/urnetwork.log`; otherwise it follows `journald`.

```sh
urnet-tools logs
```

For Docker, the right command depends on whether RAMLOGS is enabled:
```sh
docker logs -f urfix                                # RAMLOGS off (logs go to stdout)
docker exec urfix tail -f /dev/shm/urnetwork.log   # RAMLOGS on (logs go to RAM disk)
```

> [!NOTE]
> RAMLOGS is automatically enabled on lowmem/eco installs and on any machine where the disk speed audit determines the disk is too slow. When RAMLOGS is on, `docker logs` will show nothing — use the `tail` command above instead.

### Bug Fix: Clients Counter

> [!NOTE]
> This fixes a regression from the v3.23.0-fix.17-rc.1 pre-release. The `CLIENTS` column in `proxy_traffic.state` and the `clients=N` field in `[net][s]select` logs were always showing `0` because the clients counter was not being copied into bandwidth snapshots. This is now corrected.

### Active NAT Session Tracking

The `CLIENTS` counter in the traffic report (and the `clients=N` field in `[net][s]select` logs) shows the number of active NAT sessions currently multiplexed through each proxy:

```
[net][s]select: proxy[3] (172.98.64.194:1081) [fragment] success=6086 error=4 clients=7
[net][s]select: proxy[0] (185.220.101.47:1081) [normal] success=2221 error=11 clients=3
[net][s]select: proxy[4] (89.187.162.125:1081) [fragment] success=841 error=0 clients=2
[net][s]select: proxy[2] (45.134.212.68:1081) [normal] success=392 error=0 clients=0
```

> [!TIP]
> This makes it immediately obvious which proxies are under load vs. idle, and helps identify proxies that are authenticated but not carrying client traffic.

### 🔧 `[net][s]select` Error Suppression

Transient proxy connection errors were previously logged on every failure, creating significant log spam on busy or partially-degraded deployments. These errors are now rate-limited to at most one per minute, keeping logs readable without losing signal.

### 🛡️ E2E Post-Quantum Encryption: Foundation

> [!NOTE]
> Encryption is **disabled by default** in this release. No behavior change for existing deployments.

This release ports [urnetwork/connect#183](https://github.com/urnetwork/connect/pull/183) into the fork. The upstream PR introduces end-to-end encryption between provider and client using TLS 1.3 with the `X25519MLKEM768` post-quantum hybrid KEM (ML-KEM / Kyber), per-peer identity verification via Ed25519 signatures, and AES-256-GCM AEAD. It also hardens contract reliability: `CloseContract` now uses confirmed delivery instead of fire-and-forget, which previously allowed dropped closes to permanently strand escrow on the server.

The full implementation is present and building in this fork but inactive (`Encrypt: false`, `TlsTimeout: -1`). It will be enabled in a future release following the upstream rollout plan.
