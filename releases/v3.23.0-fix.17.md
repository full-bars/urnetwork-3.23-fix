## What's New in v3.23.0-fix.17

### Proxy Hot-Reload

> [!IMPORTANT]
> Proxies take 8–12 hours to fully warm up on the platform. Previously, removing a single dead proxy required a full restart — wiping the warm state of every live proxy on the machine. That's over.

The provider can now add and remove proxies from a running instance without a restart. Changes to your proxy list are applied live: dead proxies are cancelled and drained, new proxies are started with a staggered delay to avoid a burst of simultaneous connection attempts.

Proxy slot assignments (`proxy[N]`) are now **stable across reloads** — a proxy's slot number is assigned once and persisted to `proxy.state`. Re-adding a proxy that was removed will restore its original slot number.

**Triggering a reload:**

```sh
urnet-tools proxy refresh        # reload proxy list from config, confirm before applying
urnet-tools proxy remove-dead    # interactively remove dead and/or inactive proxies
```

`proxy refresh` shows a diff of what will be added and removed and asks for confirmation before applying. `proxy remove-dead` prompts separately for dead proxies and inactive proxies so you can handle each category independently.

> [!TIP]
> A reload with an empty resulting proxy list will exit the provider cleanly — useful for a controlled shutdown without a SIGTERM.

### `provider logs` Command

Stream or dump the provider's RAMLOGS output directly:

```sh
urnet-tools logs          # dump current RAMLOGS buffer to stdout
urnet-tools logs -f       # tail RAMLOGS in real time (handles log rotation automatically)
```

### Bug Fix: Clients Counter

> [!NOTE]
> This fixes a regression introduced in the v3.23.0-fix.17-rc.1 pre-release. The `CLIENTS` column in `proxy_traffic.state` and the `clients=N` field in `[net][s]select` logs were always showing `0` due to the clients counter not being copied into bandwidth snapshots. This is now corrected.

### Per-Proxy Bandwidth Tracking

The provider tracks cumulative bandwidth per proxy — bytes sent and received, broken down into billable (user-attributed) vs. total (including protocol overhead). Persisted to `proxy_traffic.state` on the config volume and readable at any time:

```sh
urnet-tools proxy traffic          # Linux
docker exec urfix cat /root/.urnetwork/proxy_traffic.state  # Docker
```

Results are sorted by billable traffic descending:

```
========================================================================

 Updated: 2026-06-03T08:30:24Z
========================================================================
+-------------+--------------------------+---------+-------------------+-------------------+
| PROXY ID    | IP ADDRESS               | CLIENTS | BILLABLE (TX/RX)  | TOTAL (TX/RX)     |

| proxy[3]    | 172.98.64.194:1081       | 7       | 310 MB / 204 MB   | 312 MB / 206 MB   |
| proxy[7]    | 45.142.212.75:1081       | 4       | 198 MB / 143 MB   | 200 MB / 145 MB   |
| proxy[0]    | 185.220.101.47:1081      | 3       | 142 MB / 98 MB    | 144 MB / 100 MB   |
+-------------+--------------------------+---------+-------------------+-------------------+
```

### Active NAT Session Tracking

The `[net][s]select` log now includes a `clients=N` counter per proxy line showing how many active NAT sessions are multiplexed through that proxy:

```
[net][s]select: proxy[3] (172.98.64.194:1081) [fragment] success=6086 error=4 clients=7
[net][s]select: proxy[0] (185.220.101.47:1081) [normal] success=2221 error=11 clients=3
[net][s]select: proxy[2] (45.134.212.68:1081) [normal] success=392 error=0 clients=0
```

---

### Proxy Health Reports

`urnet-tools proxy health` / `proxy-health` (Docker) shows dead and degraded proxies and streams live recovery and loss events. Full dead/degraded lists and transition history are persisted to `proxy_health.state` and `proxy_health.log` on the config volume (survives RAMLOGS).

---

### `[net][s]select` Error Suppression

Transient proxy connection errors were previously logged on every failure, creating significant log spam on busy or partially-degraded deployments. These errors are now rate-limited to at most one per minute per error type, keeping logs readable without losing signal.

---

### E2E Post-Quantum Encryption — Foundation

> [!NOTE]
> Encryption is **disabled by default** in this release. No action required and no behavior change for existing deployments.

This release includes the upstream E2E post-quantum encryption layer (PR #183) — TLS 1.3 with `X25519MLKEM768` hybrid KEM, per-peer identity verification via Ed25519 signatures, and AES-256-GCM AEAD. The implementation is present and building but inactive (`Encrypt: false`). It will be enabled in a future release following the upstream rollout plan.

---

### Installer Improvements

- `urnet-tools` now accepts a global `-t <tag>` flag for pinning to a specific version on any subcommand
- Install URL is configurable via `URNETWORK_INSTALL_URL` for self-hosted mirrors
- `install` and `auth-provide` prefer the locally running script over fetching from GitHub
