# Release v3.23.0-fix.18.2

**Date:** 2026-06-08  
**Type:** Critical Hotfix  
**Severity:** High

## Critical Fix: Proxy Authentication Failure Causing Provider Crash

> [!WARNING]
> **Critical Issue Resolved:** A single proxy failing authentication during startup would call `os.Exit(1)` and **crash the entire provider**. On large deployments with thousands of proxies, this was catastrophic—any proxy hitting API timeouts during startup could kill the whole host.

### What Was Fixed

**Before:** When a proxy failed authentication 10 times, it called `os.Exit(1)`, killing the entire provider process mid-startup.

**After:** Failed proxies now exit gracefully, allowing the provider to stay up while the failed proxy waits for the hourly pulse retry mechanism.

### Changes in This Release

1. **Graceful proxy auth failure handling** (provider/main.go)
   - Replaced fatal `os.Exit(1)` with graceful goroutine return
   - Failed proxy no longer crashes entire provider
   - Other proxies continue starting normally
   - Provider remains operational and earning

2. **Enhanced logging with retry counters**
   - Added `[proxy][init]` prefix for all proxy auth messages
   - Shows proxy index and address in every message
   - Retry counter shows attempt number (e.g., `attempt 3/10`)
   - Enables debugging which proxy is failing and why

### Example Log Messages

**Before (cryptic, no context):**
```
init proxy auth failed: Timeout.. Will retry in 7.80s
```

**After (clear, actionable):**
```
[proxy][init] proxy[3633] (45.3.62.167:1081) auth failed (attempt 3/10): Timeout. Will retry in 7.80s
[proxy][init] proxy[3633] (45.3.62.167:1081) authentication failed after retries: Timeout (proxy will remain offline, retry on next hourly pulse)
```

### Impact

- **Large deployments:** Provider stays up even during API load/timeouts
- **Operations:** Clear logs show which specific proxies are failing and why
- **Reliability:** Failed proxies integrated into existing hourly pulse retry mechanism
- **No breaking changes:** Full backward compatibility

## Deployment

Deploy immediately to all production servers to prevent provider crashes during high API load.
