# v3.23.0-fix.35.5

**Released:** 2026-11-08.

Previous release: [v3.23.0-fix.35.4](https://github.com/full-bars/urnetwork-3.23-fix/releases/tag/v3.23.0-fix.35.4).

The extender role now starts by default and activates with the platform. I added `urnet-tools extender setup` to prepare a host for it, and I made that command ask before it changes anything. I also fixed receive-loop panics that a peer could trigger, and I fixed log following across trims.

Legend: **[redeploy]** needs the new provider, tool or container image. **[installer]** needs the updated installer or script. **[no redeploy]** covers documentation, CI and tests.

## Quick start

Install on Linux or macOS:

```sh
curl -fSsL https://install.fullbars.xyz | sh -s -- install
```

On FreeBSD, run the installer as a non-root service account with sudo:

```sh
fetch -qo - https://install.fullbars.xyz | sudo sh -s -- install
```

On Windows, use PowerShell:

```powershell
irm https://dl.fullbars.xyz/install-win.ps1 | iex
```

Run the provider in Docker with a persistent volume and a single-use auth code from https://ur.io:

```sh
docker run -d --name urfix --pull always --restart unless-stopped --cap-add NET_ADMIN --cap-add NET_RAW --sysctl net.ipv4.ip_forward=1 -e AUTH=authcode -e AUTHCODE='YOUR_AUTH_CODE_HERE' -v urnetwork_data:/root/.urnetwork ghcr.io/full-bars/urnetwork-3.23-fix:latest
```

This release is the provider line. For miner setup, use the separate miner release and its instructions; this workflow does not publish a miner image.

## What changed

### Extender

- **The extender role runs by default and activates with the platform** **[redeploy]** ([#1054](https://github.com/full-bars/urnetwork-3.23-fix/pull/1054)). A manager starts and stops the role to match the saved setting. `urnet-tools extender on` and `off` change it (`enable` and `disable` also work), and `off` is a saved value. Activation uses the live client token, resumes its pacing after a restart, and waits for the platform root keys before it trusts stored records. An unreachable TCP 443 probe holds the retry for the 12-hour renewal interval. Earlier releases did not activate the role.
- **The extender accepts the platform's own hosts by default** **[redeploy]**. The platform proves an extender by forwarding a request to its own API host, and the empty allow list refused it. The platform space is now allowed. A public-suffix space is limited to the API host.
- **TCP 443 binds first** **[redeploy]**. Nothing else opens while it is taken, and the log names the holder when `ss` can find it. The DNS carrier tries UDP 53 by default. UDP 53 is optional, and you manage its firewall rule.
- **Status shows each carrier and why the platform left one out** **[redeploy]**. `urnet-tools extender`, `status` and `top` show the bound and accepted carriers, the record expiry and the state of each address family. Every extender log line starts with the bridge mark, so `grep` finds all of them. Requests count only after authorization and admission.
- **Restarts and errors are tighter** **[redeploy]**. A role whose supervisor exits is restarted. A failing start is logged once. Root key errors no longer log response bodies, and an invalid `URNETWORK_EXTENDER` value warns once. `top` resets its extender state when you switch providers, and commands for another user's provider re-run under sudo.

### Extender setup

- **`urnet-tools extender setup` is new** **[redeploy]** ([#1054](https://github.com/full-bars/urnetwork-3.23-fix/pull/1054)). It checks whether TCP 443 is occupied, whether the provider binary may bind it, and whether the host firewall allows the carrier ports. It prints every command, asks before it changes anything, and then checks a live bind as the provider user.
- **Only an explicit `--yes` (`-y`) or `--force` approves a non-interactive run.** An elevated rerun shows its own plan and asks again, and a manual rerun keeps your target and flags. When setup cannot see which process holds port 443, it rechecks as root and no longer reports "already configured".
- **firewalld and capabilities are handled conservatively.** Setup plans the runtime and permanent firewalld rules separately and never reloads. If it cannot read the rule state, it stops with the cause. ufw plans only the missing rules. Setup keeps the existing file capabilities when it adds the bind capability.
- **FreeBSD setup is print-only and untested.** It prints the temporary `sysctl` commands and their undo and changes nothing. That setting removes privileged-port protection for all local users, and the text says so. Regular providing on FreeBSD is unaffected. FreeBSD port checks now use `sockstat`.
- **Port checks match the exact local port.** A connected UDP socket or a port such as 4430 no longer counts as port 443.
- **The installer prints one notice and asks nothing** **[installer]**. It says whether TCP 443 is free or what holds it, and it never fails the install.

### Provider and logs

- **Receive-loop panics a peer could trigger are fixed** **[redeploy]** ([#1052](https://github.com/full-bars/urnetwork-3.23-fix/pull/1052)). A frame with no path, and a pack with the wrong lane head or a stale index, each stopped the client for every peer. They now return an error, drop, or heal. Regression tests reproduce each panic on the old code. Mismatch diagnostics are bounded.
- **Log following survives a trim** **[redeploy]** ([#1053](https://github.com/full-bars/urnetwork-3.23-fix/pull/1053)). The follower tracks the file path, so a trimmed RAM log no longer silences the stream, and a split line no longer prints twice.
- **`urnet-tools diag` help states the real free-space check** **[redeploy]** ([#1055](https://github.com/full-bars/urnetwork-3.23-fix/pull/1055)). It checks a fixed 512 MiB on the diag directory's filesystem. A negative availability count no longer lets a capture start on a full disk.

### Documentation

- **The extender guide, log reference and README are updated** **[no redeploy]**. The log reference gains an extender section. The README says the default Docker bridge activates IPv4 only and adds Compose examples. SN25 figures were refreshed.

## Known limitations

- The Docker RAM log follower can still replay retained lines after a trim.
- A hot-swap candidate can race the old provider while it still holds a listening socket.
- FreeBSD extender setup has not been tested on a FreeBSD host.
