# v3.23.0-fix.35.5

**Released:** 2026-11-07.

Previous release: [v3.23.0-fix.35.4](https://github.com/full-bars/urnetwork-3.23-fix/releases/tag/v3.23.0-fix.35.4).

The extender role now starts by default and activates with the platform. I added `urnet-tools extender setup` to prepare a host for it, and I made that command ask before it changes anything. I also fixed receive-loop panics that a peer could trigger, and I fixed log following across trims.

Legend: **[redeploy]** needs the new provider, tool or container image. **[installer]** needs the updated installer or script. **[no redeploy]** covers documentation, CI and tests.

## Quick start

Install on Linux or macOS:

```sh
curl -fSsL https://install.fullbars.xyz | sh -s -- install
```

On FreeBSD, run the installer as a non-root service account with sudo:

```sh
fetch -qo - https://install.fullbars.xyz | sudo sh -s -- install
```

On Windows, use PowerShell:

```powershell
irm https://dl.fullbars.xyz/install-win.ps1 | iex
```

Run the provider in Docker with a persistent volume and a single-use auth code from https://ur.io:

```sh
docker run -d --name urfix --pull always --restart unless-stopped --cap-add NET_ADMIN --cap-add NET_RAW --sysctl net.ipv4.ip_forward=1 -e AUTH=authcode -e AUTHCODE='YOUR_AUTH_CODE_HERE' -v urnetwork_data:/root/.urnetwork ghcr.io/full-bars/urnetwork-3.23-fix:latest
```

This release is the provider line. For miner setup, use the separate miner release and its instructions; this workflow does not publish a miner image.

## What changed

### Extender

- **The extender role runs by default** **[redeploy]** ([#1054](https://github.com/full-bars/urnetwork-3.23-fix/pull/1054)). A manager starts and stops the role to match the saved setting and logs the reason for every change. Turn it off or on with `urnet-tools extender off` or `urnet-tools extender on`; `disable` and `enable` also work. `off` is a saved value, so a cleared setting turns the role back on. Earlier releases did not activate the role for clients.
- **The role activates with the platform and keeps its state across restarts** **[redeploy]**. The activation loop posts with the live client token and persists when each address family may post next, so a restart resumes the cadence instead of posting every family at once. Stored records stay unverified until the platform root keys load, and the root keys come from `/hello`. A newer directory record keeps a family only when it lists the stored address. If the key lookup fails, renewal falls back to a fixed 12 hours.
- **An unreachable TCP 443 probe holds the retry for 12 hours** **[redeploy]**. When a family has not activated and the platform cannot reach TCP 443, the provider waits its renewal interval before it retries. It does not use the shorter backoff ladder.
- **The extender allows the platform's own hosts by default** **[redeploy]**. The platform proves an extender by forwarding a request to its own API host, and the empty allow list refused it. The platform space and one wildcard level are now allowed, and hosts you add extend the list. A derived space that is a public suffix is limited to the API host.
- **TCP 443 binds first, and nothing else opens while it is taken** **[redeploy]**. The role tries UDP 53 for the DNS carrier by default. A blocked TCP 443 is explained in full, with the holder named when `ss` can find it.
- **Status shows each carrier and why one was left out** **[redeploy]**. `urnet-tools extender`, `status` and `top` show the bound carriers, which ones the platform accepted, the record expiry and what each address family is doing. The health line repeats the last accepted and refused carriers. A carrier that returns is reported once. A listing is never shown as active after its signed expiry.
- **Extender log lines start with the bridge mark** **[redeploy]**. A check, no-entry, cross or warning mark follows where one applies, so `grep` for the bridge finds every extender line and a cross finds every failure.
- **Requests served are counted at the source** **[redeploy]**. A request counts only after it passed authorization and admission and the stream was handed over. Refused requests, scanners and probes are never counted.
- **A role that stopped is restarted** **[redeploy]**. If the supervisor exits on its own, the manager now joins the dead role and starts a replacement. A start that keeps failing is logged once, and a start is announced only after it succeeds.
- **Stale and cancelled activations no longer confuse the manager** **[redeploy]**. The provider keeps the live activation until a replacement finishes its first key lookup. It never installs an activation for a slot that already ended.
- **Root key errors no longer log response bodies** **[redeploy]**. Untrusted bodies and transport details are left out.
- **An invalid `URNETWORK_EXTENDER` value warns once** **[redeploy]**. The warning used to repeat on every reconcile while direct providing was off.
- **`urnet-tools top` resets its extender state when you switch providers** **[redeploy]**. A discarded fetch no longer leaves later polls blocked.
- **Commands for another user's provider re-run under sudo** **[redeploy]**. This applies before the tool touches that provider's socket or its pending override file, and dry-run is kept.

### Extender setup

- **`urnet-tools extender setup` is new** **[redeploy]** ([#1054](https://github.com/full-bars/urnetwork-3.23-fix/pull/1054)). Setup checks whether TCP 443 is occupied, whether the provider binary may bind it, and whether the host firewall allows the carrier ports. It prints every command it would run, asks before it changes anything, and then checks a live TCP 443 bind as the provider user.
- **Only an explicit flag approves a non-interactive run.** Use `--yes` (`-y`) or `--force`. An elevated rerun now shows its own plan and asks again, because the elevated host can differ from the first plan. The command no longer adds approval itself. A manual rerun keeps your target and flags.
- **A hidden TCP holder no longer reads as "already configured".** When the run cannot see which process holds port 443, setup rechecks as root first.
- **firewalld rules are planned separately and never reloaded.** Setup plans the runtime and the permanent rules on their own, so it does not discard unrelated runtime changes. If it cannot read the rule state, it stops with the cause and does not guess a plan. ufw plans only the rules that are missing.
- **Existing file capabilities are preserved.** Setup reads grouped capability flags and keeps the capabilities already on the binary when it adds the bind capability. It refuses a blocked bounding set.
- **FreeBSD setup is print-only and untested in this release.** It prints the temporary `sysctl` commands and their undo, and it makes no change. Regular providing on FreeBSD is unaffected. The `sysctl` setting removes privileged-port protection for all local users, and the text says so and explains how to restore the previous value. FreeBSD port checks use `sockstat`, including dual-stack entries, so they no longer need `lsof`.
- **UDP 53 is optional and user-managed.** Setup does not open it.
- **Port checks match the exact local port.** A connected UDP socket or a longer port number such as 4430 no longer counts as port 443.
- **The installer prints one notice and asks nothing** **[installer]**. It says whether TCP 443 is free or what holds it, says plainly when a non-root provider cannot bind 443, and never fails the install. It no longer calls a failed port check free.

### Provider and transfer

- **Receive-loop panics a peer could trigger are fixed** **[redeploy]** ([#1052](https://github.com/full-bars/urnetwork-3.23-fix/pull/1052)). A sealed frame with no path, and a pack whose lane head named another sequence or a stale index, each stopped the whole client for every peer. A missing path is now an error, a pack on another lane is dropped, and a stale head index is healed. Regression tests reproduce each panic on the previous code.
- **Mismatch diagnostics are bounded** **[redeploy]**. A stale older head no longer stops the receive loop, and repeated drops no longer flood the log.

### Logs and diagnostics

- **Log following survives a trim** **[redeploy]** ([#1053](https://github.com/full-bars/urnetwork-3.23-fix/pull/1053)). The follower tracks the file path, so a trimmed RAM log no longer leaves the stream silent. It no longer prints a split line twice. If repeated content makes the resume point unclear, it replays lines and does not lose new output.
- **`urnet-tools diag` free-space help is correct** **[redeploy]** ([#1055](https://github.com/full-bars/urnetwork-3.23-fix/pull/1055)). The capture checks a fixed 512 MiB on the filesystem that holds the diag directory, and the help now says so. A negative availability count is treated as zero, so a capture cannot start on a full filesystem.

### Documentation and maintenance

- **The extender guide is rewritten** **[no redeploy]**. It covers ports, firewalls for ufw, firewalld, iptables and nftables, IPv6, Docker modes, restart behavior and troubleshooting. The log reference gains an extender section. The README states that the default Docker bridge activates the extender for IPv4 only, names the two ways to get IPv6, and adds Compose examples.
- **The log reference no longer lists the unsupported `--important` flag** **[no redeploy]**.
- **Windows follower tests run on the Windows runner** **[no redeploy]**. The tests replace the followed file in one step, as other systems do.
- **SN25 live figures were refreshed** **[no redeploy]**. See the [head-tier page](https://github.com/full-bars/urnetwork-3.23-fix/blob/main/docs/Bittensor-Head-Tier.md).

## Known limitations

- The Docker RAM log follower may replay retained lines after the log is trimmed.
- A hot-swap candidate can race the old provider while it still holds a listening socket. This release does not fix that race.
- FreeBSD extender setup is print-only and has not been tested on a FreeBSD host.
