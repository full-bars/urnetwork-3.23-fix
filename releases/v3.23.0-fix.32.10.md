# v3.23.0-fix.32.10

> [!NOTE]
> This release fixes the stage-1 proxy-quality probe and adds a read-only grade for the direct path. The probe no longer condemns a proxy from a clustered sample. It now waits for enough dials before it convicts. The new direct grade shows whether a failing proxy is bad or the box's own route is bad. The release also relabels the proxy-health down bucket. It corrects the metrics and profile documentation. A default box changes only in what it logs and in one new state file.

> [!IMPORTANT]
> The direct grade is read-only. Nothing acts on it. It is written to its own file and never into `proxy.state`, so trim, audit and admission ignore it. Read the line as "this box's egress can reach the internet". Do not read it as "the direct transport is healthy". The transport's own product is inbound reachability of the box address, which no outbound probe can see.

## What's Changed

### Added

- **A read-only grade for the direct path** ([#776](https://github.com/full-bars/urnetwork-3.23-fix/pull/776)): the provider now grades its own local-IP egress. An operator can then tell a bad proxy from a bad box. It samples the same destination table as the proxy probe, with the same sampler. It dials each host at port 443 from the box's own address, and it requires a verified TLS handshake. A bare connection test is not enough. Any intercepting middlebox can answer a plain connection for every destination, so a TCP-only check would call a box healthy while it has no working route. The score is the fraction of destinations that completed a verified handshake. A destination that connected but failed certificate verification is counted separately as intercepted. It lowers the score and it is reported on its own, so an operator can see a box that is intercepted rather than merely slow. The two scores are comparable estimates of the same fraction, not paired samples. The grade lands in `~/.urnetwork/direct_grade.json`. It never lands in `proxy.state`, so no existing consumer can act on it. It runs on the reaper tick. It needs both the table probe and the direct transport enabled. A tier change logs `[proxy][grade] direct: <tier> (score x.xx, n/m)`. The periodic grade summary carries a `direct:` line.

### Fixed

- **The stage-1 probe condemned proxies on a clustered sample** ([#775](https://github.com/full-bars/urnetwork-3.23-fix/pull/775)): the probe drew a contiguous block of the destination table. That table is grouped by theme. A block landed on one or two adjacent themes. Destination failures are strongly correlated inside a theme, so one refused region failed the whole pass. The score then swung between A and F as the rotation moved between regions. The proxy never changed. The recorded failures were runs of consecutive table rows. The probe now samples a fixed, content-keyed permutation of the table. It orders the table by the hash of each hostname. One block now spans many themes. Every property the probe relies on is unchanged. Blocks stay disjoint. The table is still walked in order. The dial count does not change. Set `use_spread_order` to false to restore the old behaviour. That is a clean way to measure the change on one box.
- **A thin pass could still convict a proxy** ([#775](https://github.com/full-bars/urnetwork-3.23-fix/pull/775)): the probe could end a pass below the bar after a few correlated failures. A new `min_confirm_dials` floor now gates both the early abort and the final verdict. A pass below the floor keeps dialing its block. A pass that runs out of block below the floor keeps the previous grade. The paid grader uses a floor of 6 by default. That is the staged base width. The URL admission path and the reaper keep a floor of 0, so their dial profile is unchanged. Set the key to -1 on the paid path to turn the floor off.
- **The proxy-health down bucket reused the word degraded** ([#769](https://github.com/full-bars/urnetwork-3.23-fix/pull/769)): the live status and the `top` view called the was-up-now-down bucket `degraded`. The whole-pool figure uses that word for a different state. The bucket is `dropped` now, so `down` has one meaning. Labels and wording only; the reaper inputs are unchanged.

### Changed

- **The sn pin is advanced and the head binding model is updated** ([#771](https://github.com/full-bars/urnetwork-3.23-fix/pull/771)): `bind-head` and `unbind-head` now use the many-to-one dual-signed fleet binding. The commands keep their names and their offline-print and on-chain submit shape. The flags follow the new model: `--manifest`, `--hotkey_seed_file`, `--valid_from_epoch`, `--valid_to_epoch`, `--effective_epoch`, `--client_id` and `--client_seed_file`. The sn dependency pin is advanced.
- **The metrics and profile documentation is corrected** ([#772](https://github.com/full-bars/urnetwork-3.23-fix/pull/772), [#773](https://github.com/full-bars/urnetwork-3.23-fix/pull/773), [#774](https://github.com/full-bars/urnetwork-3.23-fix/pull/774)): the metrics port is `9100`, not `9091`. The endpoint takes the next free port up to `9103`. The `/metrics` endpoint is off until `urnet-tools metrics on` turns it on. `URNETWORK_METRICS` sets a bind address, not a switch. The docs now describe the `monitoring/` bundle that ships. They no longer name a compose file that does not exist. The metric table gains the supervised-loop series. The profile command reference is corrected.

## Deploy Notes

1. **Update and restart.** `urnet-tools update` picks up the release. No config changes are needed. NOTE: the probe fix is on by default.
2. **The spread sampler is on by default.** `use_spread_order` defaults to true. Set it to false in `~/.urnetwork/proxy_probe.json` to restore the old contiguous sampling. That is the A/B lever for measuring the churn change on a canary box.
3. **The confirmation floor is on by default for paid and file proxies.** `min_confirm_dials` defaults to 0 in the file. The paid grader raises it to 6. The URL admission path and the reaper keep 0. Set it to -1 on the paid path to turn the floor off. The floor can never exceed the widest block the probe can dial.
4. **The direct grade needs a verified TLS handshake to score a destination.** A destination that connects but fails certificate verification is recorded as intercepted and does not count as reachable. Watch the intercepted count on the first canary: a non-zero value points at interception or a misconfigured certificate on the box's path, not at the proxies. The destination table was measured from a clean box: 125 of 127 hosts complete a verified handshake, so a healthy route should show an intercepted count of zero.

5. **The direct grade writes a new state file.** It appears at `~/.urnetwork/direct_grade.json` only when the direct transport is enabled. The table probe must be on too. The grade is read-only, and nothing acts on it. On a multi-container stack, mount each node its own state volume so the file is not shared.
6. **What to watch on a canary.** Watch the A-to-F churn on paid proxies before and after the update. The fix must lower the churn on a box whose real capability did not change. Watch the `[proxy][grade] direct:` line for the box's own route.
6. **Docs.** The new probe keys are in [Configuration](../docs/Configuration.md). The log lines are in [LOG_REFERENCE.md](../LOG_REFERENCE.md).
