# v3.23.0-fix.34.0

> **Built from:** `cfa720aa0` on `release/34.0` (the code head after #906; this notes commit is on top). Release candidate lineage: `v3.23.0-fix.34.0-rc1` → `v3.23.0-fix.34.0-rc2`.

> [!NOTE]
> v34 moves the provider onto the **v2026 connect generation**. Everything a provider needs for SN25 stays as it was; the engine under it changes, and the conversation is now the same one the sn line has been running in the field. No wire change: `protocol/*.proto` and the reproduced `.pb.go` files do not move.

> [!IMPORTANT]
> Soak this on a canary before a fleet rollout. NY5 has run rc2 for ~2 hours with no restarts, ~1,056 proxies up, earning, zero panics, and RSS around 800 MB (watch the curve). rc2 adds one runtime guard (a proxied TLS handshake can no longer strike or retry a family) and the CI modern-provider gate; this final adds the network-switch notice fix and the OpenRC CI hardening. The checklist's meso-miner mirror follows as its own release.

## What this release is

Five engine slices land from the pinned v2026 engine (`full-bars/connect c8d8cdf536a8`, the module the sn line pins): family dial and DoH family policy; egress, route manager and platform budget; the ICE resolver and routing classifier; the shared provider UDP socket lifecycle; and the transfer layer, including the reliable lane and the subprotocol surface. Each slice adopts upstream files on the leaf rule and keeps the fork's behaviour behind adapters; `transport_fork_helpers.go` holds the additions.

v33.1 and v33.2 merge forward. v33.1 brings the shared Docker entrypoint, `h3 auto`, the installable update selection, the one-call network-token renewal and the Blocker data. v33.2 is the image-workflow fix. The post-slice work lands here as well: transfer stages S2/S3 and S7/S8, the ICE IPv6 fix, per-proxy dual stack, the budget review and the governor review.

## Highlights

- **The v2026 engine generation.** Same generation as the sn line, with IPv4 as the primary control plane and never demoted; only IPv6 may narrow. The family-pinned v4 and v6 transports, the DoH family policy, the route manager and the platform budget move together.
- **Dual stack is a control, not an assumption.** `ip_version` (`dual`, `ipv4`, `ipv6`, `legacy`; default `dual`) governs the direct identity's platform transports. `proxy_target_family` (`v4` default, `proxy` opt-in) decides whether the provider or the SOCKS5 proxy resolves a proxied destination. `v4` keeps per-target address health and the local DNS cache; `proxy` lets the proxy choose the family and gives up per-target visibility.
- **The network switch notice no longer cries wolf.** `choose_network main` or `--reset` with nothing saved, and re-saving the same URL pair, no longer print the "jwt was issued by the previous network" warning. The notice compares the effective `api_url` before and after the change, so it appears only when the JWT is actually invalidated. Auth codes are single-use; a false warning used to cost one.
- **A proxied handshake can no longer demote a family.** `proxyDialError` already kept a proxy's failure out of the family ledger, but a TLS handshake over a proxy fails with a plain timeout, so a proxied stall used to demote the proxy socket's family and then retry through the same proxy. The dial now checks `dialUsesProxy` at every decision: no strike, no retry.
- **The governor sees what enforce would see.** In shadow mode it now restores and persists the learned baseline instead of starting from the plain 20% threshold, so `baseline` and `threshold` describe the same window. A locally cancelled attempt is no longer recorded as an early death.
- **Transfer accounting is exact and opt-in.** S2/S3 split the logical and retained queues and make retained accounting opt-in; S7/S8 bring reliable-lane provenance (default off) and the reliable handoff timeout (default `-1`, off). First-send counters record only after a successful write.
- **The budget path cannot panic on an exact hierarchy.** Standalone reserve/release no longer takes the root admission lock, `Reserve` charges the full hierarchy instead of underflowing, the waiter grant scratch is reused, and capacity waiters wake in FIFO order.
- **ICE name resolution prefers IPv4 on a family-agnostic lookup.** A dual-stack STUN/TURN name whose AAAA answers first no longer parks candidate gathering on a dead v6 path; `ip4`/`ip6` keep the resolver's own order, and address literals are checked against the requested family.
- **The modern-provider evidence is enforced by CI.** `modern_provider_gate_test.go` runs on every build, so the PQ (X25519MLKEM768) and resizable-window capabilities cannot disappear without the build failing. The platform gate itself turns on at 2026-10-21 00:00 UTC unless the operator moves it.

## Transport defaults in this release

- `h3` = `direct`: H3, H3 over DNS and the DNS pump are fallbacks for the direct identity, idle while H1 works. `N` extends the same fallback set to the N best proxies; `all` is every proxy; `auto` sizes it from memory. None of them runs beside H1 on a proxy.
- `h1_plus` = `on`: new H1 dials try the authenticated carrier upgrade before a plain websocket.
- `h3_datagram` and `h3_datagram_send` default on, as upstream; the blackhole guard drops the datagram lane when nothing comes back.
- `proxy_target_family` = `v4`; `proxy` is the dual-stack canary knob. `ip_version` = `dual` for the direct identity.

## Fixed

- A proxied TLS handshake no longer records a family strike or retries on another family.
- The governor restores its baseline in shadow mode; a local teardown is not governor evidence.
- Transfer first-send counters no longer count a write that never reached the wire.
- `Reserve` charges an exact-equality hierarchy instead of panicking; the standalone budget path is lock-free; waiters wake in FIFO order.
- ICE resolution prefers IPv4 for family-agnostic names and enforces the family for literals.
- The updater pages the release list and skips releases it cannot install; the nightly PELICAN check reads the shared entrypoint; the provider package timeout is 900s for the `-race` shard.
- The poller fan-out test no longer assumes six ephemeral ports hash to both shards (test-only, #889).
- The network switch notice only appears when the effective network changes; a real switch still warns.
- The OpenRC smoke workflow declares `contents: read` and disables checkout credential persistence (CI only).

## Known limits

- The shared UDP socket poller, the light classifier and the budget hierarchy are **inert on the Linux fleet** (present, not wired into the default path). A clean soak is not coverage for them.
- The Windows and darwin egress paths were not exercised; the Windows egress pinning now fails closed when every option fails, which needs the Windows canary.
- Proxy H3 is a fallback, never a parallel transport. `proxy_target_family=proxy` gives up per-target address health and cannot prove a proxy is IPv6-capable; SOCKS5 does not report the family it used upstream.
- The meso-miner mirror of this generation is a separate release; 3.23-fix and meso run different generations until it lands.
- The modern-provider gate is evidence-based: a provider with no fresh probe row is not modern for the Quality and Speed buckets until the capability probe measures it (evidence is re-measured at three days, stale at seven).
- **Deferred security follow-up in the root tuning queue.** A root-run tuning toggle appends its pending op through a lock file opened with `O_TRUNC` in a directory the service user controls, so that user can make root truncate a chosen root-owned file (a denial of service; nothing is written through the descriptor). The fix is a privilege-model decision (drop privileges for state writes, a root-owned spool, or both), not a mechanical patch; it is recorded as finding 8 in sn #93.

## Deploy notes

1. Canary first. NY5 has run rc2 for ~2 hours: no restarts, ~1,056 proxies up, earning, zero panics, RSS ~800 MB (watch the curve). rc2 adds #897 (the proxied-handshake guard) and #896 (CI); this final adds the network-switch notice fix and the OpenRC CI hardening.
2. Native installs replace the provider binary; identities and state are unchanged. The Go `urnet-tools` is a **separate release asset** (`urnet-tools-linux-amd64`); the `urnet-tools` file inside the provider tarball is the legacy shell script.
3. Rollback: keep the previous provider binary and a state tarball. Stop the unit, restore the binary, start.
4. If you change `proxy_target_family` to `proxy`, canary one box and watch unreachable/auth rates; the proxy's resolver becomes authoritative.
5. If you widen H3 (`N`, `all`, `auto`), expect one redial and about 1.75 MB of platform speed tests per added proxy; a proxy that fails the SOCKS5 UDP relay check stays on H1.
6. CI now runs the host and Docker shakedowns in parallel (per-workflow concurrency groups and a jittered, retried JWT mint), so a release is bounded by the slower suite instead of their sum.
