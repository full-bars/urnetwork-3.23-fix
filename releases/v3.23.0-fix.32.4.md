# v3.23.0-fix.32.4

> [!NOTE]
> This release fixes a credential-rotation loop on paid, file-sourced proxies introduced when the rotation feature shipped in v3.23.0-fix.32.1. Affected nodes continuously re-authenticate credentialed proxies every ~30 seconds instead of only when credentials actually change, flooding the backend control plane and the ramlog. Proxies keep serving between cycles — this is not a connectivity outage — but any node running credentialed proxies on 32.1 through 32.3 should update.

This is a focused hotfix. Its one fix stops perpetual credential rotation on paid proxies.

## What's Changed

### Fixed

- **Perpetual credential rotation on paid proxies** ([#680](https://github.com/full-bars/urnetwork-3.23-fix/pull/680)): the reload cycle recorded a running proxy's auth baseline as the same pointer handed to its own goroutine, which the proxy runtime mutates during its auth flow. The baseline drifted within milliseconds of launch, so every ~30s reload saw a phantom credential change and rotated — relaunching (and re-mutating) the proxy, forever. Only credentialed (paid, file-sourced) proxies were affected; nil-auth proxies always compared equal. The baseline is now a deep copy, isolated from the object the runtime mutates. A genuine credential change (re-paste) still rotates exactly once.

## Deploy Notes

1. **Update and restart — no config changes.** `urnet-tools update` picks up the fix; a normal restart or hotswap is enough, nothing to reclaim.
2. **Most affected: nodes running credentialed (paid) file-sourced proxies on v3.23.0-fix.32.1 through 32.3.** URL-sourced or nil-auth proxies were never affected.
