## What's New

### Allocation-free ID generation

`NewId()` was calling `ulid.Make()` on every call, which heap-allocates each time. It's on the hot path for every sequence, message, and transport ID, so under load that's thousands of allocations per second feeding the GC.

Now it uses an inline monotonic ULID generator that writes directly into a stack-allocated `[16]byte`. Same format, zero heap cost. The `github.com/oklog/ulid/v2` dependency is dropped entirely.

### Zero-alloc protobuf codec on the relay hot path

Every relayed packet was going through `proto.Marshal`/`proto.Unmarshal`, which uses reflection to walk Go structs. That reflection cost and the intermediate struct allocations dominated the per-packet profile.

The send and receive paths now use a hand-rolled wire codec that writes bytes directly into pooled buffers with no intermediate structs. Output is byte-for-byte identical to `proto.Marshal` across all frame types. The legacy path (v1 peers) is unchanged.

Both ports are from upstream v2026.6.24.

> [!NOTE]
> Data-plane only. Auth, proxy management, hub reporting, and contract handling are unaffected.
