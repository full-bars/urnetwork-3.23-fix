# v3.23.0-fix.32.9

> [!NOTE]
> This release adds an opt-in H3 (QUIC) transport beside H1 for the direct identity, behind `URNETWORK_H3=on`. It is off by default, so a box that does not set it behaves exactly as on 32.8.

> [!IMPORTANT]
> Beta and unproven. The platform does not score or pay by transport mode, so no gain from H3 is claimed. Enable it on a single box first and watch the `[t]h3` lines, the `[t]auth error` rate and billable per hour against a box without it. It takes effect only after a restart.

## What's Changed

### Added

- **`URNETWORK_H3` (beta, off by default): H3 (QUIC) beside H1 for the direct identity** ([#744](https://github.com/full-bars/urnetwork-3.23-fix/pull/744), [#746](https://github.com/full-bars/urnetwork-3.23-fix/pull/746)): the engine already contained a working H3 platform transport that `Auto` mode never launched. With `URNETWORK_H3=on` the direct (non-proxied) identity starts it beside H1. A proxied identity never does, because the H3 transport opens a UDP socket on the host and would send its QUIC from the host address instead of through its proxy.
- **H1 stays the health signal** ([#744](https://github.com/full-bars/urnetwork-3.23-fix/pull/744)): a failed H3 connect, for example because UDP is filtered, is "mode unavailable". It is not recorded as a backend failure or a proxy auth failure, backs off quietly for up to 10 minutes, and logs a single `[t]h3 unavailable, staying on h1` line. An H3 authentication does not clear the failures H1 recorded, and an H3 connect or drop does not mark the identity up, down or dropped.
- **Both transports stay connected** ([#744](https://github.com/full-bars/urnetwork-3.23-fix/pull/744)): H1 and H3 tie on preference, so one is elected active. The other no longer idles out and reconnects in a cycle, and H1 is no longer torn down when H3 connects first.
- **H3 traffic counts into total** ([#746](https://github.com/full-bars/urnetwork-3.23-fix/pull/746)): the H3 socket's bytes are credited to the identity's total traffic, so `top`, `status` and the Prometheus total series include them. Billable is counted at the IP layer and is unaffected.

## Deploy Notes

1. **Off by default.** Nothing changes until `URNETWORK_H3` is set to `on` (or `1`, `true`, `yes`) in the unit and the provider is restarted.
2. **One extra platform connection per box.** The direct identity holds an H3 connection beside its H1 one.
3. **Direct identity only.** Proxied identities never start H3, so a box's proxies are unaffected.
4. **Turning it off.** Unset `URNETWORK_H3` and restart.
5. **What to watch on a canary.** The `[t]h3 unavailable` line, the `[t]auth error` rate, the backend-degraded state, billable per hour and resident memory, against a box without H3 over the same window. A rise in auth errors or the degraded state, or a fall in billable, is a reason to turn it off.
6. **Log lines** are described in [LOG_REFERENCE.md](../LOG_REFERENCE.md), and the setting in [Configuration](../docs/Configuration.md).
7. **No other behavior changes.** This release adds H3 and nothing else; the fleet-wide fixes are in 32.8.
