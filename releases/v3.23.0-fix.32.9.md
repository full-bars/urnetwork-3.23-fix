# v3.23.0-fix.32.9

> [!NOTE]
> This release lands the H3 (QUIC) transport beside H1 for the direct identity. H3 is beta and off by default. A box that does not switch it on behaves as it did on 32.8. The release also adds transport counters you can see, a low-noise STUN summary, and proxy and pool fixes.

> [!IMPORTANT]
> Beta and unproven. The platform does not score or pay by transport mode. So no traffic gain from H3 is claimed yet. Try it on one box first. Watch the `[t]h3` lines, the `[t]auth error` rate, the backend-degraded state and billable per hour. Compare against a box without it. H3 starts on a restart, or at once with `urnet-tools set h3 on`.

## What's Changed

### Added

- **H3 (QUIC) beside H1 for the direct identity, beta and off by default** ([#744](https://github.com/full-bars/urnetwork-3.23-fix/pull/744)): the engine already had a working H3 platform transport. `Auto` mode never launched it. Set `URNETWORK_H3=on` and the direct identity runs it beside H1. A proxied identity never does. H3 opens a UDP socket on the host, so its QUIC would leave from the host address. H3 is auxiliary, and H1 stays the health signal. It costs one extra platform connection per box.
- **H1 stays the health signal** ([#744](https://github.com/full-bars/urnetwork-3.23-fix/pull/744)): a failed H3 connect is "mode unavailable". That happens when UDP is filtered. It is not a backend failure and not a proxy auth failure. H3 backs off quietly for up to 10 minutes. It logs one `[t]h3 unavailable, staying on h1` line. An H3 connect or drop does not mark the identity up, down or dropped. Both transports stay connected. Neither idle-drains when the other won the election.
- **Switch H3 live with `urnet-tools set h3 on|off`** ([#753](https://github.com/full-bars/urnetwork-3.23-fix/pull/753)): the new runtime gate needs no restart. On lets the idle transport dial at once. Off closes a live connection and stops further dials. That is not counted as an H3 drop. The key is persisted and replayed at startup. A persisted off beats `URNETWORK_H3=on`. Clearing the key hands the decision back to the environment variable.
- **H3 socket bytes count into total traffic** ([#746](https://github.com/full-bars/urnetwork-3.23-fix/pull/746)): the H3 UDP socket now credits the identity's total. `top`, `status` and the metrics include it. Billable is counted at the IP layer. Billable is unaffected.
- **A QUIC DATAGRAM lane, receive then send, both off by default** ([#761](https://github.com/full-bars/urnetwork-3.23-fix/pull/761), [#762](https://github.com/full-bars/urnetwork-3.23-fix/pull/762), [#763](https://github.com/full-bars/urnetwork-3.23-fix/pull/763), [#765](https://github.com/full-bars/urnetwork-3.23-fix/pull/765)): `h3_datagram` offers DATAGRAM on the H3 connection. A server that accepts then sends its small frames as datagrams. `h3_datagram_send` lets this provider send small frames the same way. Larger frames stay on the reliable stream. Datagrams are used only while H1 is up. The blackhole guard drops the lane when datagrams go out and none come back. The H3 memory is bounded like upstream and scales with the provider's budget.
- **See what each transport mode carries** ([#753](https://github.com/full-bars/urnetwork-3.23-fix/pull/753), [#755](https://github.com/full-bars/urnetwork-3.23-fix/pull/755), [#759](https://github.com/full-bars/urnetwork-3.23-fix/pull/759)): payload frames and bytes are counted per mode. The modes are H1, H3 and the two DNS modes. The figures show up in `[health]` and in `/metrics`. They also land in the baseline record, the Grafana dashboard and a new `top` panel. The H3 share uses the direct identity's H1 as its denominator. That is the fair comparison. A box that never tries H3 sees no new fields.
- **A low-noise STUN success summary** ([#749](https://github.com/full-bars/urnetwork-3.23-fix/pull/749)): STUN now reports one `[stun] ok=N fail=M` line per interval. The interval is one minute under load and five minutes otherwise. Success and failure are counted in the fork's own code. A Cloudflare STUN endpoint is added as a probe only. No STUN or ICE behaviour changes.
- **A report id on close frames** ([#750](https://github.com/full-bars/urnetwork-3.23-fix/pull/750)): `CloseContract` frames now carry a `ReportId`. It is logged. A retry or out-of-band dedup mismatch can then be triaged from the client side. The close report is built in one place now.
- **`urnet-tools set` documents the new keys** ([#764](https://github.com/full-bars/urnetwork-3.23-fix/pull/764)): the help rows now cover `h3`, `h3-datagram`, `h3-datagram-send`, `baseline` and `proxy-audit`. Each row gives its domain, default and effect. The `metrics-listen` row is documented too.

### Fixed

- **An H3 reconnect leaked a socket** ([#751](https://github.com/full-bars/urnetwork-3.23-fix/pull/751)): each reconnect leaked one UDP file descriptor, its read goroutine and the QUIC transport state. The transport and socket close in order now.
- **An idle connection never drained** ([#751](https://github.com/full-bars/urnetwork-3.23-fix/pull/751), [#752](https://github.com/full-bars/urnetwork-3.23-fix/pull/752)): the inactive-drain check counted keepalives as use. The peer pings on a timer, so the check never saw an idle connection. It counts payload only now. The closed line still reports the total per direction.
- **H3 bytes went uncounted on a direct box** ([#757](https://github.com/full-bars/urnetwork-3.23-fix/pull/757)): the bandwidth record was registered after the transport started. The first dial then found nothing and kept the raw socket. Every H3 byte went uncounted. The record is registered before the transport now.
- **A path-size report inflated the send-error metric** ([#765](https://github.com/full-bars/urnetwork-3.23-fix/pull/765), [#763](https://github.com/full-bars/urnetwork-3.23-fix/pull/763)): quic-go rejects an oversized DATAGRAM before it is queued. That is path discovery, not a failed send. The async lane no longer counts it. A report that cannot lower the limit is still counted.
- **A datagram reader could close a live channel** ([#761](https://github.com/full-bars/urnetwork-3.23-fix/pull/761)): the reader slot was reserved after the receive closer had started waiting. That is a wait group misuse. Every reader slot is reserved before the closer waits now.
- **Stale datagram fragments held memory** ([#761](https://github.com/full-bars/urnetwork-3.23-fix/pull/761)): expiry ran only on arrival. An incomplete message on a quiet connection held its allocation until teardown. A timer expires fragments now. Payload is counted only after a route accepts a message.
- **The STUN probe was wrong about its own servers and results** ([#749](https://github.com/full-bars/urnetwork-3.23-fix/pull/749)): it read the compiled defaults. A client with its own ICE servers was judged against servers it never used. It also counted some failures as success. It held a lock across each round trip. It reads the active settings and bounds the response body now. It uses one success test and stops on shutdown.
- **Log markers were restored and standardized** ([#748](https://github.com/full-bars/urnetwork-3.23-fix/pull/748)): the ready, hotswap and lifetime markers are back to their documented form. The contract close tokens are intact again. Provider lines use one emoji per namespace now.
- **A source that went empty kept its proxies dialing** ([#756](https://github.com/full-bars/urnetwork-3.23-fix/pull/756)): those proxies are cancelled now. They drain first when they still have live clients. A drained proxy whose source returns wakes a reload at once. Pool reuse and growth are judged over the current interval. The no-source reason reads honestly now.
- **A corrupt `proxy_url.json` quarantine lost the configuration** ([#758](https://github.com/full-bars/urnetwork-3.23-fix/pull/758)): the quarantine restarted from an empty state. The sources, the permanent blacklist, the exclude patterns and the cleanup threshold went with the cache. The replacement now starts from the last configuration that parsed.
- **The download worker no longer needs an authenticated GitHub call** ([#768](https://github.com/full-bars/urnetwork-3.23-fix/pull/768)): `/latest-version` resolved the latest release tag through the GitHub API. That API allows 60 anonymous requests per hour per source IP. Cloudflare Workers egress from shared addresses, so the budget stayed spent and the endpoint answered a 502 `failed` for every caller, including the clients it exists to rescue. It reads the tag from the `/releases/latest` redirect now. That path needs no token and has no such limit. The GitHub API stays as a fallback that uses `GITHUB_TOKEN` when the secret is set.

### Changed

- **CI smoke runs are serialized** ([#760](https://github.com/full-bars/urnetwork-3.23-fix/pull/760)): six open pull requests authenticated against the live API at once. The shared account hit its sign-in limit. One smoke run now runs at a time. A queued run waits instead of racing.

## Deploy Notes

1. **Off by default.** Nothing changes until `URNETWORK_H3` is `on`. The values `1`, `true` and `yes` also work. `urnet-tools set h3 on` works too.
2. **Switch H3 live.** `urnet-tools set h3 on` starts it without a restart. `urnet-tools set h3 off` closes a live connection and stops further dials. Clearing the key returns the decision to `URNETWORK_H3`.
3. **Try the DATAGRAM lane on one box.** `urnet-tools set h3-datagram on` enables the receive side. Then `urnet-tools set h3-datagram-send on` enables the send side. Both are off by default and need `h3` on.
4. **One extra platform connection per box** while H3 is on. This applies to the direct identity only. Proxies are unaffected.
5. **What to watch on a canary.** Watch the `[t]h3 unavailable` line and the `[t]auth error` rate. Watch the backend-degraded state, billable per hour and resident memory too. Compare against a box without H3 over the same window.
6. **New metrics need this release.** The `urnet_transport_*` and `urnet_h3_*` series stay empty on an older provider. The DNS-mode counters stay zero on a stock provider. `Auto` mode does not start those modes.
7. **Docs.** The settings are in [Configuration](../docs/Configuration.md). The log lines are in [LOG_REFERENCE.md](../LOG_REFERENCE.md). The new series are in [Monitoring](../docs/Monitoring.md).
8. **Deploy the download worker.** The worker fix arrives with PR #768, which merges before the tag. The code is in `workers/dl-fullbars/src/index.js`. It does nothing until you run `wrangler deploy` in `workers/dl-fullbars/` after that merge. This note is for this repo's worker.
