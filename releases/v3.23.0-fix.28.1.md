# v3.23.0-fix.28.1 — Paid/free probe divergence + earn-skip (expected)

> [!NOTE]
> Provider behavior change — **fleet deploy required** (`needs-fleet-deploy`). The probe cadence and probe-spend profile change on every box the moment it runs the new binary; existing boxes keep the old behavior until they are redeployed.

## What's New

### 💸 Paid/file proxies: probe spend now proportional to suspicion

Stage-1 table probing splits into two cadences. Paid/file proxies — whose
probe bandwidth the operator pays for — move to a **wider stale window**
(`paidStaleCalm=6h` / `paidStaleHot=3h` vs the URL window's 3h/1h,
pressure-ramped the same way), cutting paid probe traffic roughly 3x at the
hot end.

**Earn-skip**: a paid proxy with a positive billable delta within the last
15 minutes is demonstrably alive — the backend is routing real sessions
through it — so it is not re-probed at all. The signal is the per-address
delta, never the raw cumulative counter, so a proxy that earned once early
then died cannot look "earning" forever. Two guardrails keep fail-fast
honest:
- A hard **24h force-probe ceiling**: every paid proxy is probed at least
  once per day regardless of earn state.
- **Never-graded proxies are always probed** — earn-skip can never suppress
  the first grade.

In steady state, a paid proxy that is actively relaying traffic is never
probed; probe spend becomes proportional to suspicion rather than time.

### 🛡️ URL startup cooldown (probe-amplification protection)

The first URL fetch + stage-1 probe pass is deferred until the process has
been alive `probeStartupCooldown` (20s). A crash-looping box (bad binary,
OOM, exec trap) restarts every ~5s and previously re-fetched + re-probed the
URL lists on every restart — the probe-amplification loop. A box that cannot
stay up now never probes at all; a healthy box waits a few seconds and then
fetches exactly once as normal.

### 📊 Grade summary: per-source freshness windows

The dashboard summary's stale ratio now picks its freshness window per entry
source — URL entries are judged against the URL reaper window, paid/file
entries against the paid window — and resolves ownership by the same
desired-set rule the paid grader uses, so an address that is in the paid
file is always reported under the paid owner even if its first-seen
provenance tag says "url".

## Notes

- The earn tracker consumes the existing `ProxyHealthSnapshot` bandwidth map,
  normalizing its formatted `proxy[N] (addr)` keys to the raw address the
  grader uses; per-address state is pruned to the live proxy set (and cleared
  when the health set empties), so memory stays bounded as proxies churn.
- Read-only with respect to the proxy lifecycle, as before: grades are never
  consulted for admission, eviction, give-up, or cleanup.
- `~/.urnetwork/proxy_probe.json` with `{"enabled": false}` remains the kill
  switch for all stage-1 probing.
- Multiple independent review passes plus automated review on the PR; the
  earn-skip regression suite drives the tracker through the real snapshot
  API and is mutation-verified.
