# v3.23.0-fix.28.1 — Hub grade surfacing, paid/free probe divergence, tool distribution, TLS-verified proxies (expected)

> [!NOTE]
> Fleet deploy required for provider/hub behavior changes: probe cadence + probe spend, admission probing, and the hub schema/dashboard all change the moment boxes run the new binaries. Existing boxes keep old behavior until redeployed.

## What's New

### 🏗️ Hub A-F grade surfacing — the dashboard finally sees provider grades (#360, merged)

The provider boxes compute A-F grades for every proxy they serve, but the hub never received them — the fleet dashboard was blind to the grading system, and its existing "Score" column is a different traffic-composite metric. This closes the gap end-to-end: the provider's report payload now carries each proxy's grade (`score/graded/failed/tier/last_graded`, omitempty for backward compatibility), the hub ingests it into a new `proxy_grades` store (latest-wins per node+proxy per hour, 7-day retention), and the dashboard renders a color-coded A-F **Grade** column — distinct from the traffic-composite **Score** column. URL-store grade timestamps are now honest (a real `LastGraded` field, stamped only on genuine stage-1 grades, never on liveness-only probes). Grade tiers are sanitized to exactly A-F at ingest with HTML-escaping at both render sites (stored-XSS hardening).

### 💸 Paid/file proxies: probe spend now proportional to suspicion (#357, expected)

Stage-1 table probing splits into two cadences. Paid/file proxies — whose
probe bandwidth the operator pays for — move to a **wider stale window**
(`paidStaleCalm=6h` / `paidStaleHot=3h` vs the URL window's 3h/1h,
pressure-ramped the same way), cutting paid probe traffic roughly 3x at the
hot end.

**Earn-skip**: a paid proxy with a positive billable delta within the last
15 minutes is demonstrably alive — the backend is routing real sessions
through it — so it is not re-probed at all. The signal is the per-address
delta, never the raw cumulative counter, so a proxy that earned once early
then died cannot look "earning" forever. Two guardrails keep fail-fast
honest:
- A hard **24h force-probe ceiling**: every paid proxy is probed at least
  once per day regardless of earn state.
- **Never-graded proxies are always probed** — earn-skip can never suppress
  the first grade.

In steady state, a paid proxy that is actively relaying traffic is never
probed; probe spend becomes proportional to suspicion rather than time.

### 🛡️ URL startup cooldown (probe-amplification protection) (#357, expected)

The first URL fetch + stage-1 probe pass is deferred until the process has
been alive `probeStartupCooldown` (20s). A crash-looping box (bad binary,
OOM, exec trap) restarts every ~5s and previously re-fetched + re-probed the
URL lists on every restart — the probe-amplification loop. A box that cannot
stay up now never probes at all; a healthy box waits a few seconds and then
fetches exactly once as normal.

### 🔒 TLS-verified URL proxy admission (#359, expected)

URL-source proxies were admitted on a two-stage probe: SOCKS5 greeting, then
SOCKS5 CONNECT to the API. Any endpoint answering CONNECT with REP 0x00
entered the pool — including TLS-intercepting (MITM) proxies that terminate
TLS themselves and present a self-signed certificate. A stage 3 now runs a
TLS handshake through the same tunnel with ServerName pinned to the API host:
a transparent proxy relays the handshake untouched and verifies; an
interceptor presents its own certificate and is classified `probeTLSFailed`
— never admitted to the pool, and a once-good proxy that later turns hostile
is demoted through the reaper's failure-count → blacklist lifecycle. No
config knob: the check mirrors the provider's own auth-time TLS verification,
so pass/fail tracks real auth exactly.

### 🛠️ urnet-tools / urnet-docker tool distribution + self-update (#362, expected)

The Go-based fleet ops tool (rewritten in #345) is now actually shippable:
`release.yml` builds `cmd/urnet-tools` and `cmd/urnet-docker` for the full
matrix and attaches them as standalone assets (`urnet-tools-<os>-<arch>` /
`urnet-docker-<os>-<arch>`). The Linux and macOS installers fetch the Go
binary (sha256-verified against the release API digest) instead of
self-copying the legacy shell script, with a shell fallback for releases
that predate the asset. Docker-only users get a standalone host-side
installer (`scripts/install-urnet-docker.sh`, `curl ... | sh`,
digest-verified). **The tool keeps itself current**: `urnet-tools update`
refreshes both the provider and the tool binary itself from the same release;
new `self-update`/`selfupdate` subcommands update only the tool; `urnet-docker
update` self-updates the tool. The structural check on downloaded binaries is
now platform-aware (ELF/Mach-O/PE), so self-update works on macOS and Windows,
not just Linux.

### 🔧 Encryption: restartHandshake retries failed epochs (#361, expected)

A review HIGH: the restartHandshake guard treated a FAILED epoch as in-flight
forever — no second handshake attempt was ever made, routine once the 60s
TlsTimeout fails epochs against departed peers. Failed epochs are now rebuilt,
paced by a 5s cooldown so a fast-failing peer cannot spawn a handshake per
sealed write, and the parked handshake worker is freed on rebuild.

## Notes

- The earn tracker consumes the existing `ProxyHealthSnapshot` bandwidth map,
  normalizing its formatted `proxy[N] (addr)` keys to the raw address the
  grader uses; per-address state is pruned to the live proxy set (and cleared
  when the health set empties), so memory stays bounded as proxies churn.
- Read-only with respect to the proxy lifecycle, as before: grades are never
  consulted for admission, eviction, give-up, or cleanup.
- `~/.urnetwork/proxy_probe.json` with `{"enabled": false}` remains the kill
  switch for all stage-1 probing.
- Multiple independent review passes plus automated review on each PR.
