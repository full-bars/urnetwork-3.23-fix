# v3.23.0-fix.27.1 — Encryption-Mode Port, Fixes to the urnet-docker CLI, and Hub-Side A-F Grade Visibility

This release hardens the transport layer with the first real port of upstream's EncryptionMode era (tri-state encryption with fail-closed gates), fixes how the `urnet-docker` CLI passes flags to containers, and — if the hub grade-surfacing branch lands — starts the migration of A-F proxy grades from the provider boxes onto the hub dashboard.

## 🗂️ What's New

- **EncryptionMode tri-state port (scope 2)** (#350): the fork's `EncryptionSettings.Encrypt` bool is replaced with upstream's tri-state `EncryptionMode` (Off / Opportunistic / Required; zero value = Off = today's behavior). Under `Required`, consumers fail closed with `ErrEncryptionRequiredNotEstablished` instead of silently downgrading to plaintext. The port includes the refuse-plaintext send/receive gates, contract-open force-unwrapped pinning, and — the piece that matters even in the default Opportunistic mode — rekey continuity, so there is no plaintext window mid-rekey. The upstream `TlsTimeout` default stays at the fork's `-1`; upstream's 60s is a separate decision, tracked. ~300 lines, hand-mapped onto the diverged `transfer_encrypt.go` (the fork has diverged ~1,350 lines from the upstream parent, so this is a port, not a copy). Gate tests ported and race-clean.

- **`urnet-docker exec` flag forwarding fixed** (#349): `urnet-docker exec` now honors the standard `--` separator (docker/ssh convention), forwarding everything after it verbatim to the inner command. Unknown leading flags now error loudly with a hint instead of being silently dropped, a trailing target flag with no value errors instead of panicking, and a pre-separator `--help` prints usage instead of silently doing nothing. 25 `splitExecArgs` cases plus regression tests; full suite and race runner green.

- **Hub-side A-F grade surfacing** (roadmap step 3, expected this release): the provider's fleet report now carries each proxy's grade (`score/graded/failed/tier/last_graded`), the hub ingests it into a new `proxy_grades` store (latest-wins per node+proxy per hour with history), and the dashboard gains a color-coded A-F **Grade** column in the Best Proxies table and node drawer — distinct from the existing traffic-composite **Score** column. (Exact scope pending merge of the feature branch.)

## ⚠️ Breaking Changes

- **(None. Drop-in upgrade.)** The EncryptionMode port is backward-compatible: the zero value of the new field means Off, which is exactly today's behavior, and nothing in the fleet enables Post-Quantum Encryption today.

## Highlights

> [!IMPORTANT]
> **Encryption becomes tri-state, and consumers can finally refuse plaintext** (#350). Upstream replaced the boolean `Encrypt` with Off/Opportunistic/Required. The fork's default behavior is unchanged (Off), but under `Required` the consumer fails closed instead of silently establishing a plaintext session — the property that makes the setting worth having. The rekey-continuity fix in this port also closes a plaintext window that existed in the default Opportunistic mode.

> [!IMPORTANT]
> **`urnet-docker exec` stops eating your flags** (#349). The old parser silently dropped unknown leading flags meant for the inner command, made `--help` a no-op before the separator, and panicked on a trailing flag without a value. `--` now means what it means in docker and ssh, unknown flags fail loudly, and the happy path is covered by 25 test cases.

> [!CAUTION]
> **The hub dashboard's Grade column is a new metric — it is not the Score column.** The existing Score column is the hub-side traffic composite (`win_pct × ln(1+traffic)`). The new A-F Grade column comes from the provider's grading pipeline (the same tier letters the provider logs and stores). They measure different things and are labeled separately; do not compare them directly.
