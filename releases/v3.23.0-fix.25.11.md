# 🧹 v3.23.0-fix.25.11 — Auth Failure Proxy Cleanup

> **TL;DR** New `proxy remove-dead --auth-failures=N` flag to remove proxies exceeding a per-address authentication failure threshold. Uses a 250/day rate limit to prevent fleet-wide churn. Self-healing: skips proxies currently up. Also fixed a stale auth command reference in `AI.md`.

---

## ✨ `proxy remove-dead --auth-failures=N`

Auth errors per-proxy are now tracked in `proxy.state` and exposed to the cleanup pipeline.

- **`--auth-failures=N`** — removes proxies exceeding N auth failures per day (rate-adjusted for uptime). Only targets proxies not currently up — if a proxy recovers, it's automatically skipped.
- **`--degraded` now auto-includes auth-failing proxies** — `--degraded` also catches proxies with ≥250 auth failures/day.
- **Health report** now shows an `AUTH ERRS` column.

```bash
urnet-tools proxy remove-dead --auth-failures=100 --preview
urnet-tools proxy remove-dead --auth-failures=100 --yes
```

## 🐛 Self-Healing Skip

The `--auth-failures` flag now skips proxies that are currently up and authenticated — a proxy that recovered on its own won't be removed just because it had a bad streak earlier.
