# v3.23.0-fix.35.7

**Released:** 2026-11-08.

Previous release: [v3.23.0-fix.35.6](https://github.com/full-bars/urnetwork-3.23-fix/releases/tag/v3.23.0-fix.35.6).

I made updates use the newer tool for verification when it is available. I also added a second way to let the extender use TCP 443 and made several installer failure paths clearer.

Legend: **[redeploy]** needs the new provider, tool or container image. **[installer]** needs the updated installer or script. **[no redeploy]** covers documentation, CI and tests.

## Quick start

Install on Linux or macOS:

```sh
curl -fSsL https://install.fullbars.xyz | sh -s -- install
```

On FreeBSD, run the installer as a non-root service account with sudo:

```sh
fetch -qo - https://install.fullbars.xyz | sudo sh -s -- install
```

On Windows, use PowerShell:

```powershell
irm https://dl.fullbars.xyz/install-win.ps1 | iex
```

Run the provider in Docker with a persistent volume and a single-use auth code from https://ur.io:

```sh
docker run -d --name urfix --pull always --restart unless-stopped --cap-add NET_ADMIN --cap-add NET_RAW --sysctl net.ipv4.ip_forward=1 -e AUTH=authcode -e AUTHCODE='YOUR_AUTH_CODE_HERE' -v urnetwork_data:/root/.urnetwork ghcr.io/full-bars/urnetwork-3.23-fix:latest
```

This release is the provider line. For miner setup, use the separate miner release and its instructions; this workflow does not publish a miner image.

## What changed

### Updater and extender [redeploy]

- When a newer tool is available, `urnet-tools update` installs it first and runs it again to update the provider. The second run keeps the target and prior approval. If the tool install or rerun fails, the current tool continues the update. The environment marker `URNET_TOOLS_UPDATE_REEXEC` prevents a loop.
- If the updater cannot read the running provider image, it explains this once and asks the provider for its version. Port-443 file permission can cause this; it is not itself proof of a failed handoff.
- On Linux, `urnet-tools extender setup` offers a system-wide setting as an alternative to the binary's port-443 file capability, including on an already configured host. It writes `net.ipv4.ip_unprivileged_port_start=443` to `/etc/sysctl.d/99-urnetwork-extender.conf`. Any local user can bind ports 443 and above. Setup backs up an existing drop-in with its mode to `/etc/sysctl.d/99-urnetwork-extender.conf.pre-urnetwork` and prints a recovery command that restores it; recovery deletes the drop-in only if setup created it. If the prior live value is unknown, recovery prints the exact sysctl check and asks the operator to set the distribution's value (usually 1024) instead of guessing. A low live value alone is not counted as configured unless a sysctl configuration file persists it. Sudo reruns carry an exact provider selector and refuse a changed target. Setup warns if the binary retains a capability and offers removal only with separate terminal consent as root when no other capabilities are present. Restart or hand off the provider after removal. `urnet-tools extender status` reports the route and warns about a lingering capability.
- When that system setting is active, the updater skips capability checks and does not print a setcap warning. When it rolls back to a binary that needs a simple systemd unit, it also demotes `Type=notify-reload` units.

### Installer [installer]

- Restart confirmation reads the terminal even when the installer arrives through a pipe. Without a terminal it stops and tells you to use `-y`. Approval is carried through sudo and command dispatch.
- OpenRC install tree preparation is checked before service installation. A failure stops the install. If a systemd restart fails after replacement, rollback attempts to restore the previous unit as well as the binary and reports failures.
- The optimizer tracks completed, skipped and failed operations. More post-swap, capability, state-directory and logrotate failures name the failure and recovery command. Some failures remain unchecked; see the limits below.

### Documentation [no redeploy]

- The release notes, changelog, fork notes and guides describe the update order, port options and remaining limits.

## Known limits

- Updating directly from 35.5 with the port-443 capability can still report a false failure once: that update is run by the old tool. Run `urnet-tools self-update` first to avoid it.
- The update from 35.6 to 35.7 uses the old order; the 35.6 verification check already handles an unreadable image. The new tool-first order applies to subsequent updates when a newer tool is available.
- Some installer cleanup errors remain suppressed. The legacy shell optimizer also suppresses some ZRAM package and service errors; it checks whether ZRAM is active and tries a manual fallback, but its success summary does not prove each step succeeded.
- Alpine BusyBox `find -delete` in OpenRC tree preparation has not been verified. The installer-matrix workflow runs on matching tags; openrc-smoke runs on main, pull requests, a schedule or manual dispatch, not on tags.
- The non-root OpenRC sudo path has not been verified on a real host. The installer writes `.version` after the root-owned tree preparation without checking that write.
- The RAM log fix has not been verified in a full two-process HotSwap on a real host.
