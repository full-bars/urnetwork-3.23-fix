## What's New

### Hub TLS with Cert Pinning (PR [#186](https://github.com/full-bars/urnetwork-3.23-fix/pull/186))

The hub now supports HTTPS with trust-on-first-use certificate pinning.

**Hub side:**
- Binary accepts `-tls-addr` flag (default `:8443`, set via `URNETWORK_HUB_TLS_ADDR`)
- Auto-generates ECDSA P-256 cert on first boot
- `/api/cert` endpoint exposes SHA-256 fingerprint for TOFU verification

**Provider side:**
- `hub.pin` file stores the expected fingerprint
- `report_url` file stores the TLS URL
- Bandwidth reporter verifies cert before each report

**`urnet-tools hub` commands:**
| Command | What it does |
|---|---|
| `hub init` | Enables TLS, restarts, prints fingerprint + firewall hint |
| `hub link https://host:8443` | Fetches fingerprint, pins it, sets report URL |
| `hub unlink` | Removes pin, reverts to plain HTTP |
| `hub test [url]` | Verifies pinned fingerprint matches (openssl/curl) |
| `hub open-port <port>` | Detects firewalld/ufw/iptables/nftables, prints sudo command |
| `hub update [-f] [-t tag]` | Transactional binary update with automatic rollback |

### Live Hub Heartbeat + SSE Push (PR [#187](https://github.com/full-bars/urnetwork-3.23-fix/pull/187), [#188](https://github.com/full-bars/urnetwork-3.23-fix/pull/188))

**Problem:** Providers report every 5-15 minutes, making dashboard stats feel stale.

**Solution:** A lightweight in-memory heartbeat endpoint + Server-Sent Events push.

**`/api/heartbeat` (provider → hub):**
- 15s default cadence (configurable via `HEARTBEAT_INTERVAL` env)
- Carries: node_id, Mbps RX/TX, clients, connections, uptime, memory
- Per-proxy status + contract counters only if changed since last tick
- Zero DB writes — updates in-memory node state only

**`/api/events` (hub → dashboard):**
- `GET /api/events` pushes `data: refresh` when heartbeats/reports arrive
- Dashboard subscribes via `EventSource`, re-fetches immediately
- 30s poll remains as backstop for environments where SSE is stripped/buffered
