## Autonomous proxy recovery + outage leak hardening

This release combines two independent fixes shipped this week.

### Autonomous proxy recovery (new in fix.11)

Proxies with dead or offline endpoints were getting stuck in exponential backoff indefinitely, never self-recovering without a provider restart.

- **Hourly recovery pulse**: every 60 minutes the provider wakes all stalled transports and proxies, giving them a fresh connection attempt without requiring a restart.
- **Exponential backoff on strategy selection** (`net_http.go`): the connection strategy layer now backs off between failed attempts (5s → 10s → ... → 1h cap) and resets on successful connection or pulse.
- **Dialer health reset on pulse**: previously-blacklisted routes get a clean slate on each pulse, so endpoints that came back online are rediscovered automatically.
- **P2P backoff**: P2P transports now use the same backoff and pulse integration.

Healthy connections are unaffected — the pulse is ignored by transports that are currently connected.

Supersedes the `v3.23.0-beta.1 (Automated Proxy Recovery)` pre-release.

### Outage data leak hardening (fix.10, included)

During backend API outages, the provider was leaking huge amounts of bandwidth through two control-plane retry storms. Combined with the resend cap from fix.9, these changes structurally prevent the leak.

- **Transport reconnect backoff** (`transport.go`): `runH1` and `runH3` now apply exponential backoff on consecutive auth failures — 5s → 10s → 20s → 40s → 60s cap. Clears immediately on successful reconnect.
- **Contract creation gated during outages** (`transfer.go`): When the backend is unreachable, contract creation API calls are skipped entirely. Retry poll interval raised from 5s to 30s while degraded. Resumes immediately on recovery.
- **Reliable degraded state detection** (`transport.go`, `transfer_contract_manager.go`): New `lastBackendFailNano` signal updated on every failure (not rate-limited), eliminating false-clear windows at log-suppression boundaries.

Normal operation is unaffected — all changes are gated behind `isBackendDegraded()` which only activates after real backend failures.
