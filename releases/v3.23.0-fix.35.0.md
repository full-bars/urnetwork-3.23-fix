# v3.23.0-fix.35.0

**Status:** ready to cut. Nothing is tagged or pushed. Base tag `v3.23.0-fix.34.3`. Head: `main` as of the merge of PR 977 (`badc2a978`). This version supersedes the 34.4 draft, which was staged but never tagged; every entry it carried is here.
**Sourcing:** condensed from the merge commits and PR bodies in this window, and checked line by line against the delta in the pre-release review (progress entry #4713). Not yet confirmed on a live node.

Legend: **[redeploy]** needs the built artifact redeployed. **[installer]** needs the installer or unit refresh. **[no redeploy]** docs, CI or tests only.

## Extender serving role

- **A provider can serve as an extender** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/971>). `URNETWORK_EXTENDER=auto|on|off`, off by default. When on, the provider binds tcp 443, quic 443 and dns 4053, and forwards client streams only to the hosts named in `URNETWORK_EXTENDER_ALLOWED_HOSTS`; with that list unset every forward is refused, and the ready line says so instead of leaving a serving role that silently sends nothing. The role renders its carriers, listeners and relayed bytes on `/metrics`, logs one ready line and each transition instead of repeating a status dump, and logs a refusal at most once a minute with the number it stands for. The DNS answer path is bounded to 512 bytes or the query's advertised EDNS size, so a spoofable source cannot use the forwarder as a reflection amplifier, and the privileged-port widening no longer breaks the whole listen when port 53 already carries quic.

## Data path

- **Egress TTL realism, the h3 datagram handshake, redirect scoping and DoH dial visibility** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/976>). Egress TTL realism ships inactive: `shadow` measures what the provider's TTL would be and leaves packets unchanged, `mirror` sets it on new flows, and the zero mode does nothing and says nothing. The h3 datagram auth response is negotiated on the real handshake instead of only in tests, so an older peer that expects the compatibility form is accepted. Redirect policy is scoped per hop. A failed DoH dial now logs, once per path per interval, with no allocation on the success path.

## Subsystems

- **The security generator and the control API refuse less silently** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/975>). The generator refuses to write unformatted source and stages both outputs next to their targets, so an interrupted run cannot truncate the live file. It bounds a feed response, reports a truncated scan instead of counting it as clean, ingests CIDR rows, and enforces a per-family floor. The control API keeps a server refusal that carries no pack instead of dropping it as malformed, and tolerates a nil context in the auth observation helpers.

## Reliability

- **URL proxies launch again when the warmup hold expires** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/973>). On a node whose registered pool contains proxies that never authenticate, the warmup ratio never reached its 90% gate, so the only exit was the 60-minute backstop: every qualified URL-sourced proxy sat deferred for an hour while the running pool drained, and the URL fetcher was parked behind the same flag, so the list never refreshed either. LA6 showed this as `53 deferred (warmup=53)` for a full hour and then one launch burst at the backstop. The hold is now bounded to five minutes from the provider's start in both the reload gate and the fetcher, and the reload fires when the grace expires on its own clock, so replacements launch a few minutes after a start instead of an hour later.

## Operator tools

- **The trim cap is visible** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/965>, <https://github.com/full-bars/urnetwork-3.23-fix/pull/966>). `urnet-tools proxy trim` with no argument reports the cap in force and which source set it (operator, OOM or thrash), the configured pool size before the cap, how many proxies the cap holds back, and the live up/connecting/dropped/dead counts. `urnet-tools status` shows the same as a `trim` row whenever a cap applies, so a capped node does not read as a small one. The provider's effective cap wins over the `proxy_trim` file, and trim state is reported only from a complete pool, so an unreadable `proxy_url.json` can no longer understate the configured pool and clamp the status denominator below the running count.
- **The TLS ClientHello is a runtime switch** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/972>). `urnet-tools set tls-hello on|off` makes the normal and resilient dialers present Chrome's TLS ClientHello instead of Go's on new connections, live and without a restart, with `URNETWORK_TLS_HELLO` as the startup default. It affects new connections only: an open session keeps the handshake it made and follows the setting the next time it dials. The Chrome hello is **off by default** while it soaks, so a box that never sets the key keeps Go's hello exactly as before; a persisted `off` beats `URNETWORK_TLS_HELLO=on`, and clearing the key hands the decision back to the environment.

## Observability

- **The lifetime counters say when they began** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/967>, <https://github.com/full-bars/urnetwork-3.23-fix/pull/969>). The lifetime store persists a start stamp, written once when the store is created and never rewritten, and the `[lifetime]` and `[pqe]` lines read `all-time (since 2026-10-22 13:04 PDT)`. A store written before this release keeps its totals but has no recorded start, so its start is pinned to the load time and the line says the start is approximate and the totals include earlier history instead of inventing a date. The scrape gains `urnet_lifetime_start_timestamp_seconds` and `urnet_lifetime_start_approximate` (0 exact, 1 approximate).
- **Contract discovery and path building are measurable** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/977>, <https://github.com/full-bars/urnetwork-3.23-fix/pull/971>). `/metrics` gains `urnet_contract_attempts_total{result}` and `urnet_contract_denied_total{reason}` so a box that finds no data path says which side refused and on what grounds, `urnet_path_channels_total{window}`, `urnet_path_channel_connects_total{window}` and `urnet_path_channel_connect_millis_total{window}` so each window's building and its time to a usable provider are visible, and `urnet_extender_requests_total{service}` with `urnet_extender_refused_total{stage}` for the serving role. The contract counters log a refusal once a minute with its count, and a channel logs one line when it first connects: `[path] quality channel connected in 240ms (provider 1a2b3c4d)`.

## CI

- **The live-numbers job signs its commits** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/968>). The scheduled SN25 cost-table refresh imports the CI signing key and refuses to push an unsigned commit. It also runs on pushes to `main` and twice an hour off-peak, because GitHub starts scheduled jobs best effort and can skip them, and the wiki mirror runs every time now, not only when the numbers changed.
- **The smoke and soak client-id checks restart the provider for real** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/955>, <https://github.com/full-bars/urnetwork-3.23-fix/pull/957>). The checks used `urnet-tools hot-restart -f` and compared one decoded JWT; they now stop the provider with SIGTERM, start it again, and diff the full stored client-id list, and they fail when the store has no ids to compare instead of passing vacuously.

## Documentation

- **The pages link to the wiki** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/963>). Documentation links point at the wiki pages instead of raw markdown paths, and the SN25 cost table shows dollar figures and explains what the oracle row means (<https://github.com/full-bars/urnetwork-3.23-fix/pull/960>).
- **The phantom auto-update commands are gone** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/961>). The guides named `urnet-tools auto-update-enable` and `auto-update-disable`, which do not exist; they now say `urnet-tools auto-update daily|weekly|monthly|off`.
- **The hot-restart prune rule is documented correctly** **[no redeploy]**. The store prunes entries whose `minted_at` is older than 30 days at load time, not entries whose slot has not reconnected for 30 days, and the page now says so.

## Caveats

- The extender role is off by default and has not served live traffic yet; the first node to enable it is the canary.
- Egress TTL realism ships inactive. `mirror` changes what leaves the box, so it needs a deliberate switch on one node before any wider use.
- The five-minute warmup grace is proven by unit tests (`TestURLWarmupHold`, `TestReload_WarmupGate_GraceExpiresURLProxies`) and a full provider test pass. The LA6 confirmation has not been recorded yet.
- With an operator trim cap set above the configured pool, the trim report prints the cap and then `no cap applied` on the next line. The cap is not binding in that case; the wording will be reconciled later.
