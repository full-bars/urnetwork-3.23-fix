# v3.23.0-fix.35.0

**Released:** 2026-10-23. **Previous release:** `v3.23.0-fix.34.3`.

This release brings the newer upstream feature set to the fork. The extender v2 stack lands as a work in progress that does not activate yet, so no provider serves as an entry relay. The provider can dial through a VLESS/Reality carrier, the TLS hello can be switched to a Chrome-shaped one, the egress path consults the ad and tracker blocker, and a group of dataplane fixes, reliability fixes and observability additions come with it. The extender, the Chrome hello, egress TTL realism and the blocker are off by default, so a node that changes nothing behaves as before apart from the fixes.

Not yet confirmed at fleet scale: the build is running on one canary node and has not been rolled out further.

Legend: **[redeploy]** needs the built artifact redeployed. **[installer]** needs the installer or unit refresh. **[no redeploy]** docs, CI or tests only.

## Extenders

- **The extender v2 stack lands as a work in progress that does not activate yet** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/971>). No provider serves as an entry relay: nothing registers the host or sends clients to it, and activation is tracked in `urnetwork/connect#230`. The extender library and server land with signed records, a trust chain, a directory and feed client, and the tcp, quic and dns carriers. The provider-side serving role is opt-in through `URNETWORK_EXTENDER`, runs on a direct slot only, and binds tcp 443 first, then quic 443 and dns 4053; a failed tcp bind retries no faster than every three minutes. The role keeps its own identity seed at `.provider.extender.key`, reports status in the log, and exports `urnet_extender_*` Prometheus metrics. The directory gains the pinned-candidate accessor, so a strategy pinned to one extender address dials it without a hold counting against the pool.
- **A VLESS/Reality client carrier** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/971>). VLESS connections run over tcp, TLS, Reality, WebSocket and HTTP upgrade, with share-link import and export.

## Egress blocking

- **The packet path consults the ad and tracker blocker** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/974>). The egress decision now consults the blocker before the port-25 local route, the SMTP guard, the local security bypass and the security policy inspect, and a hit drops the packet. The host lookup runs only when the ip range misses, so the common case costs one range lookup. The blocker is installed through `SetBlocker` by the device and shared with the dns path, and its own enable and disable take effect immediately: nothing installs one on this fork yet, so traffic is unaffected until that wiring lands. The shipped block tables are unchanged.

## Fingerprinting

- **A switchable Chrome ClientHello, with a drift harness** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/972>). The dialer can emit a Chrome-shaped TLS hello. It is off by default: `urnet-tools set tls_hello on` flips it live for new connections without a restart, `URNETWORK_TLS_HELLO` sets the startup default, and a persisted off beats the env. Open connections keep the handshake they made. The harness pins golden TLS ClientHello and QUIC Initial values and fails a test when the dialer drifts from them. The committed golden is synthetic uTLS Chrome_133 output from our own code, not a capture of real Chrome, so the gate proves parity with the uTLS reference; a real-capture step replaces it later.

## Dataplane leaves

Four additive leaves from the newer dataplane generation (<https://github.com/full-bars/urnetwork-3.23-fix/pull/976>):

- **Egress TTL realism** **[redeploy]**. The provider's egress TTL can be applied or shadowed on the socket, with counters for both modes. It ships inactive: the zero mode disables it entirely, and only an explicit shadow or mirror mode turns it on.
- **H3 datagram auth compatibility** **[redeploy]**. The connection negotiates the authentication shape the peer accepts. The negotiator existed but was never called; it is wired into the transport now.
- **Redirects are scoped to one request** **[redeploy]**. A redirect can no longer leak its headers or method into a later attempt.
- **DoH dial observation** **[redeploy]**. What the resolver dial observed is recorded, behind the dial context settings.

## Upstream pieces

- **The blocklist generator is a Go program** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/975>). It replaces the shell pipeline, preserves CIDR masks, validates octets, parses the abuse.ch csv feeds, enforces per-feed minimum counts and subtracts reserved space. It runs only through `go:generate`, is never invoked by the build, and refuses a target without a do-not-edit marker unless forced. The existing `gen.sh` and `urls.txt` stay in place.
- **Lag tickets and measurement ids** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/975>). The protocol gains the lag ticket and report messages, and extenders are named by measurement id. Nothing emits them before peers speak the protocol.
- **API additions** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/975>). Auth request observations, opt-in through the request context. A control-result error reply is treated as a refusal. Wallet mapping consent calls. The host resume watch (`host_sleep.go`) is not part of this group; the extender stack above owns it.

## Reliability

- **URL proxies launch again when the warmup hold expires** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/973>). On a node whose registered pool contains proxies that never authenticate, the warmup ratio never reached its 90% gate, so the only exit was the 60-minute backstop: every qualified URL-sourced proxy sat deferred for an hour while the running pool drained, and the URL fetcher was parked behind the same flag, so the list never refreshed either. LA6 showed this as `53 deferred (warmup=53)` for a full hour and then one launch burst at the backstop. The hold is now bounded to five minutes from the provider's start in both the reload gate and the fetcher, and the reload fires when the grace expires on its own clock, so replacements launch a few minutes after a start instead of an hour later.

## Operator tools

- **The trim cap is visible** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/965>, <https://github.com/full-bars/urnetwork-3.23-fix/pull/966>). `urnet-tools proxy trim` with no argument reports the cap in force and which source set it (operator, OOM or thrash), the configured pool size before the cap, how many proxies the cap holds back, and the live up/connecting/dropped/dead counts. `urnet-tools status` shows the same as a `trim` row whenever a cap applies, so a capped node does not read as a small one. The provider's effective cap wins over the `proxy_trim` file, and trim state is reported only from a complete pool, so an unreadable `proxy_url.json` can no longer understate the configured pool and clamp the status denominator below the running count.

## Observability

- **The lifetime counters say when they began** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/967>, <https://github.com/full-bars/urnetwork-3.23-fix/pull/969>). The `[lifetime]` and `[pqe]` lines printed an `all-time` total with no start date, so a store that began this morning and one counting for months read the same. The lifetime store now persists a start stamp, written once when the store is created and never rewritten, and the lines read `all-time (since 2026-10-22 13:04 PDT)`. A store written before this release keeps its totals but has no recorded start, so its start is pinned to the load time, saved at once so an idle node does not re-pin a later date on every restart, and the line says the start is approximate and the totals include earlier history instead of inventing a date. The process-scoped figures, `since-start` on the `[pqe]` line and `lifetime_recovered` and `lifetime_lost` on `[health][proxies]`, now carry their own start time, so the two scopes can no longer be confused. The scrape gains `urnet_lifetime_start_timestamp_seconds` and `urnet_lifetime_start_approximate` (0 exact, 1 approximate).

- **Contract discovery reports outcomes and refusal reasons** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/977>). The only contract metrics were acquired and denied, so an operator asking why no data path appears had to guess. The metrics now carry a `result` label on `urnet_contract_attempts_total` and a `reason` label on `urnet_contract_denied_total`, and a rate-limited log line names the reason the provider gave.

## Data

- **The IP security and blocker tables are refreshed** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/959>). Both generated tables sync from upstream's 5485774e snapshot: the blocked-host table moves from 164,212 to 164,225 entries, and the CFAA prefixes from 46,733 to 47,632 IPv4 and 597 to 619 IPv6. Data only.

## CI

- **The live-numbers job signs its commits** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/968>). The scheduled SN25 cost-table refresh imports the CI signing key and refuses to push an unsigned commit. It also runs on pushes to `main` and twice an hour off-peak, because GitHub starts scheduled jobs best effort and can skip them, and the wiki mirror runs every time now, not only when the numbers changed.
- **The smoke and soak client-id checks restart the provider for real** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/955>, <https://github.com/full-bars/urnetwork-3.23-fix/pull/957>). The checks used `urnet-tools hot-restart -f` and compared one decoded JWT; they now stop the provider with SIGTERM, start it again, and diff the full stored client-id list, and they fail when the store has no ids to compare instead of passing vacuously.

## Documentation

- **The pages link to the wiki** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/963>). Documentation links point at the wiki pages instead of raw markdown paths, and the SN25 cost table shows dollar figures and explains what the oracle row means (<https://github.com/full-bars/urnetwork-3.23-fix/pull/960>).
- **The phantom auto-update commands are gone** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/961>). The guides named `urnet-tools auto-update-enable` and `auto-update-disable`, which do not exist; they now say `urnet-tools auto-update daily|weekly|monthly|off`.
- **The hot-restart prune rule is documented correctly** **[no redeploy]**. The store prunes entries whose `minted_at` is older than 30 days at load time, not entries whose slot has not reconnected for 30 days, and the page now says so.

## Caveats

- The extender role is opt-in and new. Its tests cover the library (103 tests) and the role (11 tests), and one live run served tcp 443, quic 443 and dns 4053 on a test host. Nothing here proves it at fleet scale, and the default is off.
- The Chrome hello golden is synthetic uTLS output, so the harness proves parity with uTLS, not with real Chrome. The switch is off by default.
- Egress TTL realism ships inactive (zero mode), and the ad/tracker blocker has no live installer on this fork yet: both are wired but inert until their switches are used or the device installs the blocker.
- The five-minute warmup grace is proven by unit tests (`TestURLWarmupHold`, `TestReload_WarmupGate_GraceExpiresLaunchesURLProxies`) and a full provider test pass. The LA6 confirmation (the one-hour deferral becomes a launch a few minutes after the start) has not been recorded yet.
- With an operator trim cap set above the configured pool, the trim report prints the cap and then `no cap applied` on the next line. The cap is not binding in that case; the wording will be reconciled later.
