# v3.23.0-fix.33.2

> [!NOTE]
> Docker-only patch. The provider and `urnet-tools` binaries are identical to `v3.23.0-fix.33.1`; no provider behavior changes.

The 33.1 image never published. Its tag's copy of the image workflow failed before the build-and-push job could run:

- the Pelican egg check still grepped `docker/scripts/start_nightly.sh`, but the 33.1 entrypoint consolidation moved `func_check_update` into `provider_common.sh`, so the check read a thin wrapper and failed;
- the provider package needs about 446s under `-race`, and the CI package timeout was 600s, so a slower runner timed out mid-package.

Because a tag is immutable, the fix could not be applied to 33.1. This patch carries the two CI fixes (the same change that landed on `main` as #885) plus the post-33.1 documentation commits, so the tag can produce and push the image. Releases up to 33.1 are unaffected; their binaries are the same.

## What's Changed

- ci: fix the nightly pelican check and raise the provider test timeout (`0c9c39529`)
- docs: the dual-stack page and its README index entry (`8a200050c`, `d0c6866f0`)

**Full Changelog**: <https://github.com/full-bars/urnetwork-3.23-fix/compare/v3.23.0-fix.33.1...v3.23.0-fix.33.2>

## Deploy Notes

1. No operator action beyond the normal update. Docker users can pull `ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.33.2`.
2. Native installs already on 33.1 do not need this patch; the binaries are identical.
3. The shakedowns that failed on 33.1 did so only because the image was missing; they run against this tag's image.
