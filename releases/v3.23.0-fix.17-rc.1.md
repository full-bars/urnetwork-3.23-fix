### Installing / Testing

**Linux (bare metal / VM):**
```sh
curl -fSsL https://raw.githubusercontent.com/full-bars/urnetwork-3.23-fix/refs/heads/beta/scripts/Provider_Install_Linux.sh | sh -s -- install
```

**Updating an existing install to this RC:**
```sh
urnet-tools update -t v3.23.0-fix.17-rc.1
```

**Docker:**
```sh
docker pull ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.17-rc.1
```
```sh
docker run -d \
  --name=urfix \
  --restart=unless-stopped \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  -e URNETWORK_AUTH_CODE=YOUR_AUTH_CODE \
  -e HOST_HOSTNAME=$(hostname) \
  -v urfix_config:/root/.urnetwork \
  ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.17-rc.1
```

**Docker — useful commands:**
> [!TIP]
> Run these commands from your host to monitor the container's proxy health and traffic in real-time.

```sh
# View logs
docker logs -f urfix

# Proxy health (dead/degraded list + live event stream)
docker exec -it urfix proxy-health

# Proxy health state file
docker exec urfix cat /root/.urnetwork/proxy_health.state

# Proxy health event log
docker exec urfix tail -f /root/.urnetwork/proxy_health.log

# Proxy traffic (bandwidth + active clients per proxy)
docker exec urfix cat /root/.urnetwork/proxy_traffic.state
```

### What's New

**Per-Proxy Bandwidth Tracking**

The provider now tracks cumulative and real-time bandwidth per proxy — bytes sent and received, broken down into billable (user-attributed) vs. total (including protocol overhead). Updated every heartbeat cycle and persisted to `proxy_traffic.state` on the config volume (survives RAMLOGS). Readable at any time via:

```sh
urnet-tools proxy traffic          # Linux
docker exec urfix cat /root/.urnetwork/proxy_traffic.state  # Docker
```

Results are sorted by billable traffic descending, so your busiest proxies are always at the top:

**Active NAT Session Tracking**

The `[net][s]select` log now includes a `clients=N` counter per proxy line, showing the exact number of active multiplexed NAT sessions currently routing through that proxy:

```
[net][s]select: proxy[3] (172.98.64.194:1081) [fragment] success=6086 error=4 clients=7
[net][s]select: proxy[0] (185.220.101.47:1081) [normal] success=2221 error=11 clients=3
[net][s]select: proxy[4] (89.187.162.125:1081) [fragment] success=841 error=0 clients=2
[net][s]select: proxy[2] (45.134.212.68:1081) [normal] success=392 error=0 clients=0
```

> [!TIP]
> This makes it immediately obvious which proxies are under load vs idle, and helps identify proxies that are authenticated but not carrying client traffic.
