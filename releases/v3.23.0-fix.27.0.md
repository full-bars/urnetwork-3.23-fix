# v3.23.0-fix.27.0 — A-F Proxy Quality Tiers, Paid-List Grading, and a Provider-Aware urnet-tools in Go

This release is the biggest operator-facing one in the fork's recent history: the URL-source admission pipeline gets A-F quality tiers on top of the stage-1 gate, paid/file-list proxies finally get read-only grading instead of being invisible to the quality system, and the fleet ops tool `urnet-tools` is rewritten from shell/PowerShell into a single provider-aware Go binary — the tool that wiped the wrong provider's pools on 08-08 cannot exist anymore, because the new tool refuses to operate on an ambiguous target.

## 🗂️ What's New

- **A-F letter-grade proxy quality tiers** (#343): every URL-source proxy that survives the stage-1 gate is now assigned a letter grade (A >= 0.9, B >= 0.8, C >= 0.7, D >= 0.6, F < 0.6). Best-overall cache eviction keeps the highest-tier proxies when the cache is full; all sources' candidates pool into a single A-to-F admission funnel (best-first up to the cap); the fetch cycle probes only new addresses while the reaper's stale sweep refreshes cached grades; a per-cycle A-F grade breakdown is logged. Cross-source duplicates are probed once per cycle, and the eviction tie-break uses the grade score.
- **Read-only grading for paid/file-list proxies** (#344): proxies from `--proxy_file` / the internal config bypass the URL admission gate by construction and were previously invisible to the quality system. A background sweep now grades every non-URL proxy the box serves with the same stage-1 table probe on the same 1-3h stale cadence, persisting Score/Graded/Failed/LastGraded into `proxy.state`. Read-only by construction: grades never gate admission, never evict, never feed give-up/cleanup. Kill switch: `proxy_probe.json enabled=false` is a full skip.
- **Provider-aware `urnet-tools` rewritten in Go** (#345): the fleet ops tool is now a single Go codebase (`urnet-tools` for process/systemd, `urnet-docker` for containers) instead of the ~4000-line POSIX shell script plus a separate PowerShell variant. It discovers actual running providers (process scan + systemd units), identifies each by its JWT network identity, refuses ambiguous targets with an inventory table, and gates destructive ops behind a confirm prompt (`-f` for machines). All 25 legacy subcommands dispatch with verified parity.

## ⚠️ Breaking Changes

- **`urnet-tools` is now a Go binary** (#345). The migration is designed to be drop-in: the Go binary replaces the shell wrapper at the same path, and the installer keeps installing. The `.ps1` (Windows) and docker shell variants are deprecated and retired in a later phase. Operators with scripts calling `urnet-tools` subcommands should find them unchanged; operators on multi-provider boxes must now specify a target (`--unit` / `--user` / `--network` / `--network-id` / `--state-dir`) when the box is ambiguous — the tool refuses to guess.

## Highlights

> [!IMPORTANT]
> **URL-source proxies now carry an A-F grade, and the funnel admits best-first** (#343). On top of the stage-1 gate from 26.8, every admitted proxy is graded A through F, the cache evicts lowest-grade entries when full, and new candidates are admitted best-first up to the cap — so a full cache keeps its highest-quality proxies instead of whatever arrived last. The reaper refreshes stale grades on the 1-3h sweep, gated on the probe kill switch.

> [!IMPORTANT]
> **Paid/file-list proxies are finally graded — read-only** (#344). The box's quality system previously had no opinion on `--proxy_file` / internal-config proxies because they bypass the URL admission gate by construction. They're now graded on the same stage-1 table probe and the same stale cadence, and the grade lands in `proxy.state` (Score/Graded/Failed/LastGraded, omitempty — same field shape as the URL store). Structural safety: only the grade fields are written, and nothing in admission, eviction, give-up, or cleanup reads them — a graded F keeps serving exactly as it did before. `proxy_probe.json enabled=false` skips the sweep entirely.

> [!CAUTION]
> **`urnet-tools` no longer guesses which provider you mean** (#345). The legacy shell tool resolved its target from a hardcoded path with zero awareness that other providers exist on the box, so on a multi-provider machine it could act on the wrong provider entirely. The Go tool refuses: multi-provider box + no target = the command errors and prints the provider inventory. Destructive ops (`proxy clear`, `proxy remove --all`) print target + effect and require a confirm prompt; `-f`/`--yes` bypasses only the prompt, never provider selection. **Operators on multi-provider boxes must review their scripts** — a previously-"working" `urnet-tools proxy clear` that silently targeted the wrong install now fails loudly instead.
