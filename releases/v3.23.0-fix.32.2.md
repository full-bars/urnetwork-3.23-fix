# v3.23.0-fix.32.2

> [!NOTE]
> **First update after this release:** the audit ring loads on the new process and the old process flushes before it hands over, so `urnet-tools history` shows the update itself. On a node updated with `urnet-tools update -f`, the stream shows the handoff: on the spawned-candidate path (systemd, Windows) the successor writes its `start` at boot and merges the parent's `hotswap` after takeover, so the order reads `start` then `hotswap`; the Docker execve successor stamps `start` after the takeover, so it reads `hotswap` then `start`. Both orders end with the upgrade complete.

This release is about making the provider easier to understand and safer to operate: an audit trail that survives updates, a status line you can trust, a live view of what the node is doing, and an automated proxy-audit engine that parks junk proxies. It also fixes file-backed proxy management and makes the provider usable without a systemd unit.

## What's Changed

### Added

- **Audit ring now records lifecycle events** ([#668](https://github.com/full-bars/urnetwork-3.23-fix/pull/668)): `urnet-tools history` used to show only `set` and `clear` config changes. It now also records process start (with the version), the hotswap handoff, and control-socket shutdown. After an update you see the story: `hotswap` on the old process, then `start` with the new version on the successor.
- **Audit entries survive hotswap** ([#668](https://github.com/full-bars/urnetwork-3.23-fix/pull/668)): the old process flushed its audit ring at the handover point, before the takeover message, on every path (systemd, Windows, Docker). The new process then merges the ring from disk and deduplicates it, so the last commands you issued before an update are not lost. The old process also closes its control socket at that same point, so nothing accepted after the flush can disappear in its memory.
- **Live node snapshot and `urnet-tools top`** ([#664](https://github.com/full-bars/urnetwork-3.23-fix/pull/664), [#665](https://github.com/full-bars/urnetwork-3.23-fix/pull/665)): the provider keeps a cached snapshot of the node - billable rate with 10 minutes of history, clients and sessions, the proxy pool by status, pressure, memory, descriptors, the restart reason, and a flowing/idle/degraded verdict. `urnet-tools status` shows it as a live block, `status --json` prints it for scripts, and `urnet-tools top` is a full-screen live view. Older providers are handled: the block is skipped and only `--json` reports it as unavailable.
- **Restart reason** ([#664](https://github.com/full-bars/urnetwork-3.23-fix/pull/664)): `update`, `hotswap` and `restart` record why the provider is about to restart; the provider reports it after it starts, in the snapshot and as `urnet_restart_reason`.
- **Resource metrics and alert rules** ([#664](https://github.com/full-bars/urnetwork-3.23-fix/pull/664)): `urnet_mem_limit_bytes`, `urnet_rss_bytes`, `urnet_open_fds` and `urnet_fd_limit`; `UrnetworkNodeDown` and `UrnetworkRestartLoop` alerts on by default. See `docs/Monitoring.md`.
- **Automated proxy audit and quality enforcement** ([#666](https://github.com/full-bars/urnetwork-3.23-fix/pull/666)): the provider grades proxies every five minutes and parks ones that grade as proven junk. `urnet-tools proxy audit on|off|status|release` controls it live, `URNETWORK_PROXY_AUDIT=1` enables it at boot, and the status line reports parked and paused states honestly.
- **Control unitless providers** ([#669](https://github.com/full-bars/urnetwork-3.23-fix/pull/669)): a provider running without a systemd unit (a bare process or container) can be controlled directly - `status`, `config`, `logs` and `set/clear/get` work from the control socket, duplicate state-dir rows are deduplicated, and `urnet-tools get` reads a single setting.
- **File-backed proxy add and paste fixed** ([#663](https://github.com/full-bars/urnetwork-3.23-fix/pull/663)): comments and blank lines survive, duplicate entries are resolved under the shared lock, and keyed credentials are preserved.

### Changed

- **Provider status uses a sliding severity scale** ([#668](https://github.com/full-bars/urnetwork-3.23-fix/pull/668)): the systemd status line now reads `active` when 90% or more of the configured proxies are live, `partial` between 70% and 89%, `degraded` between 50% and 69%, and `critical` below 50% (including zero). The exact percentage always shows: `active: 1313/1367 proxies authenticated (96%)`. A node with a normal dead tail of proxies no longer reads as "partial" forever. The percentage is clamped at 100, and proxies parked by the audit engine are counted honestly.
- **Start entries persist immediately on normal boots** ([#668](https://github.com/full-bars/urnetwork-3.23-fix/pull/668)): only a hotswap successor holds its start entry in memory until the takeover merge. A regular boot keeps writing immediately, so a crash within thirty seconds cannot lose your start record.

### Maintenance

- **Security blocklist sync** ([#667](https://github.com/full-bars/urnetwork-3.23-fix/pull/667)): refreshed the content-filtering blocklist — a net reduction of about 6,400 IPv4 ranges and 32 IPv6 prefixes after upstream pruning.

## Deploy Notes

1. **No unit changes required**, unless you want the hotswap-capable setup (the standard installer unit works as-is; `urnet-tools update` migrates it when needed).
2. **`urnet-tools history` shows more.** Lifecycle entries are new; paging and the 1000-entry ring are unchanged.
3. **Proxy audit is opt-in.** It starts in observe mode; `urnet-tools proxy audit on` (or `URNETWORK_PROXY_AUDIT=1`) enables parking.
4. **`urnet-tools top` needs a snapshot-capable node.** Any provider at or above this release qualifies.
