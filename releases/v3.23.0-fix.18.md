## What's New in v3.23.0-fix.18

### Installing / Updating

**Binary (bare metal / VM):**
```sh
curl -fSsL https://raw.githubusercontent.com/full-bars/urnetwork-3.23-fix/refs/heads/main/scripts/Provider_Install_Linux.sh | sh -s -- install
```

**Updating an existing install:**
```sh
urnet-tools update -t v3.23.0-fix.18
```

**Docker:**
```sh
docker pull ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.18
```
```sh
docker run -d \
  --name=urfix \
  --restart=unless-stopped \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  -e URNETWORK_AUTH_CODE=YOUR_AUTH_CODE \
  -e HOST_HOSTNAME=$(hostname) \
  -v urfix_config:/root/.urnetwork \
  ghcr.io/full-bars/urnetwork-3.23-fix:v3.23.0-fix.18
```

### Proxy Hot-Reload (inherited from v3.23.0-fix.17)

> [!IMPORTANT]
> This version includes the full proxy hot-reload feature set. Proxies can now be added and removed from a running instance without a restart, preserving warm state across all live proxies.

**Reload from your proxy config:**
```sh
urnet-tools proxy refresh
```
Shows a diff of what will be added and removed, then asks for confirmation before applying.

**Remove dead or inactive proxies interactively:**
```sh
urnet-tools proxy remove-dead
```
Prompts separately for dead proxies (never authenticated) and inactive proxies (long offline), so you can choose what to remove independently.

**Monitor proxy health:**
```sh
urnet-tools proxy health
```

**View proxy traffic and active sessions:**
```sh
urnet-tools proxy traffic
```

### JWT Smart Refresh & Self-Healing Authentication

This release brings intelligent JWT token management with automatic refresh and recovery from authentication failures.

#### Automatic Token Refresh

The provider now validates JWT expiry **before making requests** using a configurable leeway window (default 30 seconds). If a token is detected as expired or close to expiration, it will automatically be refreshed before use:

- **Local expiry pre-check**: Validates token expiry time from the JWT payload (`exp` claim) before API calls
- **Graceful refresh**: Detects expired tokens early and refreshes them transparently
- **Positional token fallback**: If a token in the rotation fails, the provider retries with fallback tokens before declaring failure

#### Self-Healing on Authentication Failure

When the API returns an authentication error (exit code 78 / `ErrTokenInvalid`), the provider:

1. **Deletes the stale JWT** from the config volume
2. **Re-authenticates** using email/password credentials from environment variables (`USER_AUTH`, `PASSWORD`)
3. **Applies rate limiting** to prevent exhaustion loops: max 1 re-auth attempt per 5 minutes
4. **Continues operation** once a fresh token is obtained

This eliminates the need for manual intervention when authentication tokens expire unexpectedly. Docker and binary installs are both supported.

#### Setup for Self-Healing Auth

For self-healing to work, set your email and password in the environment:

```sh
export USER_AUTH=you@example.com
export PASSWORD=your-secure-password
```

Then restart the provider. On next authentication failure, it will automatically re-auth and resume service without interruption.

> [!NOTE]
> JWT refresh is always enabled. Self-healing re-auth only activates if you provide `USER_AUTH` and `PASSWORD` environment variables. Without those, the provider will still detect and report token expiry issues, but won't automatically re-authenticate.

### Proxy Telemetry Overhaul

Proxy session and wire metrics are now tracked at the dialer level, providing more granular visibility into connection patterns:

- **Session tracking**: Per-proxy session timers and max-age tracking
- **Wire metrics**: Detailed breakdown of active connections and their lifecycle
- **Bandwidth attribution**: Maintains per-proxy bandwidth totals (billable vs. total overhead)
- **Client multiplexing**: Shows active NAT session count per proxy

These metrics feed into `proxy_traffic.state` and `[net][s]select` log output.

### Bug Fixes & Improvements

- **Reset proxy state on `proxy remove --all`**: Clearing all proxies now properly resets the proxy list state
- **Code-78 handler**: Fast-path for authentication failures in startup scripts (shell self-healing)
- **Nil pointer guards**: Added safety checks in `provideAuth` result handling
- **Token expiry leeway**: Configurable 30-second buffer before token is deemed expired
- **GitHub Actions**: Bumped to Node.js 24-compatible versions
- **CI improvements**: Run all Go unit tests instead of hardcoded subset

---

### Proxy Stability

With hot-reload, automatic token refresh, and self-healing auth, the provider is more resilient to:
- Dead or degraded proxies (remove without restarting)
- Token expiration (automatic refresh + re-auth)
- Transient API failures (automatic retry with fallback tokens)
