## Highlights

### 🛡️ Message Pool Safety (Silent Bug Fixes)
Two latent bugs were found and closed during a scheduled code review of the memory subsystem.

- **Race condition in Share/Return:** When a buffer was returned to the pool while another goroutine was concurrently sharing it, there was a narrow window where the buffer could be handed out to a third goroutine before the share completed — silently corrupting in-flight packet data. The metadata reset is now performed under the lock.
- **Orphaned buffer leak in proto serialization:** `ProtoMarshalWithTag` grabbed a pool buffer based on an estimated size. If protobuf's actual output exceeded the estimate, the library allocated a fresh backing slice and abandoned the pool buffer without returning it. The call site now detects the reallocation and explicitly returns the orphaned buffer.

### 🔬 CI Hardening
- The test suite now runs `go test -short -race ./...` instead of a hand-picked allowlist. New tests are discovered automatically and Go's race detector runs on every build — the class of bug fixed above would be caught automatically going forward.
- Fixed `TestMessagePoolShare`, which had been silently failing since the pool gained its larger bucket sizes (16 KiB, 32 KiB, 64 KiB).
- Added a daily drift monitor that checks `full-bars/connect` for new commits to critical files and posts a Discord alert, so upstream bug fixes don't go unnoticed.

### 📊 Hub & Fleet Reliability
- Hub report failures are now visible: non-2xx responses log `[report] hub rejected report: <status>` instead of silently succeeding.
- Bandwidth reporter now starts with a random jitter up to one full interval, preventing a fleet restart from thundering-herd the hub.
