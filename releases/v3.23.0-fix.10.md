## Fix: outage data leak prevention

Supplements fix.9 with control-plane protections that significantly reduce data leakage when the backend API is unreachable.

**What was happening**: During API outages, the provider was leaking large amounts of data driven by two behaviors — transport reconnect loops firing at near-zero delay, and every active flow continuously hammering the dead API with contract creation requests (100+ flows × every 5s = thousands of concurrent HTTP goroutines against an unreachable backend).

### Changes

- **Transport reconnect backoff** (`transport.go`): `runH1` and `runH3` now apply exponential backoff on consecutive auth failures — 5s → 10s → 20s → 40s → 60s cap. Clears immediately on successful reconnect.
- **Contract creation gated during outages** (`transfer.go`): When the backend is unreachable, contract creation API calls are skipped entirely. Retry poll interval raised from 5s to 30s while degraded. Resumes immediately on recovery.
- **Reliable degraded state detection** (`transport.go`, `transfer_contract_manager.go`): New `lastBackendFailNano` signal updated on every failure (not rate-limited), eliminating false-clear windows at log-suppression boundaries.

Normal operation is unaffected — all changes are gated behind `isBackendDegraded()` which only activates after real backend failures.

**Note**: Awaiting validation in a production outage. The fix is structural — the leak mechanism is prevented by design — but real-world confirmation is pending.
