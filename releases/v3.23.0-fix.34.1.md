# v3.23.0-fix.34.1

> [!NOTE]
> This is a patch on v3.23.0-fix.34.0 with internal reliability and correctness fixes and one blocklist data refresh. There is nothing to configure and no operator action beyond the normal update and restart. Seven of the eight items are the v34 review follow-ups. Two of those change what a running box does: the plain-DNS rotation now stays consecutive within one lookup under concurrent load, and a 401 from the network refresh is now terminal instead of falling back to the legacy code-create flow. The other five change a comment, a test, a lint-level assignment, or code that no shipped setting reaches, so a default box behaves exactly as it did. The CFAA egress blocklist is refreshed to 40,924 IPv4 ranges and 546 IPv6 ranges, data only.

> [!IMPORTANT]
> The one behavior change worth knowing before you update is the network refresh. A 401 from `POST /auth/network-refresh` is terminal now. The provider no longer retries the legacy code-create flow with the same dead token, because that call would fail the same way and bury the real error. The refresh fails, the current JWT stays in place, and the next hourly pass retries. A 403 and the other 4xx refusals keep the existing fallback; 408, 425, 429, a 5xx and a transport error stay errors. The new-code item that could look alarming, the UDP poller batch return, is inert: no shipped setting sets `SocketReadShardCount`.

## What's Changed

### Fixed

- **Plain-DNS resolver rotation is per lookup, not per process** (`net_http_doh.go`): when DoH has no answer the resolver falls back to the configured plain-DNS servers, and the server it dials rotates one entry per resolver attempt. That counter was shared by the whole cache and advanced once per attempt, so a concurrent lookup could move it between another lookup's two attempts and both could land on the same address family. On a node that lacks that family each such lookup then pays a wasted or timed-out attempt, which is the exact cost the operator-paired v4-then-v6 list exists to avoid. Each lookup now seeds its own attempt counter from the shared one, and the shared counter advances once per lookup instead of once per attempt. Lookups still spread across the configured servers, and the attempts of one lookup walk consecutive entries. A dial with no per-lookup counter still uses the shared rotation. DoH stays primary, so only the plain-DNS fallback changes.
- **A network-refresh 401 is terminal and no longer falls back to code-create** (`provider/network_refresh.go`): the hourly renewal tries `POST /auth/network-refresh` first and keeps the legacy code-create and code-login flow for a server that predates the route (404, 405, 501) or refuses this request. A 401 is different: the legacy call would present the same dead token, fail the same way, and mask the real error under a second failure, so a 401 now ends the refresh with an error instead. The current JWT stays in place, and the next hourly pass retries. A 403 and the other 4xx refusals except 408, 425 and 429 still fall back. A 408, 425, 429, a 5xx or a transport error stays an error, as before.
- **The UDP shared-socket poller returns the rest of the batch when a drain is canceled** (`ip_udp_socket_poller.go`): a batch read from one socket holds one pooled buffer per fragment of an oversized datagram. When a canceled drain refused one packet it returned only that packet, so the packets behind it in the same batch were never returned to the message pool and stayed counted as taken. The drain now returns the remainder of the slice. The poller is still inert in production: no shipped setting sets `SocketReadShardCount`, so the shared socket lifecycle is never built. The same change documents that the blocking enqueue runs on the shard's single drain loop, so one slow receive callback couples every flow hashed to that shard, which the per-flow reader did not do. That head-of-line cost has to be measured before the setting is enabled anywhere. It also records that a zero-length datagram ends a drain harmlessly on a level-triggered backend.
- **Docker public-IP detection no longer masks curl's exit status** (`docker/scripts/provider_common.sh`): the identity report wrote `export URNETWORK_PUBLIC_IP="$(curl ...)"`, which is shellcheck SC2155, because `export` reports its own status and swallows the command's. The declaration and the assignment are separate now, followed by the export. The detected address and the log line are unchanged; only the exit status the script can see is curl's.

### Changed

- **The reliable handoff timeout default is 0, not -1** (`transfer.go`): `DefaultReceiveBufferSettings().ReliablePackHandoffTimeout` was -1, which reads as an unbounded wait, in a field no production caller reads yet. The receive path still selects its handoff wait with `ClientSettings.BufferTimeout`, and the selector that reads this field (`packHandoffTimeout`) has test callers only. The default is 0 now, and the comment states that the field is carried for a later wiring decision with no effect yet, and that a negative value must not become the default until the receive path is wired to it deliberately. Nothing about a running box changes.
- **Windows egress fail-closed behavior is documented** (`egress_windows.go`, comment only): a host with a v4 egress index and `index6 == 0` fails dials of IPv6 destinations, because the only attempted option is the v4 one, an `AF_INET6` socket rejects it, and the all-options-failed rule turns that into a dial error. That is intentional: such a host has no v6 index to pin to. The comment also records why the early return after the first successful option is safe for IPv4 destinations, where Go creates an `AF_INET` socket and the v4 option is the one that applies. No code path changes.
- **The normal strategy dial is pinned to the same egress control** (`egress_dial_sites_test.go`, test only): the normal strategy dial reaches the network through `ConnectSettings.DialContext` rather than a raw `tls.Dialer` shortcut. On the branch with no `DialContextSettings` and no `ProxySettings`, that path builds `NetDialer()` and calls `net.Dialer.DialContext` on it, so the socket still installs `DialControl` and the forced-interface egress control still runs. The new test asserts the control runs exactly once, on the live socket of a plain dial, against the strategy's own normal dialer, so dropping `NetDialer`'s `Control` field fails the build. No production change in this patch.
- **The CFAA egress blocklist is refreshed** to 40,924 IPv4 ranges (from 41,513) and 546 IPv6 ranges (from 575), data only. The table is a newer upstream sync; port policy and verdict semantics are unchanged.

## Deploy Notes

1. **Update and restart.** `urnet-tools update` picks up the release. No config change, no new setting and no migration. The native install path and the Docker entrypoint are unchanged.
2. **Nothing to enable or disable.** The reliable handoff default and the UDP shared-socket poller stay inert. No production caller reads `ReliablePackHandoffTimeout`, and no shipped setting sets `SocketReadShardCount`.
3. **Watch the network refresh on a long-lived box.** A 401 now ends the refresh with a `refresh FAILED: ... — keeping existing JWT` line after the `network-refresh` line, with no `step 1/3` lines, and leaves the token in place. That is the dead-token signal. Check the provider's stored network JWT rather than waiting for a code-create fallback that will not come.
4. **The CFAA refresh is data only.** The policy and the verdicts it produces are unchanged. No action.
5. **Rollback is the usual patch rollback.** Keep the previous provider binary and a state tarball, stop the unit, restore the binary, start.
6. **Docs.** The refresh rule is in [LOG_REFERENCE.md](../LOG_REFERENCE.md). The resolver rotation is in [Dual-Stack](../docs/Dual-Stack.md). The upgrade row and the refreshed version markers are in [advanced](../docs/guides/advanced.md), [H3 Auto](../docs/H3-Auto.md), [Installation](../docs/Installation.md), [Docker Deployment](../docs/Docker-Deployment.md) and [urnet-tools (Go)](../docs/urnet-tools-go.md).
