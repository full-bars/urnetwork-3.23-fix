## What's New

### 🧠 Core Networking Stability

**SendSequence no longer panics at resend cap** — PR [#201](https://github.com/full-bars/urnetwork-3.23-fix/pull/201) (HIGH)

When a packet hit the 16-resend limit, it was removed from the resend queue but left orphaned in `sendItems`. The next cumulative ack would hit `panic("Missing item")`, tearing down the entire send sequence and flushing pending contracts. **Fix**: park the item at `AckTimeout` horizon instead of dropping it.

**Contract rejection statuses now visible to callbacks** — PR [#202](https://github.com/full-bars/urnetwork-3.23-fix/pull/202) (MEDIUM)

`HandleControlFrame` constructed `ContractStatus` on Trust/Invalid errors but returned before dispatching. Locally-rejected and malformed contracts were invisible to `registerContractCallback` (metrics) and penalty logic. **Fix**: dispatch before the early return.

**Pool buffer leak on write timeout — v2** — PRs [#203](https://github.com/full-bars/urnetwork-3.23-fix/pull/203), [#206](https://github.com/full-bars/urnetwork-3.23-fix/pull/206) (MEDIUM)

`WriteDetailed` timeout/ctx-done/done branches had `MessagePoolReturn` commented out, stranding one shared pool ref per timed-out write. PR #206 removes the double-return regression from the first fix and applies `gofmt -w` to affected files.

**SOCKS5 proxy DNS death spiral** — PR [#189](https://github.com/full-bars/urnetwork-3.23-fix/pull/189)

Resolve target hostnames locally before passing to the SOCKS5 dialer, converting FQDN→IPv4. Prevents proxy infrastructure DNS from being blacklisted by upstream resolvers.

**Proxy warmup pileup on 2000+ proxy pools** — PR [#190](https://github.com/full-bars/urnetwork-3.23-fix/pull/190)

Three compounding fixes: DNS lookup cache (60s TTL), 30s SOCKS5 dial timeout, and `markProxyDown` now clears `h.connecting` state to unblock warmup progress tracking.

**Self-wake 100% CPU feedback loop** — PR [#191](https://github.com/full-bars/urnetwork-3.23-fix/pull/191)

`modeMonitor.NotifyAll()` gated on actual mode changes. Affected v24.27 through v24.32.

**Error propagation for silent failures** — PRs [#163](https://github.com/full-bars/urnetwork-3.23-fix/pull/163), [#165](https://github.com/full-bars/urnetwork-3.23-fix/pull/165)

Silently discarded errors in reload trigger and proxy probe paths now log warnings. Split error check from sequence comparison to prevent transient FS failures from spuriously triggering reloads.

**Port bounds check** — PR [#168](https://github.com/full-bars/urnetwork-3.23-fix/pull/168)

Fix CodeQL alert #11 — `strconv.Atoi` could produce values outside 0–65535 before `uint16` cast.

**Dead code cleanup** — PR [#200](https://github.com/full-bars/urnetwork-3.23-fix/pull/200)

`rttHeap.MinRtt()` returned arbitrary heap leaf instead of actual min. `MultiRouteSelector.setActive()` ignored its parameter. Both fixed.

### ⚡ Performance

**Message pool N-way mutex sharding** — PR [#207](https://github.com/full-bars/urnetwork-3.23-fix/pull/207)

Each size-class freelist (2048/4096/16384/32768/65536) is split into **16 internal shards** with independent mutexes, eliminating cross-proxy lock contention on the hottest allocation path. Shard index stored in a new metadata byte (bumped `MessagePoolMetaByteCount` 12→13). Round-robin selection at Get time; Return reads index back for correct routing. Rollback: `URNETWORK_MESSAGE_POOL_SHARD_COUNT=1`. ~60–80% contention reduction expected at fleet packet rates.

**Default resend queue 2→4 MiB** — PR [#204](https://github.com/full-bars/urnetwork-3.23-fix/pull/204)

Raised `ResendQueueMaxByteCount` to match the 4 MiB send window. ~2× per-client throughput ceiling on default-profile nodes.

**Contract ramp-up scale 2→3** — PR [#209](https://github.com/full-bars/urnetwork-3.23-fix/pull/209)

Adds an intermediate ramp step. Progression: 2 MiB → ~44 MiB → ~86 MiB → 128 MiB (was 2 MiB → ~65 MiB → 128 MiB). Reduces unused contract allocation on short-lived/probe connections by ~30%.

**RTT fill-fraction floor 0.5→0.7** — PR [#205](https://github.com/full-bars/urnetwork-3.23-fix/pull/205)

At ≥1s RTT, 90 MiB consumed per 128 MiB contract before renegotiation (was 64 MiB). Halves contract churn on high-latency (mobile/satellite) paths.

**Hot-path allocation optimizations** — PRs [#137](https://github.com/full-bars/urnetwork-3.23-fix/pull/137), [#138](https://github.com/full-bars/urnetwork-3.23-fix/pull/138), [#148–#150](https://github.com/full-bars/urnetwork-3.23-fix/pull/148)

Zero-alloc marshal via `frame_protobuf.go`, `ulid.Make()` replaced with allocation-free `NewId()`, closure hoisting in `ip_remote_multi_client.go`, `ip.go` IpPath caching + timer reuse, `transfer.go` safeAck by-value + timer reuse.

**Write pipeline buffer drain on cancellation** — PRs [#148–#150](https://github.com/full-bars/urnetwork-3.23-fix/pull/148)

Pooled buffers drained from write pipeline on cancellation. `SendBuffer.Ack` tries all candidate sequences instead of only the first.

### 🌐 Proxy Management

**Dual-stage SOCKS5 + API reachability probe** — PR [#152](https://github.com/full-bars/urnetwork-3.23-fix/pull/152)

Tests SOCKS5 compliance AND API reachability through the proxy on a single TCP connection. Background reaper retries every 5 min, evicts after 3 failures to 24h persistent blacklist.

**Escalating give-up backoff** — PRs [#129](https://github.com/full-bars/urnetwork-3.23-fix/pull/129), [#133](https://github.com/full-bars/urnetwork-3.23-fix/pull/133)

Backoff ladder: 15m → 30m → 1h → 2h → 4h → 8h → 16h → 24h. Permanent eviction after 10 cycles via persisted `proxy_url.json` blacklist. Enforced at launch time.

**File-before-URL launch priority** — PRs [#139](https://github.com/full-bars/urnetwork-3.23-fix/pull/139), [#140](https://github.com/full-bars/urnetwork-3.23-fix/pull/140)

File-based proxies launch before URL-sourced ones. URL fetcher waits for warmup completion before first fetch.

**Pattern-based proxy management** — PR [#183](https://github.com/full-bars/urnetwork-3.23-fix/pull/183)

`proxy remove --match=<substring>` with host-substring matching and persisted exclusion patterns. `proxy exclude` subcommand manages patterns.

**Multi-tier degraded proxy cleanup** — PRs [#145](https://github.com/full-bars/urnetwork-3.23-fix/pull/145), [#185](https://github.com/full-bars/urnetwork-3.23-fix/pull/185)

Runtime-configurable auto-cleanup with source filtering. `proxy remove-dead` supports `--source`, `--preview`, `--degraded` flags.

**Operator-curated proxy resilience** — PRs [#119](https://github.com/full-bars/urnetwork-3.23-fix/pull/119), [#120](https://github.com/full-bars/urnetwork-3.23-fix/pull/120)

Auth retry with slow capped backoff (5m→10m→15m) instead of permanent offline. URL requeue decoupled from reload engine via `time.AfterFunc`.

`io.LimitReader` (8 MiB HTTP / 64 KiB DoH) on all response body reads. JWT write failure now triggers `log.Fatal`.

Replaced monolithic `ip_security.go` with layered DPI pipeline. Packed binary-search blocklist (64,131 IPv4 + 214 IPv6 ranges). BitTorrent signature detection (BEP 3/5/15/29).
