# v3.23.0-fix.35.3

**Released:** 2026-11-01. **Previous release:** `v3.23.0-fix.35.2`.

This covers everything merged since `v3.23.0-fix.35.2` (PRs 1022, 1023, 1024, 1025, 1026 and 1029). The one-line-per-change list is the Unreleased section of [CHANGELOG.md](../CHANGELOG.md).

This window is one transport fix, one security fix, a blocklist refresh, a Docker updater fix and two docs fixes. The operator-visible change is that a proxy exit without IPv6 no longer costs a dial timeout on every request.

Legend: **[redeploy]** needs the built artifact redeployed. **[installer]** needs the installer or unit refresh. **[no redeploy]** docs, CI or tests only.

## Networking

- **A proxy exit without IPv6 no longer costs a timeout on every dial** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1024>). The provider now keeps a verdict per proxy carrier. After three consecutive v6 dial failures through one carrier, v6 is refused there for 15 minutes and the dial race goes straight to v4. When the cooldown ends one probe is let through: success clears the verdict, failure arms it again. A cancelled dial proves nothing and does not count. A v4 failure resets a streak that has not reached the threshold yet, because a proxy failing both families is a dead proxy and says nothing about its v6.
- **A failure streak expires** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1024>). Two failures in the morning and one at night used to reach the threshold. A streak now has to happen inside ten minutes. A failed probe is exempt: it re-arms the cooldown however long the cooldown was.

## Security

- **The h3 relay dial no longer carries proxy credentials into the log** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1025>). A malformed proxy address could reach the operator log with its userinfo or a token path attached, because the error was wrapped and the dial error repeats the address it was given. Both h3 messages now print the redacted address, and the failure is reported as a short class. Two tests pin that the user, the password and the token path cannot appear.
- **Blocklist refresh** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1022>). The CFAA and IP blocker tables are regenerated from their upstream feeds: 164,912 blocked hosts, up from 164,781. The CFAA table shrinks with this refresh, from 48,764 to 44,467 IPv4 ranges and from 539 to 271 IPv6 ranges, so fewer ranges are blocked than on 35.2.

## Installer

- **A FreeBSD backup that cannot be removed is now reported** **[installer]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1025>). The cleanup after a successful start used to ignore the result of the removal and forget the path. It now warns and names the file that is still on disk, so an operator can find it. The install itself is unaffected.

## Docker

- **The auto-update records the release tag as its version** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1023>). The in-place updater took the version it wrote to `version.txt` from the asset URL. A URL not shaped `/download/v<tag>/`, such as a mirror, a redirect or an API asset URL, was written to the file whole, so every later check saw an older version and downloaded the archive again. The updater now records the tag the release names, and it refuses to install a release that carries no tag.

## Docs

- **The deployment page says vnStat is retired** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1026>). The rest of the tree already said so. This page still walked an operator through enabling it, mapping port 8080 and mounting `/var/lib/vnstat`. The heading is kept unchanged so that links to its anchor keep working; no file in this repository links it.
- **The Docker deployment page gives the metrics port as 9100** **[no redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1029>). The page named port 9091 for `/metrics`. The endpoint binds the first free port from 9100 to 9103, so the page now matches it.
