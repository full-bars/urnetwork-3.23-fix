# v3.23.0-fix.35.3

**Released:** 2026-11-01.

This release fixes a slow IPv6 path, a log leak, a Docker updater loop and a FreeBSD installer gap. It also refreshes the blocklists and corrects several docs.

The provider can now avoid repeated timeouts on explicitly IPv6 dials through a proxy exit that cannot reach IPv6.

Legend: **[redeploy]** needs the new artifact on the node. **[installer]** needs the installer refresh. **[no redeploy]** is docs, CI or tests only.

## What changed

### Networking

- **Repeated explicit IPv6 failures through a proxy can be skipped** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1024>).
  - The provider remembers failures per proxy carrier only when the dial explicitly identifies IPv6, by network or address. It cannot infer the exit family when a hostname is passed to the proxy.
  - After three failed explicit IPv6 dials in a row through one carrier, the provider refuses further explicit IPv6 dials there for 15 minutes. A dial race can then fall back to IPv4.
  - When the cooldown ends, the provider lets one probe through. If it works, the provider clears the memory. If it fails, the cooldown starts again.
  - A cancelled dial proves nothing. It does not count.
  - An IPv4 failure resets a streak that has not reached three. A proxy that fails both families is dead. That says nothing about its IPv6.
- **Old failures no longer add up** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1024>).
  - Before, two failures in the morning and one at night reached the limit of three.
  - A gap over ten minutes between successive failures resets the streak. The full streak can span longer than ten minutes.
  - A failed probe is the exception. It always starts a new cooldown.
  - Result: an exit that keeps failing is tried again only after its cooldown ends.

### Security

- **The h3 relay dial error no longer shows proxy credentials** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1025>).
  - A malformed proxy address could reach the log with its user, password or token path.
  - Both h3 messages now print the redacted address and a short failure class.
  - Two tests check that the user, the password and the token path cannot appear.
- **Blocklists refreshed from upstream** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1022>).
  - The IP blocker holds 164,912 blocked hosts. It held 164,781.
  - The CFAA table shrank. IPv4 ranges went from 48,764 to 44,467. IPv6 ranges went from 539 to 271.
  - The provider blocks fewer CFAA ranges than in 35.2.

### Installer and Docker

- **The FreeBSD installer warns if it cannot delete the old binary backup** **[installer]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1025>).
  - After a good start, the installer removes the backup copy of the old provider.
  - Before, a failed removal passed without a word. Now the installer warns and names the file left on disk.
  - The install itself is not affected.
- **The Docker auto-update records the release tag as its version** **[redeploy]** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1023>).
  - Before, the updater took the version from the asset URL.
  - A URL not shaped `/download/v<tag>/` (a mirror, a redirect, an API asset URL) went into `version.txt` whole.
  - Every later check then saw an older version and downloaded the archive again.
  - Now the updater writes the tag the release names. It refuses to install a release that has no tag.

## Docs fixes

These change no behavior. They correct the docs to match the code. **[no redeploy]**

- **The metrics endpoint is on by default.** The docs called it opt-in. The code has it on already. In 35.2 and in this release:
  - In auto mode on a bare-metal host, it listens on `127.0.0.1` and on the host's Tailscale IPv4 addresses, not a public interface.
  - In auto mode, a container normally listens on `0.0.0.0` inside the container. Other containers or hosts with a route to it can reach it even without a published port. If the container detects a public address on its network, it falls back to loopback and Tailscale.
  - Mode `auto` picks the first free port from 9100 to 9103. Port 9091 is not used (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1029>).
  - `URNETWORK_METRICS=<ip:port>` pins one address.
  - `URNETWORK_METRICS` does not accept `off`. Run `urnet-tools metrics off` to stop the endpoint, and remove `URNETWORK_METRICS` to keep it off across restarts and HotSwap. A nonempty value starts it again.
- **The deployment page says vnStat is retired** (<https://github.com/full-bars/urnetwork-3.23-fix/pull/1026>). The page still showed how to enable it. The page heading is unchanged, so old anchor links still work.
- **The dual-stack page says the per-carrier IPv6 memory shipped.**
- **The `urnet-tools` help menus point to the community Discord.**

## Seed files on a fleet node

`urnet-tools wallet set --coldkey_seed_file` on a fleet node prints a loud warning to stderr and then carries on. It never asks for confirmation. It never refuses, even with no terminal. The warning cannot be turned off. A seed on a node is your risk to take. The tool makes the risk hard to miss and does not block you. The `--i-am-on-my-own-workstation` flag was removed in 35.2 and stays removed.
