# v3.23.0-fix.26 — 2026-07-09

> [!IMPORTANT]
> This is a **minor version bump** (fix.25 → fix.26). Hot-restart (client JWT reuse) is now enabled by default — no env var, no toggle needed. Set `URNETWORK_HOT_RESTART=0` to disable. Session save/load ships alongside for cross-machine identity transfer, plus native macOS install, Windows hot-restart toggle, and Docker session support. No breaking changes — drop-in upgrade.

## What's New

### 🔥 Hot-Restart Enabled by Default

Since this release, `hotRestartEnabled()` returns `true` unless `URNETWORK_HOT_RESTART=0` is explicitly set. Every provider restart reuses existing per-proxy client JWTs — no re-minting, no warmup penalty. Removes the single biggest friction point for deploying provider updates.

**The context:** The write path was already un-gated in v25.15 (PR [#244](https://github.com/full-bars/urnetwork-3.23-fix/pull/244)), so per-proxy client JWTs have been saving to `~/.urnetwork/.client_jwts.json` on every auth cycle regardless of any flag. The read path was the last piece — and it was opt-in, requiring `URNETWORK_HOT_RESTART=1` on every platform. This release makes that opt-in the default for everyone.

| Platform | Default | Disable |
|----------|---------|---------|
| Linux | On — reuses JWTs on restart | `urnet-tools hot-restart off` → sets `=0` in override.conf |
| macOS | On — reuses JWTs on restart | `urnet-tools hot-restart off` → sets `=0` in launchd plist |
| Windows | On — reuses JWTs on restart | `urnet-tools.ps1 hot-restart off` → sets `=0` in user env |
| Docker | On — reuses JWTs on restart | `-e URNETWORK_HOT_RESTART=0` at container creation |

The `hot-restart on` toggle now removes any explicit env var override (leaving the Go default of true). The status command reports "on" / "off" correctly for the new default.

**Why this matters:** Restarting to deploy an update was costing 8–12 hours of re-warmup per proxy pool. With hot-restart, contracts are acquired in minutes instead of hours. The "experimental" label is dropped — proven on the test fleet since v25.4, and the safety net is robust (falls back to a fresh mint on any JWT validation failure, never a silent auth break).

### 💾 `urnet-tools session save|load` — Cross-Machine Identity Transfer (new)

PR [#250](https://github.com/full-bars/urnetwork-3.23-fix/pull/250)

Export a provider's full identity state as an encrypted portable bundle — move the entire fleet's accumulated server-side reputation from one server to another under the same account.

**Bundle contents** (7 files from `~/.urnetwork/`):

| File | Purpose |
|------|---------|
| `.client_jwts.json` | Per-proxy client JWTs (keyed by proxy address — pairing is free) |
| `jwt` + `jwt_last_refresh` | Account/network JWT |
| `.provider.key` + `.provider.cert` | Ed25519 signing seed + TLS cert/key |
| `proxy` + `proxy_url.json` + `proxy.state` | File-sourced + URL-sourced proxy pools, stable ID/health tracking |

**Security:** Password-required (`openssl aes-256-cbc -pbkdf2`). Bundle is full login credentials for the fleet — treat it as such. Network ID check on load prevents cross-account transfer. `--force` recovery override available.

**Design — staging-directory handoff:** Load never touches live files while the provider is running. Files go to `~/.urnetwork/.session-staging/` + a `.session-pending` marker. On next startup, `applyStagedSession()` atomically renames them into place before any identity loading begins. Prompts "Restart now? (Y/n)" — operator controls when the switch happens.

```bash
# Linux / macOS
urnet-tools session save nyc.urnsession
urnet-tools session load atlanta.urnsession

# Docker
docker exec -it urnetwork urnet-tools session save /root/.urnetwork/nyc.urnsession
docker cp urnetwork:/root/.urnetwork/nyc.urnsession .
docker cp atlanta.urnsession urnetwork:/root/.urnetwork/
docker exec -it urnetwork urnet-tools session load /root/.urnetwork/atlanta.urnsession
```

### 🐳 Docker Session Save/Load (feature parity)

PR [#253](https://github.com/full-bars/urnetwork-3.23-fix/pull/253)

The in-container `urnet-tools.sh` now supports `session save|load`. Interactive TTY guard rejects `docker exec` without `-it`. Restart via `pkill` triggers the start script's crash loop — `applyStagedSession()` picks up the staged files on the next launch.

```bash
docker exec -it urnetwork urnet-tools session save /root/.urnetwork/nyc.urnsession
docker exec -it urnetwork urnet-tools session load /root/.urnetwork/atlanta.urnsession
```

### 🔧 Transport Self-Wake Loop Fix

PR [#248](https://github.com/full-bars/urnetwork-3.23-fix/pull/248)

Restructured `run()` in `transport.go` to eliminate a structural vulnerability: the `activeMode()` notify channel is now captured **after** `setActiveMode()`, so any `NotifyAll()` triggered by the mode-selection work can never close the channel the `select` is waiting on. Guarded with a `lastMode` dedup — if the best available mode hasn't changed, `setActiveMode()` is skipped entirely. Zero latency impact, zero risk to billable traffic.

### 🌐 IPv6 STUN Auto-Detect

PR [#246](https://github.com/full-bars/urnetwork-3.23-fix/pull/246)

On startup, the provider probes IPv6 STUN reachability with a `sync.Once`-guarded 100ms UDP dial. If the probe fails, ICE candidates are restricted to `NetworkTypeUDP4`/`NetworkTypeTCP4` — eliminating "network is unreachable" STUN errors on hosts without functional IPv6 routing (WARP containers, certain VPS providers).

### 🔧 Atomic File Writes

PR [#250](https://github.com/full-bars/urnetwork-3.23-fix/pull/250)

6 file write paths converted from plain `os.WriteFile` to `os.CreateTemp` + `os.Rename`. This is the prerequisite that makes `session save` safe to run against a live provider — concurrent writes produce a complete pre- or post-rename version for `tar`, never a torn file.

| File | Previous | Now |
|------|----------|-----|
| `jwt` (auth + refresh) | `os.WriteFile` | `os.CreateTemp` + rename |
| `jwt_last_refresh` | `os.WriteFile` | `os.CreateTemp` + rename |
| `.provider.key` | `os.WriteFile` | `os.CreateTemp` + rename |
| `.provider.cert` | `os.WriteFile` | `os.CreateTemp` + rename |
| `proxy` | `os.WriteFile` | `os.CreateTemp` + rename |

`show_help()` rewritten with full detailed descriptions (Idea C natural-flow layout). Hub commands listed for the first time in help. Fixed `logs [all|dump|-i]` argument docs. New `urnet-tools set help` sub-menu for runtime overrides. Updated script header.

`eco`/`ramlogs`/`lowmode`/`hot-restart` with no arguments now report their current status instead of erroring. Space-separated aliases (`hot restart`) now dispatch correctly.

### 📦 Per-Platform Tarballs

Provider tarballs are now published per-platform as separate release assets (e.g. `urnetwork-provider-v3.23.0-fix.26-linux-amd64.tar.gz`) alongside the universal bundle. Each includes the binary and the platform's management script flat at the root — no subdirectory navigation needed.

### 🔒 Security: Passphrase Cmdline Leak Fix

PR [#254](https://github.com/full-bars/urnetwork-3.23-fix/pull/254)

All `openssl enc -pass "pass:$var"` invocations changed to `-pass "file:$_pf"` — passphrase written to a `chmod 600` temp file, used by openssl, then immediately cleaned up. Prevents the passphrase from appearing in `/proc/cmdline` or `ps` output.
