# 🔑 v3.23.0-fix.26 — Session Portability + Hot-Restart by Default

> **TL;DR** Hot-restart (client JWT reuse) is now enabled by default — no `-e URNETWORK_HOT_RESTART=1` needed, on all platforms. Set `URNETWORK_HOT_RESTART=0` to disable. Cross-machine session save/load ships alongside this: `urnet-tools session save|load` exports/imports the full identity bundle as an encrypted tar. Native macOS install and Windows hot-restart toggle round out the cross-platform story.

---

## 📝 Always-On Identity Persistence

`~/.urnetwork/.client_jwts.json` is now populated on every proxy auth by default. Previously, JWTs were only written when `URNETWORK_HOT_RESTART=1` was explicitly set, meaning you had to:
1. Enable the flag
2. Restart and wait for every proxy to re-auth (hours)
3. Restart *again* to actually reuse anything

Now the write path is unconditional — identities land on disk as proxies naturally cycle through auth. The read path stays gated, so **nothing changes until you opt in**.

| Path | Before | After |
|------|--------|-------|
| Write (save JWT) | Gated on `HOT_RESTART=1` | Always |
| Read (reuse JWT) | Gated on `HOT_RESTART=1` | Always (new default) |

## 🔥 Hot-Restart Enabled by Default

Since v3.23.0-fix.26, `hotRestartEnabled()` returns `true` unless `URNETWORK_HOT_RESTART=0` is explicitly set. This means every restart reuses the existing per-proxy client JWTs — no re-minting, no warmup penalty.

| Platform | Default | Disable | Enable (explicit) |
|----------|---------|---------|-------------------|
| Linux | On | `urnet-tools hot-restart off` → sets `=0` in override.conf | `urnet-tools hot-restart on` removes override (falls back to default) |
| macOS | On | `urnet-tools hot-restart off` → sets `=0` in launchd plist | `urnet-tools hot-restart on` removes plist env (falls back to default) |
| Windows | On | `urnet-tools.ps1 hot-restart off` → sets `=0` in user env | `urnet-tools.ps1 hot-restart on` removes env (falls back to default) |
| Docker | On | `-e URNETWORK_HOT_RESTART=0` at container creation | Not needed (default) |

**Why this matters**: The write path was already un-gated in v25.15 (PR #244), so every auth cycle has been writing JWTs to disk regardless. Now the read path follows suit — your next restart uses what's already there. No env var to set, no toggle to flip, no Docker flag to remember.

**If you need to disable**: Set `URNETWORK_HOT_RESTART=0`. Use the platform toggle or the env var directly.

## 💾 Session Save/Load

Export a provider's full identity state as an encrypted, portable bundle — move your fleet's accumulated reputation between servers under the same account.

**Bundle contents** (7 files from `~/.urnetwork/`):

| File | Purpose |
|------|---------|
| `.client_jwts.json` | Per-proxy client JWTs (keyed by proxy address) |
| `jwt` + `jwt_last_refresh` | Account/network JWT |
| `.provider.key` | Ed25519 signing seed |
| `.provider.cert` | TLS cert/key pair |
| `proxy` | File-sourced/paid proxy pool |
| `proxy_url.json` | Active URL-sourced proxy cache |
| `proxy.state` | Per-address stable ID/health tracking |

**Security:**
- Password-required encryption via `openssl aes-256-cbc -pbkdf2`
- Passphrase never appears in `/proc/cmdline` (uses `-pass file:` with temp file)
- Network ID check on load prevents loading a session from a different account
- `--force` override available for recovery scenarios

**Design** — `session load` uses a staging-directory handoff:
1. Load writes files to `~/.urnetwork/.session-staging/` + marker
2. Prompts "Restart now? (Y/n)" — restart is user-controlled
3. On next startup, `applyStagedSession()` atomically swaps files in
The running provider never sees the files change during operation.

```bash
# Linux / macOS
urnet-tools session save nyc-backup.urnsession   # encrypt and export
urnet-tools session load atlanta.urnsession      # decrypt and import

# Docker
docker exec -it urnetwork urnet-tools session save /root/.urnetwork/nyc.urnsession
docker cp urnetwork:/root/.urnetwork/nyc.urnsession .
docker cp atlanta.urnsession urnetwork:/root/.urnetwork/
docker exec -it urnetwork urnet-tools session load /root/.urnetwork/atlanta.urnsession
```

## 🖥️ Cross-Platform Support

### macOS — Native Install

New `Provider_Install_Mac.sh` — the macOS equivalent of the Linux installer:

```bash
curl -fSsL https://raw.githubusercontent.com/full-bars/urnetwork-3.23-fix/refs/heads/main/scripts/Provider_Install_Mac.sh | sh -s -- install
```

- Installs the provider binary to `~/.local/share/urnetwork-provider/bin/urnetwork`
- Creates a `launchd` user agent at `~/Library/LaunchAgents/com.urnetwork.provider.plist`
- `RunAtLoad` + `KeepAlive` for auto-start on boot and crash recovery
- Logs to `~/Library/Logs/com.urnetwork.provider/`
- Strips `com.apple.quarantine` xattr automatically
- All commands work: `start|stop|restart|status|hot-restart|session|proxy|hub|auth|logs`

```bash
urnet-tools start                    # launchctl bootstrap
urnet-tools stop                     # launchctl bootout
urnet-tools hot-restart on           # set env in plist + restart
urnet-tools session save backup.urnsession
```

**Binary builds:** darwin/amd64 and darwin/arm64 now built and published in every release alongside the existing linux binaries. CI matrix expanded.

### Windows — Hot-Restart Toggle

`urnet-tools.ps1` now supports `hot-restart on|off`:

```powershell
urnet-tools.ps1 hot-restart on       # sets URNETWORK_HOT_RESTART=1 as user env var
urnet-tools.ps1 hot-restart off      # removes the env var
urnet-tools.ps1 hot-restart          # show current status
```

- Uses `[Environment]::SetEnvironmentVariable(User)` for persistence
- Sets `$env:URNETWORK_HOT_RESTART` in the current process so immediate `Start-Process` restart inherits it
- Prompts "Restart provider to apply? [y/N]"
- Help text reorganized matching Linux PR #245 (grouped sections, all commands listed)

### Docker — Session Save/Load

The Docker `urnet-tools.sh` now has `session save|load` commands. Workflow:

```bash
# Save
docker exec -it urnetwork urnet-tools session save /root/.urnetwork/nyc.urnsession
docker cp urnetwork:/root/.urnetwork/nyc.urnsession .

# Load
docker cp atlanta.urnsession urnetwork:/root/.urnetwork/
docker exec -it urnetwork urnet-tools session load /root/.urnetwork/atlanta.urnsession
```

- Interactive TTY guard: prompts helpfully if `docker exec -it` is omitted
- Restart via `pkill` triggers the start script's crash loop → `applyStagedSession()` picks up

## 🔧 Atomic File Writes

6 file write paths converted to atomic tmp+rename (prevents torn files during concurrent writes):

| File | Previous | Now |
|------|----------|-----|
| `jwt` (auth + refresh) | `os.WriteFile` | `os.CreateTemp` + rename |
| `jwt_last_refresh` | `os.WriteFile` | `os.CreateTemp` + rename |
| `.provider.key` | `os.WriteFile` | `os.CreateTemp` + rename |
| `.provider.cert` | `os.WriteFile` | `os.CreateTemp` + rename |
| `proxy` | `os.WriteFile` | `os.CreateTemp` + rename |

This is the prerequisite that makes `session save` safe to run against a live provider — a concurrent write means `tar` gets the complete pre- or post-write version of each file, never a torn one.

## 🔒 Security

- Session bundles: encrypted via `openssl aes-256-cbc -pbkdf2`, password-required
- Passphrase never appears in `ps` output or `/proc/cmdline` (uses `-pass file:` with temp file)
- Network ID check on session load prevents loading a session from a different account
- All identity files: `0600` permissions in a `0700` directory
- Client JWTs are per-proxy scope — cannot be used to login, mint proxies, or access billing
